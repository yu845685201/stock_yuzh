## 二、新发现详述

### X-16 ⚪ 沪深主板 \*ST 板幅 5%/10% 并存——既有规则口径局限（不阻塞）

**数据事实（20260930 与 20251231 双日验证，长期并存非临时）**：

```
10% 板位样本（实际按 10% 涨跌幅交易）: *ST华鹏 -9.90%、*ST发展 +9.87%、*ST广糖 +9.98%、
                                      *ST岭南 -10.14%、*ST顾地 +9.96%、*ST美芝 +10.01%
5% 板位样本（按 5% 交易）:            *ST华幸 -5.11%、*ST联翔 -4.64%、*ST亚士 +4.69%、
                                      *ST建艺 +4.84%、*ST易录 +4.89%
——同为沪深主板 *ST，两种板幅并存；不带星 ST 与多数 *ST 按 5%。
```

**对现有代码的影响评估**（`limit_up_rules.limit_pct` 以 is_st 布尔统一给 5%）：

- **涨停/跌停判定不受影响**：阈值法是"下界 + close=high 护栏"，9.87% 涨幅 ≥ 4.9% 阈值且收盘封高 → 正确判涨停（实测 T17b 已确认）；
- **炸板判定有误报可能**：threshold = 5% − 0.1，涨 5~10% 未封住的 *ST 会被误判"炸板"——当日全市场该区间 ST 仅 5 只、实际触板误报约 0~2 只/日；
- **F 项免疫**：limit_price = max(分笔价) 与规则板幅无关（T17b 实测 *ST发展 分笔 max=2.45=收盘封板价，输出正确）；
- 结论：**记录为已知局限，不修改规则函数**（修改需先弄清 10% 档的确切适用条件，收益 < 每日 2 只的误报）；B 项校准的炸板率统计含此噪声，量级可忽略。

### T18：决策 3 深市路径（巨潮披露季窗口）执行细节打通

- **日期格式坑（探路脚本踩到）**：`query_market_window` 的 seDate 必须 `yyyy-MM-dd`（isoformat）；传 `yyyyMMdd` 接口**不报错、静默返回 0 条**——生产代码用 isoformat 无恙，实施披露日回补工具时保持；
- **必须带 category 过滤**（`category_ndbg/bndbg/yjdbg/sjdbg_szsh`）：全市场单日 1,787~2,703 条会触发 CninfoWindowTooLarge（40 页上限）；category 过滤后普通披露日 **52~63 条（1~3 页）**、披露截止日（4-30）2,703 条（91 页，需按 3~4 天拆窗）；
- **`_query_market_window` 需加 category 参数**（当前未暴露，约 5 行改动）；
- **5 年回补总请求量实测推算**：4 个披露季 × 5 年，按 3~4 天拆窗 ≈ 200 窗 × 2~4 页 = **400~800 请求 ≈ 10~20 分钟**（1.5s 限速）——决策 3 方案 A 的执行成本比第二轮估算更乐观。
