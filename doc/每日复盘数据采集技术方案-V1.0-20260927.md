## 〇、与原方案 V1.0 的差异说明（实施前必读）

本方案在上游方案基础上，经确认做了四处调整，开发人员以本方案为准：

| # | 变更项 | 原方案表述 | 本方案 | 原因 |
|---|---|---|---|---|
| 1 | 兜底来源 | 每项数据列有"首选来源 + 兜底" | **只实现首选来源，兜底一律不实现**。首选源失败走"源内恢复"（重试/冷却/次日补抓），恢复不了在报告标"待补"；未来启用兜底源属数据源变更，按项目规范另行评审 | 范围收窄决策 |
| 2 | Tushare | 结构化财报指标首选，多项数据兜底 | **整体排除**（不注册、不使用任何积分档）。结构化财报指标首选来源变更为**同花顺个股财务页**（原兜底顺位顶替） | 免费积分档限频过多，实际可用性差 |
| 3 | 复权因子 | "tdx-api ✅ xdxr 模型"（理解为已有现成接口） | tdx-api **新增只读 HTTP 接口** `/api/ths-factor`、`/api/xdxr` 暴露协议库已有能力（详见第三章） | 实测 xdxr / THS 因子仅有 Go 内部模型，无 HTTP 门面；已确认允许为 tdx-api 新增只读接口（不改现有接口逻辑） |
| 4 | 主力资金流 | "tdx-api 分笔自算"，未定范围 | **每日异动股子集**（约 300-500 只），非全市场 | 全市场约 8 万次分页请求 / 2-3 小时，对 tdx-api 单 TCP 连接与通达信服务器压力过大；子集与复盘"个股异动"章节正好配套 |

## 一、目标与范围

### 1.1 目标

为每日复盘报告补齐 14 类缺失数据，全部走免费来源，满足原方案第四章验收标准：每个新数据源配同步报告（沿用现有 sync report 模式）、缺数据章节标"待补"而非留空。

### 1.2 范围约束（四条，全文有效）

1. **只实现首选来源**：兜底来源一律不实现（各设计小节"兜底"仅备注"不实现"）。
2. **Tushare 整体排除**：任何积分档都不用。
3. **tdx-api 仅新增两个只读接口**（`/api/ths-factor`、`/api/xdxr`），不触碰现有接口。
4. **合规红线**（沿用 `cninfo_source.py` 文件头约定，对全部外网源生效）：串行限速、正常 UA/Referer、不破解任何技术措施（含同花顺 hexin-v cookie）、风控识别即退避冷却、仅自用不分发。

## 二、总体架构

### 2.1 分层与现有模式复用

沿用 stock_yuzh 现有同步器模式（不引入新框架）：

```
HTTP 采集基类（新增） → 数据源 source（新增，每源一个类）
                      → 采集管理器 manager（新增，每源/每组一个）
                      → DAO mixin（新增，挂进 DatabaseConnection）
                      → PostgreSQL（ON CONFLICT upsert）+ tmp/manifest（全量任务）
                      → report_writer 统一 sync report → data/reports/
                      → CLI 子命令（src/cli/main.py）+ 编排命令
```

参照模板：`src/sync/financial_pdf_manager.py` + `src/data_sources/cninfo_source.py` 组合（进度/断点/风控急停/报告的完整先例）。

### 2.2 新增代码结构规划

```

│   ├── http_collector_base.py      # 新增：统一 HTTP 采集基类（2.3）

│   ├── sse_szse_source.py          # 新增：沪深交易所官网（披露日历/龙虎榜/两融）
│   ├── csindex_source.py           # 新增：中证指数官网（指数估值）

├── sync/
```

### 2.3 统一 HTTP 采集基类 `http_collector_base.py`（稳定性核心）

现有 cninfo/tdx 源**不迁移**；全部新增外网源继承此基类。职责：

```python
class ReviewBlockedError(Exception):       # 风控基类异常，各源子类化（如 ThsBlockedError）
    cooldown_seconds: int = 600            # 冷却时长（配置可覆盖）

class HttpCollectorBase:
    # 会话：模块级唯一 requests.Session()（连接复用）
    # headers：构造时注入 UA / Referer / Accept（每源配置，模板见第八章）
    # 超时：connect=(5, 30) —— 连接 5s / 读 30s，防挂死
    # 代理：bypass_proxy 配置项（默认 False，外网走系统代理；与 tdx 本地绕过逻辑无关）
    # 限速：每源独立 request_interval（串行 sleep），不用 ApiRateLimiter（与 cninfo 惯例一致）
    # 重试：请求级 run_with_retry（utils/retry.py），指数退避 + 随机抖动 ±20%，
    #       仅对网络类异常/5xx 重试；风控信号（4xx/验证码页/非预期响应）不重试，直接抛 ReviewBlockedError
    # 风控识别钩子：_check_risk_control(resp) -> None | raise ReviewBlockedError
    #   子类覆写：识别 403/429、验证码页特征串、非 JSON 响应等（对照第六章矩阵）
    # 急停：manager 捕获 ReviewBlockedError → 本轮该源急停（结果 blocked=True），
    #       冷却 sleep 后可由编排器决定是否重试一次；进度/断点已落盘可续
```

要点：

- **风控信号必须显式识别，不许裸重试**——裸重试是触发封禁升级的主因（baostock/cninfo 先例均已验证此模式）。
- **单源急停不影响其他源**：异常在 manager 边界收敛，编排器按源隔离（2.5）。
- 所有请求前后打 debug 日志（URL、状态码、耗时、行数），问题可追溯。

### 2.4 断点续传与幂等

**双轨制**（沿用 financial_pdf 模式）：

- **增量任务（日频/周频）**：通用游标表 `sync_cursor`（第五章 DDL），按 `(source_name, cursor_key)` 记 `last_success_date` 等游标；配合 upsert 幂等（`ON CONFLICT DO UPDATE`），任意重跑安全。
- **全量任务（复权因子、THS 财报首次全量等）**：`tmp/<task>_manifest.json`（原子写 `.tmp` + `replace()`，每完成一只保存，急停可续，禁止手工改动——沿用 fundamentals_rebuild 惯例）。
- **入库校验**（第五章）：行数下限、关键列非空、日期范围；校验失败该批不入库、写报告。

### 2.5 盘后编排命令 `sync-review-data`

```python
@cli.command('sync-review-data')
@click.option('--sources', default='all', help='逗号分隔子集：index,factor,overseas,valuation_idx,announcement,disclosure,lhb,margin,ths_finance,money_flow,valuation_calc')
@click.option('--as-of', default=None, help='yyyyMMdd，缺省当日')
def sync_review_data(ctx, sources, as_of): ...
```

- **前置校验**：检查当日全市场日K是否已同步（`his_kline_day` 当日行数 vs `base_stock_info` 股数），未同步则中止并提示先跑 `sync-kline-day`（分笔子集、涨跌幅筛选都依赖日K；不自动触发，与现有流程保持正交）。
- **执行顺序**（默认 all，串行）：

```
1 index          指数日K（tdx-api，快，先出大盘数据）
2 factor         复权因子增量（依赖日K除权检测清单）
3 overseas       外围市场（新浪，独立）
4 valuation_idx  指数估值（中证，独立）
5 announcement   公告清单 + 业绩预告（巨潮，同一批请求）
6 disclosure     披露日历回填（官网）
7 lhb            龙虎榜（官网，17:30 后才有数据）
8 margin         两融（官网，T-1）
9 ths_finance    THS 财报增量（依赖 5/6 的当日披露清单，高峰期可 --sources 跳过、后台补）
10 money_flow    分笔资金流（依赖日K异动子集计算）
11 valuation_calc PE/PB 自算（依赖 9 的财报数据与日K/股本，缺则对应字段标待补）
```

- **单源失败不阻塞**：每源 try/except 隔离，失败源记入编排汇总（沿用 render_sync_result 输出），报告生成阶段对缺失数据标"待补"。
- **幂等重跑**：晚间补跑 `sync-review-data --sources=lhb,announcement` 这类子集补抓完全安全。

### 2.6 CLI 子命令清单

每源独立子命令（均支持 `--dry-run`，注册方式照 `sync-financial-pdf`）：

```
sync-index-kline / sync-adjust-factor / sync-money-flow / sync-announcement
sync-disclosure-calendar / sync-index-valuation / sync-ths-finance
sync-lhb / sync-margin-trade / sync-concept / sync-unlock-calendar
sync-overseas-market / calc-stock-valuation
sync-review-data（编排）
```

## 三、tdx-api 接口扩展设计

### 3.1 改动原则与部署

- **只新增**，不修改：在 `tdx-api/web/` 新增 handler 文件 `server_api_review.go`（或并入 `server_api_extended.go` 追加），照 `/api/index` handler 样式写；路由注册在 `server.go` main() 的 mux 段追加两行。**不改动任何现有 handler / 缓存 / 任务逻辑**。
- **部署**：`cd tdx-api/web && go run .`（必须全文件编译，README 已有警告）；上生产前先在 UAT 环境验证。
- **改动量预估**：两接口合计 60-100 行 Go 代码，0.5-1 人日。

### 3.2 `/api/ths-factor`（复权因子主接口）

- **能力来源**【已验证】：`extend/spider-ths.go` 已实现 `GetTHSDayKlineFactorFull(code)`，内部调 THS JSONP 接口（`d.10jqka.com.cn/v6/line/hs_{code}/01/all.js` 等），返回全历史 `[]*THSFactor{Date, QFactor, HFactor}`（同花顺前复权/后复权因子序列）。
- **接口定义**：`GET /api/ths-factor?code=000001`，响应沿用统一包络：`{code:0, message:"", data:{code, count, list:[{date, q_factor, h_factor}]}}`，date 为 yyyyMMdd。
- **为何优于价格反推**：与现有日K qfq 源**同为 THS 同源数据**，因子可直接解释现有前复权 K 线、修复"历史前复权断裂"；每股 1 个请求拿全历史，请求量最小。
- **验收**：任取 3 只有分红送转史的股，q_factor 跳变日与通达信客户端 F10 除权日一致；`raw_close × q_factor ≈ qfq_close`（与 `/api/kline-qfq` 对比，容差 0.5%，验证因子乘法方向后写死口径）。

### 3.3 `/api/xdxr`（除权除息事件）

- **能力来源**【已验证】：`client.go:751` 已实现 `Client.GetXdxr(code)`（协议功能号 0x000f，`protocol/model_xdxr.go`），返回 `XdxrResp{Count, List[XdxrEvent]}`，事件字段：Date、Category（1除权除息/2送配股上市/…/14）、Fenhong、Peigujia、Songzhuangu、Peigu、Suogu、Xingquanjia、Fenshu、Panqianliutong、Panhouliutong、Qianzongguben、Houzongguben。
- **接口定义**：`GET /api/xdxr?code=000001&limit=0`（limit=0 全历史，>0 取尾部 N 条），响应包络同上。
- **用途**：送转/分红事件日历（复盘"个股异动"补充维度）；复权因子跳变日的交叉校验（因子跳变日应存在 Category=1 事件）。

### 3.4 机会清单（本次不做，仅记录）

- F10/FINANCE（功能号 0x0010 / 0x02d0）：协议库**仅有常量注释，无解析实现**，暴露它需要新协议开发，超出"暴露已有能力"边界，且财务数据另有 THS 首选路径。
- `/api/market-stats` 涨跌统计有已知 bug（`classifyPrice` 以 `lastPrice>0` 记"涨"）：**不修不改不用**，复盘的涨跌家数由全市场日K自算。

## 四、逐项采集设计

> 每项小节统一结构：来源与接口 / 调用设计 / 频率与增量 / 落库 / 风控与失败处理 / 耗时预算 / 验证方法 / 兜底备注。
> 标注约定：【已验证】= 代码调研确认的事实；【实施时核实】= 接口参数/URL 需实施第一步抓包确认，不得凭文档臆造。

### 4.1 指数日K线（M1）

- **来源**【已验证】：tdx-api `/api/index/all?code=&type=day&limit=`（全量历史）与 `/api/index?code=&type=day&limit=N`（尾部增量）；返回 `Kline{Last, Open, High, Low, Close, Volume, Amount, Time, UpCount, DownCount}`（UpCount/DownCount 仅指数有效）。
- **指数清单**：sh000001 上证指数、sz399001 深证成指、sz399006 创业板指、sh000688 科创50、sh000300 沪深300、**bj899050 北证50（实施首日实测，协议路径无阻碍但无实测记录；失败则当日剔除并记录，不阻塞其余指数）**。
- **调用设计**：`TdxApiSource` 新增 `get_index_kline_all(code)`、`get_index_kline_tail(code, limit=5)`（复用现有重试/本地绕代理逻辑）；`preclose` 缺失字段由前一条 close 补齐，`change_rate` 自算（close/preclose-1）。
- **落库**：`trade_index_info`（已建，trade_date 为 **yyyyMMdd 字符串口径**，注意不要写成 date 类型）；upsert 键 `(ts_code, trade_date)`——若现表无该组合唯一索引，先在 init-V3.sql 补建。`UpCount/DownCount` 新增两列 `up_count/down_count` 存入（ALTER TABLE），备复盘涨跌家数参考（精确家数仍由全市场日K自算）。
- **频率与增量**：首次全量 6 请求；每日增量 6 请求。**耗时 <10s**。
- **失败处理**：单指数失败不影响其余；次日增量自动补齐（limit=5 覆盖 5 个交易日缺口）。
- **验证**：与行情软件对照当日 OHLC；北证50 与北交所官网对照。
- **兜底**：无（tdx-api 即首选亦唯一）。

### 4.2 复权因子（M1）

- **来源**：tdx-api 新接口 `/api/ths-factor`（第三章）；`/api/xdxr` 作事件校验。
- **调用设计**：`TdxApiSource` 新增 `get_ths_factor(code)`；落库 `base_adjust_factor(ts_code, trade_date, qfq_factor, hfq_factor, update_time, UNIQUE(ts_code, trade_date))`。

### 4.7 个股 PE/PB 自算（M2，本地计算）

- **频率与耗时**：每日盘后全市场重算，**<2 分钟**。
- **依赖与失败处理**：仅依赖本地表；任何输入缺失 → 对应字段空 + note，不算失败。

### 4.10 主力资金流近似（M3，口径自定义项）

- **来源**【已验证】：tdx-api `/api/minute-trade-all?code=&date=YYYYMMDD`（历史全天分页 2000 笔/次；不带 date 取当日 1800 笔/次）。每笔 `Trade{Time 仅到分钟, Price, Volume 手, Status 0买/1卖/2中性, Number}`。
- **采集范围（已确认）**：**每日异动股子集**——当日涨停 ∪ 跌停 ∪ |涨跌幅|≥7% ∪ 成交额 Top50，合并去重约 **300-500 只**。子集由当日全市场日K现算（复用 `limit_up_rules.py` 阈值口径）。
- **自算口径（写入表注释与报告口径说明，报告必须标注"近似口径"）**：
  - 单笔金额 = Price × Volume × 100（手→股）；
  - 方向归并：Status=0 记买盘主动、1 记卖盘主动；**Status=2 中性盘按价格归向**——与前一笔成交价比较，价升归买、价降归卖、平价归前一笔方向（首笔中性盘剔除），阈值参数化；
  - 大单阈值：单笔金额 ≥ **50 万元**（配置 `money_flow.big_amount_threshold`）；
  - 输出：大单买入额、大单卖出额、**大单净流入 = 买 − 卖**、大单净流入占比 = 净流入 ÷ 当日成交额（成交额取日K）。
- **落库**：`money_flow_daily(trade_date, ts_code, total_amt, big_buy_amt, big_sell_amt, big_net_amt, big_net_pct, stock_count 笔数, calib_note 默认'近似口径:分笔分桶', update_time, UNIQUE(trade_date, ts_code))`。
- **性能与灰度**：500 只 × 平均 10-20 页 ≈ 5000-10000 请求；**并发 ≤3 + 全局 5 req/s 起步（灰度）**，**15-25 分钟**。第一周子集压到 200 只观察 tdx-api 超时率（Go 侧单请求 2s 超时【已验证】），稳定后放开 500；超时率 >5% 自动降速（间隔 ×2）。
- **失败处理**：单股失败不阻塞（记失败清单）；当日失败的股**次日用历史分笔路径补**（历史接口可取昨日及之前【已验证】）；tdx-api 服务不可用 → 本源整体跳过。
- **兜底**：无（免费路径唯一，原方案已注明）。

### 5.3 通用游标表 `sync_cursor`（替代每源一张进度表）


## 六、稳定性设计

### 6.1 风控信号与动作矩阵

| 源 | 风控信号 | 识别层 | 动作 |
|---|---|---|---|
| tdx-api（本地） | HTTP 超时 / 连接拒绝 / code=-1 | 请求层 | run_with_retry 3 次指数退避（沿用现有 tdx 逻辑）→ 失败记源失败；分笔超时率 >5% 自动降速 |
| 通达信服务器（经 tdx-api） | 分笔返回空/截断、单请求耗时持续上升 | money_flow manager | 请求间隔 ×2，当日截断子集尾部，次日灰度恢复 |
| 巨潮 | 403/429/非 JSON（已有 `CninfoBlockedError`） | cninfo_source | 急停整轮 + 冷却（config，默认 10 分钟）；进度已存可续 |
| 交易所官网 | 403/429/空响应/响应结构变更 | sse_szse_source | 冷却 60s 重试 1 次 → 当日失败次日补；结构变更报错带原始响应片段 |
| 中证官网 | 文件 404 / 解析失败 | csindex_source | 次日回溯补齐 |
| 同花顺 | 403/验证码页特征/非 JSON/hexin-v 拒绝 | ths_source | `ThsBlockedError` 急停 + 冷却；当日标"待补"，**绝不重试轰炸** |
| 新浪 | 403/空 body | sina_source | 重试 1 次 → 标"待补" |

### 6.2 失败恢复策略（无兜底版）

```
请求失败 → run_with_retry（网络类异常，3 次退避）
  → 仍失败 / 风控信号 → 该源急停（本轮）
      → 冷却后编排器内重试 1 次（可配置）
          → 仍失败 → 当日标"待补"，次日编排自动补抓（游标未推进）
              → 连续 3 日失败 → 报告固定标"待补" + 日志告警（连续失败计数进 sync_cursor）
```

- **当日数据次日可补的**（巨潮窗口检索、官网历史保留、分笔历史路径）：次日自动并抓。
- **当日截面次日不可补的**（理论上无——分笔历史路径也支持次日补昨日）：无此情况。
- **恢复后的一致性**：全部 upsert 幂等，补抓不产生重复。

### 6.3 故障隔离

- 每源独立子进程级隔离不必要，**manager 边界 try/except 已足够**（与现有 sync manager 一致）；
- 编排器对每源计时并写入汇总报告：`源名 / 状态(成功|失败|待补|跳过) / 行数 / 耗时 / 失败摘要`；
- 任何源的急停/失败**不阻塞**后续源与复盘报告生成——报告侧对应章节标"待补"。
