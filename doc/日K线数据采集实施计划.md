# 日K线数据采集实施计划

> 依据：[日K线数据采集技术方案-V3.0-中间件增强.md](./日K线数据采集技术方案-V3.0-中间件增强.md)（下称"方案"）
> 排期为单人全职估算，供排产参考；每阶段末有验证关口，未过关不进入下一阶段。

## 总览

```
第1周          第2周            第3周           第4-5周
──────────────────────────────────────────────────────────────
Phase0 排雷 ──┐
F1 基本面改造 ─┼─ F2 一夜重刷 ─ F3 ─┐
M1 采集重构 ───┴───────────── M1收尾 ─┴─ M2 基线重建 ─┐
M-A 尾部接口（并行）──────────┘                       ├─ M-C 灰度切换
M-B 缓存+XDXR（M-A 后启动）───────────────────────────┘
                                                      （M-B2/M-D 按需）
```

关键路径：**M1 → M2 → M-B → M-C**；XDXR spike 是全局第一优先级（唯一技术不确定点）。

## Phase 0：排雷与准备（第 1 周，约 2-3 天）

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| T0.1 **XDXR spike**（1-2 天） | 在 injoyai/tdx 库中查证 `KMSG_XDXRINFO(0x000f)` 是否有现成封装；写最小 Go demo 连接 TDX 服务器查询平安银行除权除息事件，核对与已知分红记录一致 | 可行性结论书 | 拿到 ≥1 只股票的完整事件列表且日期/金额正确 → 走主方案；不可行 → 启用降级预案（M-B 去掉 XDXR，靠周度校准+调用方检测双防线，M-C 不受影响） |
| T0.2 测试股票集 | 选定 100 只代表股：大盘银行 / ST / 次新股 / 长期停牌 / 近期除权 / 即将除权各若干 | 固定代码清单（入库配置） | 覆盖 §5.3 灰度与 M-C 灰度共用 |
| T0.3 基线快照 | 记录现库状态：his_kline_day 行数/日期分布/amount=0 占比、base_fundamentals_info 覆盖、抽样 100 股的价格序列 | 基线报告（对比用） | 可复现查询脚本入库 |

## Phase 1：F 线——基本面修复（第 1-2 周，与 M1 并行）

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| F1a 表迁移（0.5 天） | UAT 执行方案 §5.3 迁移 SQL（stat_date 列、唯一键切换、放开 NOT NULL）；修正 init-V1.sql 与 数据模型.MD 的 DDL 滞后 | 迁移脚本 + 更新后 DDL 文档 | 迁移前后行数守恒（225,444）；约束生效 |
| F1b 采集改造（0.5 天） | `baostock_source.get_financial_data` 映射 pubDate/statDate，删除 `_get_disclosure_date`；upsert 冲突键改 `(ts_code, stat_date)` | 代码 + 单测 | pubDate 缺失走留白分支；同日双报告可共存 |
| F1c 灰度重刷（1 天） | 100 只代表股重刷，跑方案 §5.5 验证清单（含前视消除抽样） | 灰度验证报告 | 5.5 五项全过 |
| F2 全量重刷（一夜） | 任务全集 ≈24-26 万次串行调用（base_stock_info type=股票 × 上市以来报告期），断点续传 + 会话自动重登 | 重刷报告 | 5.5 清单在全量上复验；行数 ≥ 迁移前 + 补缺期数 |
| F3 匹配微调（0.5 天） | `_build_fundamentals_map` 排序键 `(disclosure_date, stat_date)`；无 pubDate 不入 map | 代码 + 单测 | 同日双报告 tie-break 用例通过 |

## Phase 2：M 线——采集侧重构（第 1-3 周，与 Phase 1 并行）

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| M1a 数据源封装（1 天） | `TdxApiSource` 增加 `get_kline_qfq_full / get_kline_qfq_tail / get_kline_raw_full / get_kline_raw_tail`，统一厘→元、手→股换算，启动探活 | 代码 + 单测 | 四个方法对 100 股实测返回与 curl 一致 |
| M1b 三模式重构（2-3 天） | `sync_kline_day` 双源合并、整股原子替换（单事务删+插）、区间内存过滤、废弃 `/api/kline-history` 日期参数用法 | 重构后 sync_manager | 全量/区间/增量三模式 CLI 全通；每股替换原子性用并发读验证 |
| M1c 检测与校验（1 天） | 跨快照 Last 检测（阈值 max(0.01, close×0.2%)）、raw 不可变校验、检测命中触发全刷（预留 refresh 语义） | 代码 + 单测 | 构造除权用例：模拟 Last 错位触发全刷且数据自愈 |
| M1d 报告扩展（0.5 天） | 采集报告增加：检测命中数、全刷股清单、两源缺失统计、耗时分布 | 报告样例 | 字段齐全可读 |
| M1e 试点对账（1-2 天） | 100 股跑三模式；与 T0.3 基线快照对比 | 试点报告 | 价格抽样一致或差异可解释；amount 非零率 ≈100%（除权日前历史除外） |

**关口 G1/G2**：F1c 与 M1e 报告评审通过。

## Phase 2.5：M2 日K基线重建（第 3 周，一夜起）

依赖 **M1 + F2 + F3**。全市场 5,200+ 股双全量重建（40-90 分钟/轮，可分夜），清除基准混杂旧数据，`his_kline_day` 基本面三列自动按新匹配重写。

**关口 G3**：与 T0.3 基线对比——行数守恒（±新股）、amount 非零、除权日前后 preclose 衔接抽验无断层、涨跌幅异常率不高于基线。

## Phase 3：中间件增强与切换（第 3-5 周）

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| M-A 尾部接口（1-2 天） | `/api/kline-recent`（`client.GetKlineDay(code,0,N)`）+ 单测 + 镜像重建部署 | 新接口 | 尾部耗时实测 ≤100ms；与 `/api/kline-all` 尾部数据逐条一致 |
| M-B1 XDXR 失效（2-3 天） | 事件查询封装 + 失效判定（仅事件日≤当天触发） | 中间件代码 | 构造含未来事件与已生效事件两种用例 |
| M-B2 qfq 缓存（2-3 天） | 本地库分表存储 + LRU；`/api/kline-history`、`/api/kline` day 分支缓存优先；`refresh=1` 旁路 | 缓存模块 | 重启不丢；refresh 强制回源；除权日次日缓存自动重基 |
| M-B3 周度校准（1 天） | 绕过缓存全市场比对脚本 + 修正告警 | 脚本 + 报告 | 试运行一周无漏报 |
| M-C 切换灰度（1-2 天） | `use_enhanced_api=true`：100 股灰度对账 → 全市场；日常增量实测墙钟 | 切换报告 | 双路径同股比对一致；日常增量 ≤8 分钟（高峰日） |

**关口 G4**：M-C 灰度对账通过后全市场切换，保留 `use_enhanced_api=false` 回退开关。

## Phase 4：可选增强（按需，不阻塞收尾）

- M-B2' 原始序列缓存（区间模式 → 分钟级）
- M-D 聚合接口（每股每日单请求）
- XDXR 事件联动 float_share 刷新（缓解股本季度滞后）
- 1 分钟线模块同类缺陷修复评估（范围外，另行立项）

## 排期与人力

| 周 | 主线 | 关键事件 |
|----|------|---------|
| 第 1 周 | Phase 0 + F1 + M1 启动 | XDXR spike 结论（决定 M-B 形态） |
| 第 2 周 | M1 收尾 + F2/F3 | F2 一夜重刷；关口 G1 |
| 第 3 周 | M2 重建 + M-A + M-B 启动 | 关口 G3（基线重建对账） |
| 第 4-5 周 | M-B 完成 + M-C 灰度 + 收尾 | 关口 G4；日常增量达到 3-5 分钟 |

总计约 **4-5 周**（单人全职）。若 XDXR spike 失败，M-B 改双防线实现，总排期不变。

## 统一原则（贯穿所有任务）

1. 每个改动先 UAT 后 PROD；灰度不通过不放大范围
2. 所有重刷/重建任务幂等可重跑，失败不阻塞主流程
3. 数据真实性原则：任何字段拿不到就留空，禁止推算回填
4. baostock 全程串行；tdx-api 调用遵守限流配置
5. 回退开关长期保留：`use_enhanced_api=false` + 中间件镜像回退
