# 每日复盘报告优化方案 V1.0（2026-10-24）

> **⚠ 本版已并入 [每日复盘报告优化方案-V2.0-20261024.md](每日复盘报告优化方案-V2.0-20261024.md)（V2.0 = 本版全部内容 + 缠论上线第二轮评价 8 项新增：P0-7/P1-8/P2-6/P4-8 等），以 V2.0 为准。**

## 一、背景与输入

本方案合并两个来源的问题清单，针对每日复盘报告（六维 md + 图文 digest + digest_note 解读）做系统性优化：

1. **2026-10-23 digest 人工评价**（2026-10-24 会话）：报告层 9 项问题——口径不自解释（炸板率三个数关系不明）、情绪判据不透明、次新股混入行业榜、"异动子集"旧文案、操作池指令性表述、黑话不自包含、PC 率归类错位、A50 快照过期误读、资金锚置信度无标注。
2. **2026-10-24 全量代码审计**：10 项业务问题（B1-B10）+ 10 项代码问题（C1-C10），含文件行号定位，均未修复。

**不动的东西（已验证有效，勿重复建设）**：同一实现两入口（链层与报告层共用规则）、逐值对拍机制（指标对拍/涨停家数交叉校验）、三态核验（数据不足≠判错）、口径注记与"不硬造"原则、2026-10-03 情绪判据校准成果（1149 对样本，`config.yaml:138-141`）。

## 二、总体策略

### 2.1 四个修复层次（优先级从高到低）

| 层次 | 回答的问题 | 改动面 |
|---|---|---|
| L1 数据正确性 | 数字本身对不对 | 代码层（改一次长期生效） |
| L2 口径可复核 | 数字对，但读者能不能自己验证 | 报告渲染代码层 |
| L3 表达规范 | 说的方式有没有执行风险 | skill 提示词层（digest_note 每日生成） |
| L4 工程质量 | 快不快、稳不稳 | 代码层 |
| L5 结构增强（可选） | 框架要不要变强 | 代码层，逐项单独授权 |

### 2.2 关键事实（决定方案形态）

- **digest 结构**：`review/digest.py:build_digest()` 渲染图表与固定段落；"复盘解读"（综合研判/操作池/数据质量点名）来自 LLM 按 skill 提示词生成的 `digest_note.md`，经 `md_fragment_to_html` 注入。**所以 L3 类问题改提示词，L1/L2 类问题改代码。**
- **情绪判据已校准**：冰点=高度≤2 或 炸板率≥50%；退潮=溢价均值≤0；高潮=高度≥5 且 溢价≥4%（`config.yaml:138-144`）。`_sentiment_cycle` 已产出判据命中明细（basis）与分位标定四态（quantile_position），**但 digest 只渲染了结论一行，数据在、没展示**——这是 L2 修复成本最低收益最高的一项。
- **回补纪律**：改涨停判定（P0-1/P0-2）会改写历史情绪序列与链 CSV。流程必须是：先改 → 4 个历史日期 A/B diff 量化影响 → 用户看 diff → 再授权全量回补（sentiment_metrics_daily 重算 + 链 CSV 重出）。

## 四、第 1 批 P0：地基修复（数据正确性，6 项）

> 目标：报告里每个数字本身可信。本批不改任何展示，改判定与取数逻辑。
> 批内建议顺序：P0-3 → P0-5 → P0-4 → P0-6 →（P0-1 + P0-2 一起做，最后做，因为涉及历史回补决策）。

### P0-1 涨停判定低价股漏判（B1）｜规模 M｜风险中

- **现状**：`THRESHOLD_OFFSET=0.10` 固定偏移法，主板判涨停阈值≈+9.90%。真实涨停价 `round(preclose×1.1, 2)` 对低价股涨幅不足 9.90%（例：preclose 2.04 → 涨停价 2.24 = +9.80%）→ 系统性漏判低价涨停股。
- **影响面**：连板/炸板/溢价/晋级/R1-R3 候选/全部情绪指标——下游全污染。
- **改法**：阈值法改为**精确涨停价比对**：`limit_price = round(preclose×(1+limit_pct), 2)`，`close ≥ limit_price − 0.001` 判涨停。`limit_pct` 按板块取值（主板 10% / 创业板科创 20% / 北交 30% / ST 5%），与 P0-2 的次新特例共用同一序列函数。
- **验收**：
  1. 单测：构造低价股用例（2.04→2.24 命中）、高价股边界（四舍五入恰在阈值上）、各板块 limit_pct 用例；
  2. 4 个历史日期 A/B 重跑，输出"判定翻转个股清单 + 涨停家数变化"，量化影响；
  3. 与 `limit_seal_stats_daily`（分笔自算封板价）交叉对拍涨停家数（沿用现有涨停家数交叉校验机制）。
- **风险与后续**：判定变化会改写历史情绪序列。A/B diff 出来后**停住**，用户确认差异合理再进入全量回补（见 8.2）。

### P0-2 次新股无涨跌幅限制期误判（B2）｜规模 M｜风险中

- **现状**：`limit_pct_series` 无 `list_date` 概念，`suppress_first_day` 只挡上市首日。注册制上市第 2-5 日无涨跌幅限制：涨幅 25% 收最高被误判"涨停"、冲高回落被误判"炸板"。
- **改法**：`limit_pct_series` 接 `list_date`：注册制板块上市前 5 个交易日内 `limit_pct=None`（无涨跌幅限制），涨停/炸板判定对该股跳过，情绪分母中不计入。
- **附带修复（评价-3，行业榜"次新股"）**：行业等权榜（`sector.industry_today`）混用了 sina_hy 概念板。改法：行业榜仅保留真实行业板；"次新股""ST 板"等概念板若入榜则单独打"概念"标签或移入概念聚集区，不与行业并列。
- **验收**：10-23 重跑行业榜，"次新股"不再以行业身份出现在等权榜；构造"上市第 3 日涨 25%"用例验证不判涨停不进炸板分母；A/B diff 纳入 P0-1 同一份报告。

### P0-3 资金锚数据源编排缺失（B7）｜规模 S｜风险低

- **现状**：`hkex_connect`/`etf_scale` 在 `ALL_SOURCES`（`review_sync_orchestrator.py:50`）但不在 `DEFAULT_SOURCES`（34-41 行），且 `--sources` 显式指定两源还报"未知源名"；326 行 `return list(DEFAULT_SOURCES)` → 只跑 `sync-review-all` 时两源永远不执行，资金锚恒停旧值。
- **改法**：两源并入 `DEFAULT_SOURCES`；修源名校验逻辑（ALL_SOURCES 内的源名应被接受）。
- **验收**：`sync-review-all` 后 `hkex_connect`/`etf_scale` 快照日期=当日；`--sources hkex_connect` 不再报错；报告资金锚节日期新鲜。**这是 P1-6 的前置。**

### P0-4 VETO 财务前视偏差（C3）｜规模 S｜风险低

- **现状**：VETO 业绩查询无 `as_of`/披露日约束 → 用未来公告否决历史候选（前视偏差），历史报告重跑不可复现。
- **改法**：财务查询统一加 `pub_date <= as_of`（披露日以真实 pubDate 为准，已有既定结论）。
- **验收**：构造"公告日 > as_of"用例验证不否决；同一 as_of 两次重跑 VETO 命中清单完全一致（同数据同结果）。

### P0-5 核验滚动统计同日双计（C8）｜规模 S｜风险低

- **现状**：`verifier.py:317` 滚动窗口条件含当日 → 同日重跑战绩双计。
- **改法**：改 `trade_date < as_of`。
- **验收**：同日连续重跑两次，滚动战绩数字不变。

### P0-6 行业归属查询不确定（C2）｜规模 S｜风险低

- **现状**：`_sector_money` 混查 `sw_2021`+`sina_hy` 无 ORDER BY，`seen` 取首行 → 同一股票行业归属取决于返回顺序，违反"同数据同结果"。
- **改法**：明确优先级（sw_2021 优先，无行再落 sina_hy）+ 稳定 ORDER BY；行业榜与资金归集共用同一归属结果。
- **验收**：同数据连续重跑多次，行业归属与资金归集逐值一致；10-23 行业大单归属 diff 为空或全部有解释。

## 五、第 2 批 P1：口径透明度（让每个数字可复核，7 项）

> 目标：非专业读者拿报告能自己验证每个结论。本批全部是报告渲染层，不动判定逻辑，可与 P0 并行授权。

### P1-1 情绪判据对照表（评价-2）｜规模 S｜收益最高

- **现状**：digest 情绪节只有"定位：回暖/震荡（未命中冰点/高潮/退潮判据）"一行（`digest.py:472-475`）。判据、阈值、当日值、分位标定四态全部已算出但未渲染。
- **改法**：情绪节渲染判据对照表（判据｜阈值｜当日值｜命中），并排展示分位标定四态（quantile_position/quantile_basis）。10-23 案例：高度 6 板命中高潮半条件、溢价 3.38% 距 4.0% 差 0.62pct——表格能直接回答"为什么不是高潮"，这正是本次评价中"定位无法复核"的解。
- **验收**：10-23 重跑后情绪节含完整对照表；阈值与 `config.yaml` 逐值一致；分位四态与规则四态分歧时（quantile_divergence=True）有显式提示。

### P1-2 口径字典（评价-1）｜规模 M

- **现状**：三个"炸板"相关数字来自三个不同模块，无任何解释：当日炸板率（情绪表 burst_rate）、题材反馈"炸板修复+0.98% 翻红 55%"（`sector_mainline.py:97-106`，昨日题材股今日表现）、封板质量"首封/开板/一次未炸 49%"（`aggregator.py:1128` 起，F 分笔指标）。
- **改法**：digest 固定渲染折叠式**口径字典**（`<details>` 折叠块；`md_fragment_to_html` 不支持则退化用引用块），逐条定义：涨停家数、炸板率（定义：炸板家数/(封板家数+炸板家数)）、溢价均值、score（10 日窗口相对读数，无绝对含义）、首封、开板、一次未炸、翻红（注明是题材反馈指标非情绪表指标）、R1-R3、P1-P3（一句话+指向报告章节）。
- **验收**：digest 中每个关键术语在字典有条目；`check_digest_numbers.py` 扩展规则：字典条目齐全性校验。

### P1-3 图注与正文数字格式统一（评价-1）｜规模 S

- **改法**：分位类图注统一"当日值 X%（250 日分位 Y%）"格式，杜绝"炸板率 +0.2%"与分位条 4% 并列无解释的混读；score 行附"（10 日窗口相对读数，样本小仅作方向参考）"——docstring 已有此口径（`aggregator.py:1063-1067`），报告未体现。
- **验收**：10-23 重跑全图注人工核对格式统一。

### P1-4 死代码与校准水印（C1）｜规模 S

- **现状**：`aggregator.py:1054-1059` 双 return，第二段不可达 → `trial` 水印永不显示、`sentiment_calibrated` 开关失效（当前 config 已 `true`，行为恰好正确，但开关形同虚设）。
- **改法**：删第二 return；水印逻辑并入首个 return 的 dict（`'trial': not self.sentiment_calibrated`）；digest 定位旁按水印标注"判据试用版"。
- **验收**：单测覆盖开关 True/False 两态渲染。

### P1-5 A50 快照过期自动降级（评价-8）｜规模 S

- **现状**：A50 涨跌幅取"快照最新可得"（`market_env.py:254-262`），间隔 17 天也照常显示 → 10-23 已人工纠正过一次"非隔夜暴跌"。
- **改法**：渲染时计算快照距锚定日天数：>3 自然日自动加注"快照过期（距上次 X 天，涨跌幅为累计值非隔夜）"；>10 天隐藏涨跌幅只留点位。采集侧评估数据源约束内的日频替代源（腾讯/新浪优先级），有则接、无则定性为周频参考源并写入口径字典。
- **验收**：构造过期快照单测；10-23 重跑显示"累计值"标注。

### P1-6 资金锚置信度三档标注（评价-9/B5）｜规模 M｜依赖 P0-3

- **现状**：北向 3131 亿是成交额非净流入（个股明细止于 2024-08-16）、ETF 份额是申赎代理、hkex/etf 因 B7 停旧值——"资金锚中性偏正"的证据强弱混合，报告无任何分级。
- **改法**：资金锚每项加质量标签：**实测**（hkex 互联互通净额等）/ **代理**（ETF 份额申赎方向、北向成交额）/ **停旧值**（红色标注+日期）。综合置信度（高/中/低）随三项状态推导渲染；历史行覆盖率差异按 calib_note 感知（P2 扩面前子集期自动降档）。
- **验收**：P0-3 修复后 hkex/etf 标"实测"；单测覆盖三档与组合态。

### P1-7 "异动子集"旧文案清理（评价-4）｜规模 S

- **现状**：`aggregator.py:361`、`env_assembly.py:427`、`money_trend.py:5,34` 硬编码"P2 前约 300-400 股/日异动子集"注记，P2 扩面后已全市场，属过期口径（10-23 报告数据质量表已自我纠正过一次）。
- **改法**：注记按行级 `calib_note` 动态生成：当日为全市场口径则写全市场；历史区间子集期如实写子集。不再硬编码时点。
- **验收**：10-23 重跑注记正确；构造 as_of 落在子集期的重跑注记同步降级。

## 六、第 3 批 P2：解读层规范（skill 提示词，5 项）

> 改动面：`.workbuddy/skills/stock-analysis-chain/SKILL.md`（508 行）+ `references/analysis_chain_reference.md`（156 行）+ `scripts/check_digest_numbers.py`。
> 本批不改 Python 代码，独立可并行。digest_note 每日由 skill 生成，规范写进提示词即长期生效。

### P2-0 SKILL.md 文档同步（C10）｜规模 S

- 修≥3 处 `tomorrow_candidates` 残留引用（该链 2026-10-18 已删并入 daily_review）；链 CSV 列数描述 12→实际 24；补写 R1 口径差异说明：报告层带弱档否决+情绪开放度/ADX 闸门，链层不带——"链 CSV 命中 9 只、报告 R1=0"是设计行为不是 bug，写清避免每次人工解释。

### P2-1 操作池句式规范（评价-5）｜规模 S

- 规则：决策树要点统一**三段式**："触发条件 → 可考虑动作 → 失效/放弃条件"。禁止无主语裸指令。
- 示例改写："竞价+2%内低吸" → "若竞价涨幅 ≤+2% 且板块龙头高开未炸板，可考虑分批低吸；龙头低开或炸板视为效应断裂，放弃"。
- 表头固定"精选观察池（非推荐）"。

### P2-2 黑话首次定义义务（评价-6）｜规模 S

- 规则：digest_note 中框架术语（P1-P3/R1-R3/首封/翻红/溢价/弱档否决等）**首次出现随文一句话定义**；P1-2 口径字典作兜底，正文不豁免。

### P2-3 数据质量点名表分类规范（评价-7）｜规模 S

## 八、执行顺序、依赖与回补纪律

### 8.1 建议授权顺序（每步独立验收）

```
第 1 步   P0-3 → P0-5 → P0-4 → P0-6        （4 项小修，一两天内全部落地，立刻消除停旧值/双计/前视/不确定）
第 2 步   P1 全批（与第 1 步可并行授权）      （纯报告渲染，10-23 重跑即见效果）
第 3 步   P2 全批（独立，与上并行）           （提示词+校验脚本，10-23 重写验收）
第 4 步   P0-1 + P0-2（改涨停判定）          （代码 + 单测 + 4 日 A/B diff → 停，等用户看 diff）
第 5 步   [用户授权] 全量回补 + 历史报告重出
第 6 步   P3 全批
第 7 步   P4 逐项决策（含缠论）
```

P0-1/P0-2 放第 4 步不是因为不重要（它是最优先的**业务缺陷**），而是因为它是唯一牵动历史数据重写的改动，按"先易后难、先无后效再有后效"的授权节奏，把需要用户看 diff 做决策的放在报告已变好之后。

### 8.2 回补纪律（P0-1/P0-2 专用）

1. 修复后先在 4 个历史日期（含 10-23）A/B 重跑，产出《涨停判定翻转清单》：翻转个股、家数变化、对涨停数/连板梯队/溢价/情绪周期定位的影响；
2. 用户审阅 diff，确认低价股补判与次新剔除方向正确；
3. 授权后全量回补：`sentiment_metrics_daily` 全历史重算（系统起点 2026-09-29，约 18 个交易日，量小）+ 5 条链 CSV 重出 + 历史报告重生成；
4. 重算前后 diff 单独成档，与 A/B 预测一致方可收口。

### 8.3 统一验收纪律（全批次适用）

- 每项修复必须带单测；
- 10-23 重跑 A/B diff：预期变化逐项列出、非预期变化为零；
- "同数据同结果"：任一 as_of 连续重跑两次，报告逐值一致；
- 指标对拍机制沿用，修复不得绕过对拍。
