# 1分钟K线采集性能优化方案 V1.0

## 1. 背景与目标
- 目标：`sync_kline_1min(init_mode=True)` 全量初始化 ≤ 10 分钟（UAT基线）。
- 约束：数据准确性不变（字段计算规则、唯一键 `(ts_code, trade_date, trade_time)`、下游立体K线逻辑保持一致）。
- 支持多数据源扩展：沿用 `DataSourceBase` 抽象，新增统一采集接口。
- 允许结构变更：staging 表、索引治理、（可选）分区表、CSV异步。

## 2. 现状瓶颈（代码位置）
- 采集→归一化→写库→CSV 串行：`backend/src/sync/sync_manager.py:212-532`。
- 写库使用 ON CONFLICT DO UPDATE，且在采集线程内执行：`backend/src/database/connection.py:510-726`。
- CSV 同步写盘：`backend/src/sync/sync_manager.py:403-411`。
- 归一化规则与 preclose 回查：`backend/src/sync/sync_manager.py:1042-1126`。

## 3. 优化方案总览
1. **流水线化**：采集 → 归一化 → staging 批量写 → merge → CSV 异步。
2. **写库优化**：初始化模式使用 staging+merge；增量维持原 upsert。
3. **索引治理**：删除冗余索引，降低写入成本（见第7节）。
4. **CSV 异步化**：从主路径移出，减少 IO 阻塞。
5. **可观测性增强**：细分阶段 wall time、吞吐、批次耗时分布。

## 4. 架构分层与数据流
### 4.1 分层结构
1. Orchestrator（调度与指标）
2. Source Adapter（多源统一采集接口）
3. Normalizer（复用现有归一化规则）
4. Staging Writer（批量落 staging）
5. Merger（集合式合并到主表）
6. Async CSV Writer（异步写CSV）

### 4.2 初始化数据流
采集 → 归一化 → staging 批量写入 → merge → CSV 异步落地 → 生成报告。

### 4.3 增量数据流
采集 → 归一化 → 原逻辑 upsert → CSV 异步落地。

## 5. 采集层（多数据源扩展）
在 `DataSourceBase` 增加统一接口：
- `fetch_kline_all(ts_code, kline_type)`
- `fetch_kline_range(ts_code, kline_type, start_date, end_date)`

现有 `TdxApiSource` 通过适配器映射现有 `get_kline_all/get_kline_history`（`backend/src/data_sources/tdx_api_source.py:87-116`）。

## 6. 归一化层（准确性保持）
- 复用 `_normalize_kline_1min_records`（`backend/src/sync/sync_manager.py:1042-1126`）。
- `preclose/change_rate/turnover_rate` 规则保持一致。
- 可在批内缓存 `preclose`，减少逐条 DB 回查，但计算逻辑不变。

## 7. 写库层（staging + merge）
- 新增 `his_kline_1min_staging`（结构与主表一致、索引最小化）。
- 初始化模式：批量写入 staging（`execute_values`/COPY），再集合式 merge。
- 合并策略：
  1) `UPDATE` 主表匹配键且字段变化记录（`IS DISTINCT FROM`）
  2) `INSERT` staging 中主表不存在记录
- 增量模式继续使用 `upsert_his_kline_1min`（`backend/src/database/connection.py:510-726`）。

## 8. 索引治理（doc/init.sql 建表）

## 9. CSV 异步化
- `CsvWriter.write_his_kline_1min_raw` 从同步路径移至异步队列（`backend/src/sync/sync_manager.py:403-411` → `backend/src/sync/csv_writer.py:302-340`）。
- 初始化模式允许 CSV 异步并行或可配置关闭。

## 10. 并发与批次配置
- 拆分采集线程池与写库线程池，使用有界队列缓冲。
- 新增配置项：采集并发/写库并发/merge批次大小/CSV并发。
- init 与增量分别配置参数（位置：`backend/config/config.yaml:101-113`）。

## 11. 可观测性与验收指标
**报告新增：**
- init 模式各阶段 wall time（采集/归一化/写库/merge/CSV）
- 每分钟写入吞吐、批次耗时分布
- `db_wall_ratio`、`db_time/records`
（报告输出：`backend/src/sync/sync_manager.py:1540-1601`）

**验收指标：**
- 全量初始化 ≤ 10 分钟
- 记录数一致、唯一键约束无异常
- `db_wall_ratio` 明显降低

## 12. 实施步骤（可回滚顺序）
1. 索引治理（删除冗余索引）。
2. 新增 staging 表与 merge SQL（不改现有路径）。
3. init 模式引入 staging + merge。
4. 采集/写库并发拆分，加入队列缓冲。
5. CSV 写入异步化（可开关）。
6. 报告指标增强。

## 14. 风险与回滚
- **staging/merge 失败**：关闭 init 新路径，回退到原 upsert。
- **CSV 异步异常**：回退为同步写。
- **索引删除影响查询**：根据实际查询需求补回索引。

## 14. 验证方案
### 运行验证
- UAT 全量初始化：
  - `python backend/main.py --env uat sync-kline-1min --init`
- 小样本冒烟：
  - `python backend/main.py --env uat sync-kline-1min --init --codes sz.000001,sh.600000`

### 数据一致性验证
- 记录数一致：主表 vs 备份表 `COUNT(*)` 对比
- 唯一键冲突：检查 `(ts_code, trade_date, trade_time)` 重复

### 性能验收
- 全量初始化 ≤ 10 分钟
- `db_wall_ratio`、`db_time/records` 明显下降
