# 日 K 线数据采集技术方案

> 版本：V2.0（重构方案） | 前置调研：本文所有接口行为均经运行中中间件实测验证（2026-09-05）

## 1. 背景与现状问题

当前日 K 采集入口为 `SyncManager.sync_kline_day`（`backend/src/sync/sync_manager.py:280`），数据走 TDX API 中间件的 `/api/kline-history`。实测确认存在以下问题：

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| 1 | **区间采集数据错乱** | `/api/kline-history` 的 `start_date`/`end_date` 参数中间件未实现（文档写了，代码没解析），只返回最近 N 条（≤800） | 按交易日分块（700 条/块）采集时，每个分块返回的都是相同的"最近 800 条"，历史区间数据重复/缺失 |
| 2 | **amount 全部为 0** | 该接口走同花顺前复权源，`Amount` 字段恒为 0（实测 000001 全部 8487 条无一非零） | 库中日 K 无成交额 |
| 3 | **复权基准混杂** | 历史上不同日期分批拉取前复权数据，除权后旧数据未重刷 | 新旧数据拼接处价格断层，涨跌幅计算错误 |

三个问题中 #1、#2 必须通过重构采集逻辑解决，无法在现接口上修补。

## 2. 需求与约束

1. 采集个股日 K 线数据
2. 三种采集方式：**全量初始化**、**指定日期区间**、**日常增量**（增量=特殊的指定日期）
3. 价格直接采**前复权价**
4. **amount 直接接口采集，不自行计算**
5. 数据准确 + 采集高性能
6. 约束：baostock 接口慢且不支持并发（每次单只股票，全市场 5000+ 次调用不现实），日 K 采集仅使用 tdx-api 中间件

## 3. 中间件能力盘点（实测结论）

| 接口 | 复权 | 时间范围 | Amount | 实测表现 |
|------|------|---------|--------|---------|
| `GET /api/kline?type=day` | 前复权 | 上市以来全量 | ❌ 恒为0 | 2-8 秒/只（服务端向同花顺全量拉取） |
| `GET /api/kline-history?limit=N` | 前复权 | 仅最近 N 条(≤800)，日期参数无效 | ❌ 恒为0 | 服务端仍全量拉取，响应小 |
| `GET /api/kline-all`(=`/tdx`) | **不复权** | 上市以来全量 | ✅ 真实值 | 0.5-5 秒/只（800条/批拼接），支持 `limit` 截尾 |
| `GET /api/kline-all/ths` | 前复权 | 上市以来全量 | ❌ 恒为0 | 同 `/api/kline` |
| `GET /api/index` / `/api/index/all` | 指数 | 最近N条 / 全量 | ✅ | 不在本次范围 |

关键事实（实测）：

- **前复权序列会因除权整体重算**：除权日当天跨快照错位 = 每股股利（000001 实测 -0.36 元、600519 实测 -28.02 元）；除权日之后所有正常交易日（含高开低开日）错位为 0（仅 1-2 厘舍入噪声）
- **原始（不复权）序列不可变**：历史 bar 永不变化 → amount 只需追加、永不重刷
- 前复权序列的 `Volume` 是真实成交量（与原始序列仅 ±1 手舍入差异）
- 前复权 `Last` 字段 = 序列内上一条收盘价的机械回显，同快照内永远相等，**除权检测必须跨快照**（新拉 Last vs 库存 Close）

## 4. 总体设计：双源双域

单源无法同时满足"前复权价"和"真实 amount"（同花顺源有价无额，通达信源有额无复权），因此采用**双源双域、按交易日对齐合并**：

```
            ┌─ 同花顺前复权源 ──→ open/high/low/close/preclose（前复权，元）
每股每日 ──┤                                              │ 按trade_date对齐
            └─ 通达信原始源 ────→ amount（真实成交额，元） ──┘
                                              (+ raw_close，可选)
                              ↓
                     his_kline_day 一行双域
```

两条域的更新规律完全不同，采集策略随之分离：

| 域 | 数据特性 | 采集策略 |
|----|---------|---------|
| 前复权价格 | 除权时**整条历史重算** | 增量追加 + 跨快照除权检测 + 命中即整股全刷 |
| 原始成交额 | **不可变**，只增不改 | 纯增量追加，永不重刷 |

## 5. 数据模型调整（his_kline_day）

现有表结构基本满足，调整点：

| 字段 | 调整 | 说明 |
|------|------|------|
| `open/high/low/close/preclose` | 语义固定为**前复权**（元） | `adjust_flag` 统一写 2 |
| `amount` | 数据来源改为通达信原始源（元） | 修复恒为 0 问题；两源对不齐的日期**留空**（数据真实性原则：无法获取不伪造） |
| `volume` | 前复权源的真实成交量（手→股） | 不变 |
| `raw_close`（**新增，推荐**） | 原始收盘价 | 支持本地精确计算复权因子 `k=qfq/raw`，解锁后复权/自定义复权；并作为跨源一致性校验锚点 |
| `trade_status` / `is_st` | 维持现状 | 停牌日两源均无 bar，自然缺失 |

主键不变：`(ts_code, trade_date)`，沿用 `upsert_his_kline_day`。

## 6. 三种采集模式

统一入口保留 `sync_kline_day(init_mode, start_date, end_date, ts_codes)`，CLI 不变（`sync-kline-day [--init] [--start-date] [--end-date] [--codes]`）。

### 6.1 全量初始化（init_mode）

```
对每只股票（线程池并发）：
  1. qfq_full  = GET /api/kline?code=X&type=day          # 前复权全量（上市以来）
  2. raw_full  = GET /api/kline-all?code=X&type=day      # 原始全量（含真实amount）
  3. 按 trade_date 对齐合并（以 qfq 为主表，raw 缺失日 amount 置 null）
  4. 整序列重算 preclose/change_rate，单位换算（厘→元、手→股）
  5. 单股事务原子替换：删除该股旧有全部行 → 批量插入     # 消除历史基准混杂
```

要点：**替换必须整股原子**（一个事务），严禁新旧数据拼接；qfq 8487 条 vs raw 8447 条（000001 实测，早期数据两源条数不齐属正常），以 qfq 为主。

### 6.2 指定日期区间（start_date / end_date）

```
对每只股票：
  1. 同 6.1 的双源全量拉取（中间件无真实区间接口，服务端反正全量拉取，
     "全量拉+内存过滤"与任何区间调用成本相同且正确）
  2. 内存过滤 trade_date ∈ [start, end]
  3. 仅 upsert 区间内的行（preclose 用序列内 Last/前日 Close 计算）
```

不修复、不依赖 `/api/kline-history` 的日期参数（中间件侧未实现）。

### 6.3 日常增量（默认 = 上一交易日）

```
对每只股票：
  1. qfq_tail = GET /api/kline-history?code=X&type=day&limit=2   # 响应小
  2. raw_tail = GET /api/kline-all?code=X&type=day&limit=2       # 响应 <1KB
  3. 除权检测（跨快照）：
       fresh_qfq_last vs 库存上一交易日 qfq close
       |差| ≤ 3厘   → 正常（舍入噪声实测 ≤2厘）
       |差| ≥ 1分   → 该股发生除权/源修订 → 转入 6.1 单股全量重刷
  4. 原始域校验：fresh_raw_close(t-1) vs 库存 raw_close(t-1)
       不一致 → 源数据修订 → 告警并全刷该股
  5. 追加：upsert 新 bar（qfq OHLC + volume + raw amount）
```

要点：

- **自愈性**：除权当天若漏检（宕机等），错位会在后续每天的比对中持续存在，直到全刷完成，事件不丢
- 漏跑多天用指定日期模式补齐
- 边界：序列首条 Last=0 跳过；停牌日无 bar 自然跳过；新股上市首日无上一日 Close，仅追加

## 7. 准确性保障

1. **除权检测**（本方案核心）：实测验证——正常日错位为 0（含全部高开低开日），除权日错位=每股股利，信号唯一且显著；阈值 1 分（0.01 元）远噪声（≤2 厘）
2. **原子性**：每股全刷为单事务替换；增量 upsert 天然幂等，任务可重跑
3. **两源交叉校验**：raw 不可变性校验（每日）+ 全量时两源 trade_date 对齐检查
4. **preclose 口径统一**：qfq 域内取值（Last 优先，缺失回退库存前日 Close），涨跌幅在 qfq 域内计算——除权日涨跌幅自动为真实涨跌，无除权断层
5. **数据真实性原则**：两源对不齐的日期 amount 留空；任何字段不估算、不伪造
6. **基线重建**：上线前执行一次全量初始化，清除现库中基准混杂的历史数据
7. 每日采集报告（现有 report 机制）记录：检测命中数、全刷股清单、两源缺失统计、耗时分布

## 8. 性能设计

实测基线（单股）：同花顺 qfq 全量 2-8s；通达信原始全量 0.5-5s；`limit` 截尾响应 <1KB 但**服务端仍全量拉取**（当前中间件无缓存）。

**P1（不改中间件，随本方案落地）**

- 线程池并发 8-16（复用现有并发框架），独立超时（qfq ≥10s、raw ≥8s）+ 指数退避重试 3 次
- 增量模式用 `limit=2` 小响应，降低传输与 DB 写入（每日全市场增量仅 ~5400 行）
- 批量 upsert 沿用现有 `%s` 批量绑定
- 预估：全市场单轮（全量/增量同墙钟）5400 股 × (2-8s + 0.5-5s) ÷ 12 并发 ≈ **40-90 分钟**，盘后窗口可容纳

**P2（改中间件，源码自有：`oficcejo/tdx-api`）**

- 暴露原始日K单请求接口：Go 客户端已有 `client.GetKlineDay(code, 0, N)`（分钟线 handler 同款调用），把原始尾部获取从全量拼接(1-5s)降到单请求(<0.3s)
- qfq 缓存：中间件缓存同花顺全量序列，用相同的 Last 跨快照检测做失效判定（失效才重新拉 THS），日常增量墙钟可降至**分钟级**
- P2 只改变传输与缓存，不改数据口径，P1 → P2 平滑升级

## 9. 配置项（config.yaml 新增 kline_day 段）

```yaml
kline_day:
  workers: 12                # 并发线程数
  qfq_timeout: 12            # 前复权拉取超时(秒)
  raw_timeout: 8             # 原始拉取超时(秒)
  max_retries: 3             # 失败重试次数
  detect_tolerance: 0.003    # 除权检测容差(元)
  detect_threshold: 0.01     # 触发全刷阈值(元)
  tail_limit: 2              # 增量模式尾部条数
  store_raw_close: true      # 是否存储原始收盘价
```

## 11. 风险与边界

| 风险 | 应对 |
|------|------|
| 同花顺源不可用（qfq 拉取失败） | 重试+告警；**禁止降级写不复权价**（口径污染比缺数更危险），缺失股留待下轮 |
| 两源历史条数不齐（8487 vs 8447） | 以 qfq 为主表，amount 缺失留空，报告中列示 |
| 阈值误判（股价极低的股票 1 分占比大） | 阈值取 `max(0.01, close×0.2%)`，且误判代价仅是一次多余全刷（幂等），无数据风险 |
| 增量漏跑多天 | 指定日期模式补齐；报告比对库存最新交易日与日历 |
| 中间件版本升级改变接口行为 | M1 封装层做启动时接口探活（复用 `/api/health`） |
