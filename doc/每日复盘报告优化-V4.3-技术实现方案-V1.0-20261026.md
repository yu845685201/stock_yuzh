## 四、详细设计

### A1 弱档否决状态渲染补全（tomorrow_plan.py）

**现状**：`gate_note`（435-441）只拼 ADX/MA20；开放度行（455）只含情绪档+ADX 档；`market_weak=True`（仅 ma60_weak 触发，gate=full/half）时两行都显示"开放"，R1 却已被否决——自相矛盾。

**改法**（`adx_info` 字段直接消费，不新计算）：

1. `gate_note` 拼接弱档判定段（ma60 非 None 时恒渲染，market_weak 时加结论词）：

```python
# P1-10 §4.4 弱档判定随行（V4.3 A1）：ma60/market_weak 在 adx_info 已算出，
# 此前零渲染——弱档否决对读者不可见，开放度行与 R1=0 表面矛盾
weak_note = ''
if adx_info.get('ma60') is not None:
    ma60_dir = '↓' if (adx_info.get('ma60') is not None
                       and adx_info.get('market_weak')) else '→/↑'
    weak_note = (f"；MA60 {adx_info['ma60']:.0f}{ma60_dir} vs 收盘 "
                 f"{adx_info.get('close', 0):.0f}"
                 f"——弱档判定{'生效（R1 不开放）' if adx_info.get('market_weak')
                              else '未生效'}")
gate_note = f"指数 ADX 闸门：{gate}（…MA20 …）{weak_note}"
```

2. 开放度行（455）：`market_weak=True` 且 gate ∈ {full, half} 时改为
   `候选开放度：回暖/震荡：R2-R4 开放（R1 因弱档否决不开放——P1-10：收盘<MA60 且 MA60 下行）`；gate=closed 分支（443-446 return）文案不变（本就整类关闭）。
3. `market_weak` 触发源区分：`gate=='closed'` 时 weak_note 标注"触发源=ADX 闸门 closed"；`ma60_weak` 时标"触发源=MA60 简化规则"（两口径取或，`aggregator.py:2447`）。

**验收**：10-23 重生成后六维 md §六 同时可见 "ADX 闸门：full"、"MA60 3881↓ vs 收盘 3690——弱档判定生效（R1 不开放）"、"R2-R4 开放（R1 因弱档否决不开放）"——"3881"从此在 md 可 grep。

### A2 R1 零因三态结构化（aggregator + candidate_rules + tomorrow_plan）

**现状**：`tomorrow_plan.py:508` 空池文案 `'无入选（池数据缺失或无满足规则的股票）'` 两态混写，10-23 实况是第三态"弱档否决"——归因文本错误。

**改法**：

1. `aggregator.py` `_build_candidates` R1 循环（2559-2596）处，对 `streak≥2 且非 ST` 的涨停股逐只记录 `is_r1` 拒绝原因（与谓词判定顺序一致：market_weak 优先 → 开板上限（区分常规/高位板档）→ 封板数据缺失）：

```python
out['R1_filtered'] = r1_filtered  # [{'ts_code','code','name','streak','open_count','reason'}]
# reason ∈ {'weak_veto', 'reopen_over', 'high_reopen_over', 'seal_missing'}
```

   仅统计 `streak≥r1_min_streak 且非 ST` 的行（连板高度不足者不入统计，避免噪声）；`open_count is None` 在 `is_r1` 中视为通过，但 market_weak 日整类拒绝 → reason 统一 `weak_veto`。
2. `tomorrow_plan.py:508` 改为三态（消费 `cand['R1_filtered']` 与 `cand['adx_gate']['market_weak']`）：
   - **弱档否决**：`无入选——弱档否决（触发源：MA60 简化规则）：N 只连板股整类不开放（前 3：{name}({streak}板/开板{oc}次)…）`；
   - **规则筛除**：`无入选——N 只连板股均未过封板规则：开板超限 X 只（{name} 开板{oc}次…）、高位板更严 Y 只`；
   - **池缺失**：`无入选（池数据缺失：当日无连板≥2 截面）`。
3. `candidate_rules.py` 新增 `r1_reject_reason(streak, is_st, open_count, rules, market_weak) -> Optional[str]`，`is_r1` 改为其薄封装（判定与归因单一出处，防两处漂移）；链侧不消费（链行为不变）。
4. 该明细同时喂 A7 的链对账解释：链 3 只 vs 报告 0 只的差异根因从"看代码注释"变成"看报告行"。

### A3 check 规则⑧：来源括注数字换源校验

**现状**：`check_note` 对 `（六维§X|图文§X|报告§|CSV:…）` 括注 ±30 字符内数字直接豁免（`check_digest_numbers.py:38-41,118`）——挂引用免检，引用不验证。

**改法**：

1. 新增 `_report_whitelist(report_path)`：读六维 md（路径由 `--report` 传入，缺省从 note 同目录 `daily_review_<as_of>.md` 推导），`_collect_numbers` + 归一化变体集（千分位 `19,729→19729`、截断 `3881.43→3881`、± 号剥离）。
2. `check_note(note_path, whitelist, report_whitelist)`：来源括注行不再整体跳过——行内数字先对 `report_whitelist` 匹配，命中则放行；未命中再查 `（推断|（计算：` 标注（诚实标注的派生值豁免，如"差 0.62pct（计算：4.0−3.38）"）；仍未命中 → 记入新清单 `cited_ungrounded`（**硬失败**，进 `STRUCTURAL_RULES` 规则⑧，失败说明含行号+数字+上下文）。
3. `run_structural_rules` 签名增加 `report_path`；`main` 增加 `--report` 参数；`--digest` 提供而 `--report` 缺失 → 结构规则⑧⑨判失败并提示补参（与 criteria_cfg 缺 config 同策略，防绕过）。
4. 容错边界：纯 0/一位数、日期/时间/章节号沿用既有结构性豁免；`<100` 的无小数整数不参与⑧（序号/维度计数误报源）。
5. **dry-run 预检**：实施时先对存量全部 note（10-08~10-25）跑一次 ⑧ 只报告不阻断，若误报 >5 处，扩展变体规则后再切硬失败；误报清单进验收记录。

### A4 check 规则⑨：闸门/否决语义一致性

**现状**：无任何机制拦"note 归因与源报告状态矛盾"——本次事件里若 note 真写错（如写"ADX 闸门关闭"），机器不拦。

**改法**（A1 落地后 md 有明确状态行可比对）：

1. 解析六维 md 的两行状态：`候选开放度：`（提取 R1 开放/弱档否决/四类全开）与 `指数 ADX 闸门：`（提取 full/half/closed 与"弱档判定生效/未生效"）。
2. 扫描 note 中含触发词 `闸门|否决|整类关闭|零开放|全开` 的行，语义比对：
   - note 声称 R1/系列被否决、关闭 → md 须含"弱档判定生效"或"闸门：closed"或定位冰点/退潮；
   - note 声称全开/开放 → md 不得含"弱档判定生效（R1 不开放）"。
3. 矛盾 → 规则⑨硬失败，说明文给出两侧原文行。
4. 仅匹配含触发词的行（叙述句"涨停 84 家全开"之类不触发；词表收窄避免误报，实施时以存量 note dry-run 校准词表）。
