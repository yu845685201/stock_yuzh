## 三、发现并修复：前复权基准断裂（本次重点）

### 现象
09-10 的 `close` 与 09-11 的 `preclose` 对不上，例如：

| 股票 | 库内 09-10 close | 源端 09-10 close | 偏差 |
|---|---|---|---|
| sz.300908 仲景食品 | 25.49 | 17.58 | -45% |
| sz.000703 恒逸石化 | 18.00 | 17.10 | -5.3% |
| sh.600016 民生银行 | 3.65 | 3.53 | -3.4% |

### 根因
105 只股票在 **09-11 除权**。前复权序列以最新交易日为基准，除权后源端**整段历史**都会被重算；而库内 09-10 及更早的数据仍是旧基准 —— 只补新区间、不重算历史，序列就会断裂。

区间补齐模式按设计**跳过除权检测**（`sync_manager.py:430`，条件含 `not is_explicit_range`），所以该问题不会自动修复，也不会报错。

### 检测
逐对相邻交易日比较 `x.close` 与 `y.preclose`（容差 0.1%）：

| 相邻对 | 不一致股票数 |
|---|---|
| 20260910 → 20260911 | **105** |
| 20260911 → 20260914 | 0 |
| 20260914 → 20260915 | 0 |
| 20260915 → 20260916 | 0 |
| 20260916 → 20260917 | 0 |
| 20260917 → 20260918 | 0 |

断裂只出现在除权日那一对，可用于定位除权日。

### 修复
1. **备份**：`his_kline_day_bak_refetch_20260920`（318,324 行 / 105 只，重拉前快照）
2. **小批量验证**：先重拉 3 只，核对根数与源端完全一致（300908=1415、000703=6968、600016=6182）
3. **全量重拉**：`--init` 走 `replace_his_kline_day`（单事务 DELETE + 整股重插）
4. **循环重试收尾**：qfq 全量接口会间歇返回 HTML 错误页，反复重跑"`update_time` 未推进"的股票，3~4 轮后收敛

### 结果
- 105/105 全部刷新完成
- **根数减少的股票数 = 0**（无数据丢失）
- 前复权链在 09-10 → 09-18 全链不一致数 = **0**

## 四、遗留问题（外部数据源限制）

**12 只股票的源端前复权数据本身缺最新值**（`raw` 有数据、`qfq` 没有，`refresh=1` 强制回源也拿不到）：

**原因**：`_merge_kline_day_sources` 以前复权序列为价格主表，主表没有的日期直接丢弃（`sync_manager.py:673`），没有 raw 兜底逻辑。
**影响**：这 12 只股票（占 5,200 只的 0.23%）的 max_date 停在 09-11 ~ 09-14，重试无效。
**建议**：如需覆盖，需在代码层增加"qfq 缺日期时用 raw 价格 + 复权因子兜底"的逻辑 —— 属设计变更，需另行评估。
