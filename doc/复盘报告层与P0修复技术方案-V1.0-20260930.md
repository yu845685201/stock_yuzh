背景事实（2026-09-29 数据充分性审计 + 本方案编写时逐项核实）：

- 阶段1 的 8 个分析模块与 `chains/daily_review.yaml` 已于 09-29 建成（覆盖六维中的「市场情绪」「个股异动」），但**报告聚合层（`backend/src/review/`）、`doc/复盘框架.MD`、review generate CLI 均不存在**；

## 一、P0-1：is_st 死列修复（M0a）

### 1.1 根因与现状

- `his_kline_day` 建表含 `is_st BOOLEAN`（init.sql:295，注释「是否ST股」），但 `dao_kline_day.upsert_his_kline_day` / `replace_his_kline_day` 的写入列不含它 → 全列 NULL；
- 读取侧 `data_reader.load_kline` 以 `(CASE WHEN k.is_st THEN 1 ELSE 0 END)` 直读（data_reader.py:218），NULL → 0；
- `precheck` 装载 kdf 后，`limit_up_rules.limit_pct(board, date, is_st)` 据此取阈值：主板 ST 应 5%（判定 4.90），现按 10%（9.90）→ **ST 股涨停/跌停/炸板判定全漏**，连板梯队、晋级率、炸板率全部失真。

### 1.2 修复设计（红线内最小修法，零新数据源）

**（1）写入侧：DAO 单一出口派生。** 在 `dao_kline_day.py` 两个写入方法入口（`upsert_his_kline_day`、`replace_his_kline_day`）统一派生：

```python
# 行 dict 已含 stock_name（upsert 的 DO UPDATE SET 含该列），派生规则复用既有实现
from ..utils.data_transformer import DataTransformer
row['is_st'] = DataTransformer.check_is_st(row.get('stock_name') or '')
```

- 同步把 `is_st` 加入 `_KLINE_DAY_COLUMN_SQL` 与 `DO UPDATE SET is_st = EXCLUDED.is_st`（改名/摘帽后重刷能正确翻转）；
- 单一出口覆盖两条写入路径（日K增量 pipeline、全量初始化），不散落各调用方；
- `DataTransformer.check_is_st` 已存在（utils/data_transformer.py:173，名称含 ST 判定），不新写规则。

**（2）存量回填：一次性 SQL（幂等，可重跑）。**

```sql
UPDATE his_kline_day
SET is_st = (stock_name LIKE '%ST%')
WHERE is_st IS DISTINCT FROM (stock_name LIKE '%ST%');
```

- 预计影响 ~200 只 ST × 各自历史行数；若锁表顾虑则按 ts_code 首字母分批。执行后 `SELECT count(*) FROM his_kline_day WHERE is_st` 应与 `stock_name LIKE '%ST%'` 行数一致（断言写进验收脚本）。

**（3）读取侧不改**（`load_kline` 的 CASE 表达式保持）。

### 1.3 口径声明（必须写进数据字典与报告口径注）

行内 `stock_name` 是**同步时点名**。2026-09 全量重初始化后，历史行均携带 2026-09 时点名称 → **戴帽/摘帽切换日之前的历史行存在误标**（摘帽股历史被多标为 ST、戴帽股早期被漏标）。影响面评估：ST 状态变更每季度十余只，对 60 交易日窗口内聚合指标（梯队/晋级率/炸板率）影响为个位数股票 × 切换日前数日；对历史回测类研究需知悉此口径。`is_st` 的准确口径定义为「**该行同步时点的名称含 ST**」，非「该交易日时点 ST 状态」。

**可选增强（独立决策项，不阻塞本修复）**：baostock `query_history_k_data_plus` 的 `isST` 字段可提供 2016 年起的逐日真实 ST 状态（上游实测 000004 有 276/610 交易日 isST=1），用于精确回填。代价：串行（用户既定约束，禁止并发）全市场 5200+ 股 ≈ 一次性 2~3 小时（与已接受的 THS 财报全量同步同量级）。**注意**：上游方案红线文本将 baostock 列入排除项，若启动需用户拍板并走数据源变更评审，本方案默认**不做**。

### 1.4 验证与验收

1. pytest：构造含/不含 ST 名称的行 dict，断言 DAO 派生与回填口径一致；`check_is_st` 对 `*ST`、`ST`、`S*ST`、正常名的边界用例；
2. 回填后人工抽验：取 5 只 ST、5 只正常股近 3 日行，`is_st` 与名称一致；
3. 复跑 `analyze run --chain daily_review --as-of <最近交易日>`，涨停家数应上升（新纳入 ST 涨停），抽查 1~2 只 ST 股连板数与行情软件一致；
4. 全量 pytest 零回归（基线 275 用例）。

## 二、P0-2：北交所日K与入池（M0c）

### 2.1 目标

北交所标的进入 `base_stock_info` + `his_kline_day` → 分析 universe 自动纳入（`load_stock_universe` 基于 base_stock_info，`board_of` 已支持 4/8/92 前缀 → 北交所，`limit_pct` 北交所 30% 已实现），"全市场"口径成立；同时获得**全市场收盘对拍源**（盘后包覆盖沪深北，可交叉校验现有沪深日K）。

### 2.2 探路先行（1 天，不可跳过）

| # | 探路项 | 方法 | 结论用途 |
|---|---|---|---|
| T1 | tdx-api 中间件是否直接支持北交所 | 用 920xxx 代码实测 `/api/kline-all`、`/api/kline-all/ths`、`/api/ths-factor`、`/api/xdxr`（3 只：920982 锦波生物、920185 贝特瑞、920575） | 决定主链路走方案 A 还是 B |
| T2 | 通达信官网盘后包实测 | 下载最近 3 个交易日 `g4day/{ymd}.zip`，解析后与库内沪深日K对拍（对拍 `raw_close` 列，**不是 `close`**——库内 close 为前复权口径） | 验证解析正确性 + 对拍容差 |

### 2.3 双方案设计

**方案 A（T1 全通过）**：北交所走既有 per-stock 链路。改动点：`base_stock_info` 补北交所标的清单（来源仍可用盘后包 cod 文件，见 2.4）→ `sync_kline_day` 的股票清单自然包含 → `kline_day_pipeline` 照常跑（前复权价 + 复权因子均由 tdx-api 覆盖）。改动最小，优先争取。

**方案 B（T1 任一失败）**：新增逐日包通道，北交所日K不入 per-stock pipeline：

- 新源 `backend/src/data_sources/tdx_official_source.py`，class `TdxOfficialSource(HttpCollectorBase)`，单方法 `fetch_daily_package(ymd) -> List[dict]`：下载 zip → 解析 → 返回沪深北全量行（含 market/code/name/prev_close/OHLC/volume/amount）；
- 新 manager `backend/src/sync/bj_kline_manager.py`：对给定交易日取包 → 过滤 `market='bj'` → 组装 `his_kline_day` 行 upsert（见 2.5 口径）→ 顺带产出**沪深对拍报告**（与库内 raw_close 逐股 diff，差异清单落 `doc/reports/`）；
- CLI：`sync-bj-kline --trade-date yyyyMMdd [--days-back N]`（回补历史用，逐交易日循环取包）。

两方案共同项：盘后包对拍纳入日常数据审计（对拍规则见 2.6）。

### 2.4 盘后包技术规格（引自 doc/reference/a-stock-data/SKILL.md §1.3，实测 2026-09-20，坑记录随实现抄入 docstring）

- URL：`https://www.tdx.com.cn/products/data/data/g4day/{ymd}.zip`（ymd=yyyyMMdd），HTTP 下载约 2.7MB；
- 结构：每市场一对文件 `{sh|sz|bj}{yyMMdd}.cod`（代码表，150 字节/条）+ `.md1`（行情块，512 字节/块）；
- 二进制布局（小端）：cod 条目 `code=record[0:6]`（ASCII 6 位数字）、`seq=<H record[32:34]`（对应 md1 块号）、`name=record[40:72]`（GBK，NUL 结尾）；md1 块 `prev_close=<d [4:12]`、`open/high/low/close=<4d [12:44]`、`volume=<Q [56:64]`、`amount=<d [72:80]`；
- 单位：volume 股、amount 元；
- 校验（**宁抛错不返回空表**，全部按格式残缺抛 RuntimeError）：cod/md1 长度整除、条数与块数一致、代码 6 位数字且无重复、seq 无重复且不越界、价格/成交额为有限数（防 NaN 绕过 close≤0）、逐市场有价行数下限（sh 10000 / sz 3000 / bj 50，下限来自 11 个真实包实测最小值，防北交所静默缺失）；
- 边界：`close<=0` 的行是通达信自编板块指数（880/881 等）非证券，跳过；北交所文件自 **2022-05-06** 起（此前包无 bj 文件，不报错；此后缺 bj 文件按格式改变报错）；非交易日/当日未发布（通常收盘后数小时）官网返回 **404** → 抛 ValueError（不返回空表）；官网保留范围实测 2021-01-04 已 404、2022-01-04 可取，未逐日验证；
- 限速：`review_sync.tdx_official_interval`（初始 2.0s，每交易日仅 1 请求，无压力）。

### 2.5 北交所入池与入库口径

- **标的清单**：`base_stock_info` 补录（ts_code 后缀 `.BJ`；source 为盘后包 cod；`list_status='L'`、`market_name='北交所'`、`list_date=NULL`——cod 无上市日，注明口径：北交所股「上市首日不判定」逻辑退化为不可判，模块按数据不足处理，可接受）。`board_of` 已支持，无需改。
- **日K行口径**（方案 B）：`close = raw_close = 包内原始价`（北交所暂无复权因子 → 因子按 1 处理）；`preclose = 包内 prev_close`；`change_rate = (close-preclose)/preclose×100`（**当日内比值，不受复权影响，天然正确**）；`volume/amount` 直接入库；`adjust_flag` 按不复权口径标注；`is_st` 由 P0-1 的 DAO 派生自动覆盖（名称来自 cod，含 \*ST 形态，如 \*ST康乐 920575）；
- **已知口径局限（写进数据字典）**：北交所历史前复权序列在除权事件处会断裂（无因子重算机制），对拍审计监控（2.6）；若 T1 证实 `/api/ths-factor` 支持北交所则方案 A 无此问题；
- **turnover_rate**：依赖 `base_fundamentals_info.float_share`。THS 财报清单为 5559 只（多于沪深日K 5222 只），预计已含北交所，实施时验证；缺股本的行 turnover_rate 留空（数据真实性原则：无法计算留空）。
- **交易日历**：`base_trade_calendar` 为沪深口径，北交所交易日与之相同（A 股统一休市），抽查 2022-05-06 起若干节假日确认即可。

### 2.6 对拍审计（沪深亦受益）

- 规则：盘后包行 vs `his_kline_day` 当日行，`raw_close` 差异 > 0.01 元、或包内有价而库内缺失（非当日增量滞后）→ 计入差异清单；
- 输出：`doc/reports/tdx_official_audit_YYYYMMDD.md`（差异股数、抽样明细、结论）；差异率 > 0.5% 视为异常，人工介入；
- 频率：随 `sync-bj-kline` 每日执行（一次请求顺带完成，零额外成本）。

### 2.7 编排与配置接线

- `review_sync_orchestrator`：方案 B 时新源 `bj_kline` 注册进 `SOURCE_WAVES` 波1（独立源，不依赖 kline 伪源）；`SOURCE_LABELS` 加「北交所日K」；
- `config.yaml` → `review_sync:` 新增 `tdx_official_interval: 2.0` 与 `bj_kline: {enabled: true}`；
- `sync-review-all` 缺省源集自动包含（进 DEFAULT_SOURCES）。

### 2.8 验收

1. `base_stock_info` 北交所标的数 ≈ 250+（对拍东财口径无法使用，以盘后包 cod 为准 + 与北证50 成分股抽查）；
2. 北交所日K自 2022-05-06 起无断档（逐月行数核对，京市场每日有价行数 ≥ 50 下限已由解析校验保证）；
3. `analyze run --chain daily_review` 后 universe 含北交所股，北交所涨停（30% 阈值）判定抽查正确；
4. 沪深对拍差异率 < 0.5%，报告落盘；
5. pytest 新增：解析器用例（构造二进制 fixture：正常/截断/缺文件/404/非有限值/下限不足各一）+ manager 组装用例。

## 四、P0-4：北交所老号段防御（M0b，S）

事实（上游实测 2026-07-31）：在市 342 只北交所中 336 只已迁 `920xxx`（如 832982→920982、835185→920185）；老码（43/83/87 段）在外部接口普遍返回**僵尸数据且 HTTP 200**（东财研报静默 0 篇、腾讯定格报价成交量 0）。

本工程语境下的实际暴露面很小：北交所代码唯一入口将是盘后包 cod 文件（P0-2），给的是**当前在市新码**，老码天然不入库；`board_of` 已将 4/8/92 全段归北交所。故本项收敛为两条防御规则：

1. **入库校验**：`bj_kline_manager`（或方案 A 的清单补录）对北交所代码白名单 `43x/83x/87x/920x`（920 尚未全启用、921 未启用），命中 921+ 或其他形态 → 抛错不入库（宁抛错不静默）；
2. **数据审计规则**：`his_kline_day` 中北交所代码若出现「当日全市场有行情而该股 volume=0 且 close=preclose」连续 ≥ 5 日的行 → 疑似僵尸码，审计报告告警（防未来号段再迁移时静默错数据）。

不实现自动老码→新码映射（无官方对照表，且盘后包直接给新码，无映射需求）。pytest：白名单与审计规则用例各 2。

## 五、复盘报告层（M1/M2，本方案主体）

### 5.1 前置交付物：`doc/复盘框架.MD`（先于代码，1~2 天，含用户校准）

作为「复盘教材 + 开发验收依据」，章节结构：

1. 四问框架（今天市场怎么样→钱在哪些方向→谁在异动→明天怎么办）；
2. 六维逐维定义：每维的指标清单、**计算口径（与本方案 5.3 一一对应）**、解读方法（指标高低对应的市况判断）；
3. 情绪周期判据表：冰点/回暖/高潮/退潮的空间板高度、炸板率、晋级率、涨跌停对比阈值（**初始值由本方案给出占位，用户校准后定稿**——校准前报告输出「判据试用版」水印）；
4. 数据源映射与已知口径局限（is_st 口径、北交所前复权局限、概念覆盖口径等，汇聚各数据字典声明）。

### 5.2 包结构（`backend/src/review/`，新建）

```
backend/src/review/
├── __init__.py
├── cross_section.py    # 向量化截面判定：涨停/跌停/炸板/连板/新高新低（复用 limit_up_rules，供聚合器重算历史截面）
├── aggregator.py       # 六维聚合：输入 DataReader/DAO 取数，输出 dict[维度] -> AggregationResult
├── sections/           # 每维一个纯函数模块（读聚合结果 → 生成章节内容结构）
│   ├── market_env.py       # 维度1 大盘环境
│   ├── sentiment.py        # 维度2 市场情绪
│   ├── sector_mainline.py  # 维度3 板块主线
│   ├── stock_movers.py     # 维度4 个股异动（明细表）
│   ├── fundamentals.py     # 维度5 业绩估值
│   └── conclusion.py       # 维度6 结论预案
├── renderer.py         # MD 组装 + HTML 渲染（内联 CSS 模板，零外部依赖）
└── generator.py        # 编排：取数→聚合→渲染→落盘；同锚定日重复生成逐字节一致
```

**关键设计决策——指标独立计算，不依赖历史链 CSV**：晋级率、昨日涨停今日溢价等需要 T-1 截面；若依赖「昨天跑过链」的 CSV，长假后首日/漏跑日报告即断。故聚合器基于 `DataReader.load_kline`（60 交易日窗口）+ `cross_section.py` 向量化**重算**任意截面；当日链 CSV（`data/analysis/daily_review_{as_of}.csv`）仅用于**明细罗列**（含是否存疑列）与**交叉校验**（重算涨停家数 vs CSV 涨停家数，不一致在报告尾部告警）。

### 5.3 六维数据映射与计算口径

约定：`as_of` 为锚定交易日；`prev` 为上一交易日；DF=由 `load_kline` 加载的全市场 60d 窗口（列：ts_code/stock_code/stock_name/trade_date/close/preclose/high/low/change_rate/volume/amount/is_st）。

**维度1 大盘环境**（sections/market_env.py）

| 指标 | 来源 | 口径 |
|---|---|---|
| 指数涨跌与位置 | `trade_index_info`（上证/深成/创业板/科创50/北证50/沪深300） | 当日涨跌幅 + 收盘相对 60d 高低位置（百分位） |
| 两市成交额及增减 | DF 沪深（及北交所，P0-2 后）分组 | `sum(amount)` 今 vs 昨，差额与百分比 |
| 上涨/下跌/平盘家数 | DF 当日截面 | `change_rate` 三分计数（剔除停牌无成交行） |
| 涨停/跌停家数对比 | `cross_section` 重算 | 判定同链模块口径（阈值法+护栏） |
| 外围市场 | `overseas_market_daily` | 美股三指数、汇率（当夜数据以最新可得标注日期） |

**维度2 市场情绪**（sections/sentiment.py，全部由 cross_section 重算）

| 指标 | 口径 |
|---|---|
| 连板梯队 | 当日连板股按高度分组计数（2板/3板/…/N板），`consecutive_limit_up` 同口径（连续涨停交易日数，剔除盘中开板后回封口径沿用链模块定义） |
| 空间板高度 | 当日最高连板数 |
| 炸板率 | 当日炸板家数 ÷（涨停 + 炸板家数） |
| 昨日涨停今日溢价 | 昨日涨停股今日 `change_rate` 均值 / 中位数；涨停股今日续涨停单独计数 |
| 晋级率 | 今日 N 板家数 ÷ 昨日 (N-1) 板家数（N=2..空间高度） |
| 情绪周期定位 | 维度6 判据表（5.1 第 3 章定稿阈值） |

**维度3 板块主线**（sections/sector_mainline.py）

| 指标 | 来源 | 口径 |
|---|---|---|
| 行业涨跌榜（今/5日） | `sector_concept_map`（source 优先 sw_2021，缺失股回退 sina_hy；按 in_date≤as_of<out_date 时点匹配）× DF | 行业内个股**等权**涨跌幅均值，今日榜 + 5 日累计榜 Top10/Bottom5（流通市值加权列为后续增强，口径注明等权） |
| 板块涨停聚集度 | 概念 `sina_gn` × 当日涨停股 | 概念内涨停家数、占成分比；聚集度 = 概念涨停家数排序 |
| 主线识别 | 上述两项交叉 | 5 日行业榜前列 且 当日涨停聚集前列 → 主线候选；高低切换观察 = 今日榜与 5 日榜位次变化 |

**维度4 个股异动**（sections/stock_movers.py，明细表为主，读链 CSV）

涨停明细（代码/名称/连板数/行业/概念/是否 ST）、跌停明细、炸板明细、放量大涨 Top N（`volume_surge`≥2 且 `big_mover`=大涨，按成交额排序）、60 日新高/新低列表。N 由 config `review.top_n` 控制。

**维度5 业绩估值**（sections/fundamentals.py）

| 指标 | 来源 | 口径 |
|---|---|---|
| 披露日历 | `base_disclosure_calendar` | 未来 5/10 个交易日预约披露家数分布；当日实际披露家数（4.4 actual 回填） |
| 业绩预告 | `performance_forecast` | 当日新增预告摘要（预增/预减/扭亏分类计数 + 代表性条目）；预告空窗期标注 |
| 个股估值 | `stock_valuation_daily`（自算） | 全市场 PE/PB 分位数分布；当日 PE 与历史分位极端值 Top N |
| 指数估值 | `index_valuation_daily` | 沪深300 等指数 PE（pe_static 口径，注明无 TTM） |

**维度6 结论预案**（sections/conclusion.py）：情绪周期定位（判据表）+ 明日关注（主线候选 + 梯队关键股 + 披露日程）+ 风险提示（炸板率/亏钱效应信号 + 数据口径局限）+ 免责声明（固定文案）。

**缺数据标注规范**：某维度输入表为空或链 CSV 缺失 → 章节渲染为「⏳ 待补：{缺什么}（{原因：表空/未采集/未跑链}）」，禁止留空或编造（数据真实性原则）。

### 5.4 渲染层（renderer.py）

- MD 为源 → 同名 `.html`（轻量模板、内联 CSS、无外部依赖，表格斑马纹即可，不做图表库）；
- 输出路径：config `review.output_dir`（默认 `doc/reports/`，符合上游方案），文件名 `daily_review_YYYYMMDD.md/.html`；
- **同锚定日重复生成逐字节一致**（沿用 result_writer 稳定性要求）：正文不出现运行时间戳（数据时点以 as_of 表达），生成耗时等元信息写 `daily_review_YYYYMMDD.meta.json`；
- 章节头部统一带「数据口径说明」链接指向复盘框架.MD 对应章节。

### 5.5 CLI 与每日流程

- `backend/src/cli/review_sync_cli.py` 新增命令组 `review`，子命令 `generate`：`run_cli.py review generate [--as-of yyyyMMdd] [--output-dir PATH]`；注册进 `main.py`；
- 每日流程（文档化，暂不强制串联）：`sync-review-all` → `analyze run --chain daily_review` → `review generate`；M2 后视稳定性考虑 `review all` 一键串联（暂不做）；
- `review generate` 对链 CSV 缺失采取降级：明细章节标待补，指标章节不受影响（独立重算设计使然）。

### 5.6 配置（config.yaml 新增 `review:` 段）

```yaml
review:
  output_dir: doc/reports      # 相对 stock_yuzh/ 或绝对路径
  top_n: 20                    # 明细表行数上限
  volume_surge_min: 2.0        # 放量大涨入选倍数
  industry_sources: [sw_2021, sina_hy]   # 行业映射优先级
  sentiment_rules: {...}       # 情绪周期判据阈值（复盘框架.MD 定稿后同步）
```

### 5.7 测试与验收

1. `cross_section.py`：向量化判定 vs 链模块逐股判定**对拍用例**（fixture df 同输入，结果必须一致——这是独立重算正确性的保证）；
2. 聚合函数：纯函数 + 构造 fixture（含 ST 股、北交所股、停牌行、数据不足行边界）；
3. 渲染：golden file 对比（固定 as_of 的 UAT 快照）；
4. 集成：UAT 库 `review generate --as-of 20260929` 产出报告，关键数字（涨停家数/成交额）与手工 SQL 抽查一致；
5. 验收（对应上游方案 §四）：盘后一条命令链生成当日 MD+HTML；可支撑章节全部呈现、缺数据章节明确「待补」；报告含口径说明与免责声明；全量 pytest 零回归。

### 5.8 性能

60d 窗口 ≈ 5200+ 股 × 60 日 ≈ 31 万行，`load_kline` 走 `_copy` 流式（链引擎同量级已验证）；聚合全部向量化；单次生成目标 < 60 秒（UAT 实测记录进 meta）。

## 七、共性规范（全部沿用，逐条核对）

1. **新数据源**：继承 `HttpCollectorBase`；文件头含安全红线声明（串行限速、正常 UA/Referer、不破解技术措施、风控识别即退避冷却、仅自用）；上游坑记录抄入 docstring（实测日期、失效模式、校验逻辑）；`review_sync` 段加独立 interval；编排器注册进波次；
