## 0. 项目定位与设计哲学

Vibe AStock 是 A 股短线复盘与跟踪工作台（本地浏览器页面 `127.0.0.1:5940`，后端 API `8770`）。v2.0.0 起换用同作者 Vibe Research 的底座：Node/TypeScript 编排 + React 前端 + Python 取数/计算子进程。

复盘功能的三条设计红线（贯穿全部代码）：

1. **程序算数、AI 只解读**：行情与统计全部由程序确定性计算；AI 复盘只能用程序打包的"资料包"写定性文字，每个数字事后由程序核对出处。
2. **缺口不当 0**：任何一块数据没取到，写明原因，绝不显示成 0（"炸板池失败按 0 家算，炸板率 0%，看着是情绪最好的一天"是代码注释里明确记录过的历史 bug）。
3. **不预测、不给建议**：复盘只写"主要观察 / 反证与缺口 / 接下来看什么（带前提的条件）"，禁止买卖、仓位、点位。

复盘相关代码位置：

| 层 | 路径 | 职责 |
|---|---|---|
| 编排层 | `orchestrator/src/finance/shortline/` | 五段式 AI 复盘（review.ts）、周报（weekly_review.ts）、明日验证（verification.ts）、涨停样本（samples.ts）、结构变化（structure.ts）、情绪历史（history.ts）、收盘取数定时任务（close_fetch.ts） |
| 取数层 | `.agents/skills/data-access/scripts/sources/` | 东财四池（shortline.py）、情绪指标（shortline_emotion.py）、题材树（shortline_themes.py）、盘面事实（shortline_facts.py）、盯盘（shortline_watch.py / shortline_live.py）等 |
| 数据注册 | `datasources/registry.json` + `CATALOG.md` | 182 个端点、35 层，其中短线专用 14 个 `cn_shortline_*` |

## 一、复盘功能

### 1.1 复盘功能全景

v2.0.0 的"复盘"一级栏目下有两个二级页面，加上若干支撑模块构成完整闭环：

| 模块 | 性质 | 内容 |
|---|---|---|
| **情绪复盘**（8 个分页） | 短线复盘主页面 | 今日情绪、AI 复盘、AI 周报、近 5 天、情绪历史、明日验证、涨停样本、结构变化 |
| **每日复盘** | 全市场复盘页面 | 市场状态八格、短线情绪、中长线、资金去向 |
| 盯盘 · 竞价与盘中 | 复盘的盘中原料 | 昨日涨停股 09:25 竞价强弱 + 六时点情绪路径快照 |
| 短线收盘取数（定时 15:35） | 数据保全 | 把当天定稿读数存到本机（对抗上游只留 30 天） |
| 交易日志 | 复盘的个人闭环 | 每笔交易自动对上入场日情绪与板位，复查"看错了还是没做好" |

复盘日默认是**最近一个已收盘交易日**（收盘后 5 分钟才算"已收盘"，等收盘集合竞价成交回写）；未来日期和非交易日直接拒绝——源码注释明确写了原因："上游对它们返回空池，下游会如实算出『涨停 0 家』，读起来像真实行情"。

### 1.2 今日情绪（程序直出的读数，AI 复盘的原料）

端点 `cn_shortline_emotion`（约 8 次东财请求，串行限流下 10–20 秒）+ `cn_shortline_cycle`（情绪周期，单独端点因为要拉 10 天池子、最慢）。四个核心指标：

- **赚钱效应**：昨日涨停股今天的中位数、均值、翻红率、再度涨停率。优先用东财"昨日涨停池"定稿记录（任何历史日都算得出），拿不到才退回腾讯实时行情，并有**覆盖率闸门**（<50% 判不可用、<90% 标 partial）。
- **晋级率**：1进2 / 2进3 / 3板以上晋级三档，逐只对照昨日涨停池与今日涨停池成员计算。
- **连板溢价**：昨日 2 板以上个股今天的平均/中位涨幅。
- **梯队断层**：全市场板位结构有没有缺档（如有 5 板和 2 板、没有 3-4 板 → 高标"悬空"）。

另有情绪周期（近 10 个交易日涨停数/最高连板/炸板率各自窗口内归一化取平均的**相对分**，定位距低点第几天、走向），代码明确警告"这是相对读数，没有绝对含义"。

### 1.3 AI 复盘（核心：五段式 + 程序核对）

移植自 v2.0.0 的 `review_agent/daily.py + grounding.py`，编排实现在 `review.ts`（约 700 行）。

#### 1.3.1 五段划分与资料映射

| 段 | 资料来源（端点） | 写什么 |
|---|---|---|
| 情绪 sentiment | `cn_shortline_emotion` + `cn_shortline_cycle` + `cn_shortline_facts` | 赚钱效应、晋级率、连板溢价、梯队断层、封板质量、亏钱效应、情绪周期位置 |
| 资金 capital | `em_market_trend`（指数+两市成交额 60 日）+ `em_market_margin`（两融）+ `cn_shortline_turnover_top`（成交额前十）+ `em_board_fund_flow`（行业资金流，备源 `sina_board_flow`） | 成交额与近几天比、两融余额与融资净买入、成交额前十集中方向、行业资金流；**明确禁止用"主力""游资"解释** |
| 题材 theme | `cn_shortline_themes`（题材事件树）+ `cn_shortline_firstboard`（首板名单） | 哪些题材涨停多、首板连板构成、头部集中度、与前一天比延续情况、首板首封时间 |
| 龙虎榜 dragon_tiger | `em_daily_dragon_tiger`（按净买额排，cap 前 20 后 10） | 上榜条数、净买额居前/居后、上榜理由；只描述榜单本身 |
| 龙头 leader | `cn_shortline_emotion` + `cn_shortline_ladder`（昨日梯队）+ `cn_shortline_facts` | 最高标是谁几板、各档断层、昨日梯队今日反馈、分制度（10cm/20cm/北交所）最高板 |
| 汇总 summary | 无自己的资料包，只看前五段正文 | 3-5 句最重要的几点、分项之间的矛盾、明日验证建议（json 代码块） |

#### 1.3.2 执行流程

```
开一次复盘（action=start）
  ├─ 校验：date 合法、≤今天、接了 AI
  ├─ 容量检查：同一天不能同时写两份；日复盘+周报合计最多同时 2 份（ensureCapacity，含"取资料中"占位防并发穿透）
  ├─ 取资料包：11 个来源并发 3 路取一次（consistency=prefer_cache），各段共用
  │    ├─ 情绪数据一条都没有 → 整次不开（no_data）："多半不是交易日/没开盘/东财整片没取到，写出来只会是空话"
  │    └─ 某段资料全没取到 → 该段标 skipped（写明原因），不写
  ├─ 后台逐段跑（切走页面不打断）：每段一个全新 AI 会话，只看自己那段资料包
  │    ├─ 格式校验不过 → 追加一句重试一次；再不过报 bad_output_format
  │    ├─ 汇总段：解析末尾 json 代码块 → 明日验证建议（校验读数清单/方向/去重/最多 4 条）
  │    └─ 每段写完就地核对（见 1.3.4）
  └─ 跑完存台账 shortline_review：一段都没写成或中途停止 → 不存；否则每次一版，不覆盖旧版
```

#### 1.3.3 资料包（Dossier）机制

- 每条证据一行：`代码 字段 = 值 单位 (日期) [ev-哈希] — 说明`，证据 id 是内容哈希。
- **上限 20000 字**，超长截断并写进缺口。
- **防前视**：复盘日之后的数据一律剔除（两融这类只给最近一段的按证据日期过滤），被剔除的条数写进缺口——"悄悄少一半证据，写出来照样像一篇完整的复盘"。
- **防爆量**：龙虎榜/题材/首板等大表按 cap 只放前 N 条（和后 M 条），其余条数写进缺口。
- **todayOnly 来源**：行业资金流这类只给当天的，复盘旧日子时不取、说明一句；东财行业资金流整片取不到时自动换新浪备源，并在缺口里写明"口径不同，不能比"。
- 证据值有特殊写法：封板时间 6 位 `133925` 转成 `13:39:25`（注释记录了实跑教训：不转的话模型写对的时刻全被记成"没有交代出处"，题材段一次 9 处）。

#### 1.3.4 数字核对（auditNumbers）——三档核对

写完的每段正文由程序逐个数字核对，结果分三档随正文一起存：

1. **对得上资料包**：数字能在证据里找到；
2. **写了算式且重算通过**：派生数字（差值/比例/合计）重算一致；
3. **没交代出处**：标红（`loose`）；算式重算不通过进 `bad_math`（保留原式、写的值、重算值）。

证据编号同样核对：正文里引到的 `ev-xxx` 在资料包里的给出原行（"查看依据"悬停可看），**编出来的编号单列**（`unknown_cites`，最多列 40 条）——"编出来的编号和编出来的数一样要让人看见"。

#### 1.3.5 写法规则（注入每段提示词的 RULES）

- 只用资料包里的数，写数字标证据编号；自己算的数写完整算式（`69-43=26`）；
- 日期写完整格式；小数比例写成百分数；
- 缺口只能写"没取到/没放进资料包"，**不能说成市场没有这个现象**；
- 分清样本和全市场（昨日涨停那批 ≠ 全市场）；
- **读法边界**（防 AI 过度解读）：成交额排名≠放量缩量；最高标看不出资金主体/换庄；涨停原因是源站编辑归因；龙虎榜单日榜与三日榜区间重叠不能跨记录求和；历史分位推不出均值回归。

#### 1.3.6 输出物格式与内容

存进台账 `shortline_review` 的 JSON 记录（每次一版，可多版并存）：

```jsonc
{
  "date": "2026-10-09", "settled": true,          // 复盘日；是否已收盘
  "ai": "Claude Code 订阅",                        // 用的哪家 AI
  "started_at": "...", "finished_at": "...",
  "sections": [                                    // 六段
    { "id": "sentiment", "label": "情绪", "status": "done|failed|skipped|cancelled",
      "text": "正文（带 [ev-xxx] 编号）", "error": "...", "evidence_count": 87,
      "audit": { "total": 42, "bound": 38, "derived": 2, "loose": 2, "bad_math": [...] },
      "cited": [ { "id": "ev-...", "line": "原始证据行" } ],   // 查看依据（≤80 条）
      "unknown_cites": ["ev-..."] },               // 编出来的编号
    ... 共 6 段
  ],
  "gaps": ["情绪四项:…", "题材事件树:共 52 条记录,资料包只放了前 10 条…"],  // 全局缺口
  "conditions": [ { "metric": "promotion_1to2", "direction": "up", "reason": "…" } ],  // 明日验证建议
  "conditions_note": "另有 2 条…没采用"
}
```

页面呈现：五段+汇总正文、每段核对结果（对得上/重算通过/没出处三色）、"查看依据"悬停原始证据行、建议的验证条件**一键加进明日验证**。

### 1.4 AI 周报

同一套"分段跑、程序核对、存台账"机制（`weekly_review.ts`，台账 `shortline_weekly_review`），三个分项段+汇总：

| 段 | 资料包 |
|---|---|
| 情绪走势 | 本周+上周每个交易日的 `cn_shortline_daily` 六项读数 |
| 题材轮动 | 本周每天 `cn_shortline_themes` 前 6 + 后 2 个题材（只留涨停数/集中度/状态/最高板/延续率）+ `cn_shortline_structure` 最高标 |
| 验证回看 | 本周每天的明日验证对账结果，由程序改写成带证据编号的证据行（判断方向/前一晚读数/当天读数/实际方向/对账结果五行一条） |
| 汇总 | 开头写明本周休市的工作日；"下周看什么" |

**隐私边界**：周报"本周我的交易"从交易日志在本机算，只在页面显示，**不进 AI 资料包**。日复盘和周报合计最多同时跑 2 份。

### 1.5 明日验证（复盘 → 次日对账的闭环）

复盘的落点是"写下明天要验证的条件"，下一场收盘自动对账（`verification.ts`）。

**可用的 8 项读数**（每项带"变了才算变"的 eps 阈值，防止"涨停 40→41 就算上升"的噪声）：

| 读数 | 阈值 | 语义提示 |
|---|---|---|
| 涨停家数 | 差 5 家 | 市场整体的赚钱意愿 |
| 最高连板高度 | 差 0.5 板 | 情绪天花板，压缩=周期见顶 |
| 1进2 晋级率 | 5 个百分点 | 最敏感一档，走低=接力收缩 |
| 赚钱效应中位数 | 0.5pp | 多数人的体感 |
| 炸板率 | 5 个百分点 | 资金分歧（升=转弱） |
| 跌超5%家数 | 差 5 家 | 大面的量级，判退潮先看它 |
| 头部题材集中度 | 5 个百分点 | 一枝独秀还是遍地开花（无历史序列，不给基准） |
| 全市场跌停家数 | 差 5 家 | 极端风险直接读数（同上） |

**基准发生率**：每个方向在近 60 个交易日逐日 d−1→d 的发生频率；可比日 <12 不给；≥0.7 提示"本来就常发生，判对信息量低"、≤0.3 提示"少见方向，判对含量高"。单条超额 = 命中(1/0) − 基准发生率。

**战绩纪律**（防自欺是这一模块的特色）：

- 下一场 **09:15（集合竞价）之后**写或改的条件标"事后"：照样对账，**不计入战绩**——"看过盘再写的判断不算数"；
- 下一场未收盘的对账标"暂定"，不计入；
- 读数没取到 = null（判不了），不算判错——"把没数据和判错了混为一谈会污染战绩"；
- 同一晚同一读数只能一条；删除条件在交易日历取不到时**不放行**（删掉的条件不留痕迹会直接从战绩消失）；
- 汇总分母只算判定得了的条目，超额只在有基准的那批上算。

### 1.6 涨停样本（打法的市场现象统计）

`cn_shortline_settled` 逐只明细 × 7 种打法过滤（`samples.ts`）：

- 打法：首板打板 / 首板·早封（≤10:00 最后封板）/ 首板·尾盘封（≥14:30）/ 首板·涨停数前二行业 / 连板接力（≥2 板）/ 高标接力（≥3 板）/ 全体涨停（基准线）；
- 封板时间 5 档（开盘秒板 ≤09:35 / 9:35-10:00 / 10:00-11:00 / 11:00-14:00 / 14:00 后）；
- **分环境用入场那天（前一交易日）的情绪**，不用当天——代码注释明确："决策发生在前一天收盘，那时看不到当天的情绪（VA v2 修过的前视偏差）"；情绪强中弱 = 涨停家数×(1+最高连板)×(1−炸板率) 在**你自己交易过的日子**里三等分；
- 统计口径：胜率（不算持平）、均值、中位、最好最差、再涨停率（判不了的踢出分母）；
- **口径警示原文**（SAMPLE_CAVEAT，界面和给 AI 的文字都必须带）："样本=前一天收盘还封在涨停板上的票（事后名单）。包含一字板等未必买得进的票，没排除排队买不到的情况；冲板没封住的不在样本里。收益按前一天收盘到当天收盘、等权计算，没有成交模拟。这是市场现象统计，不是策略回测。"
- 样本窗口 20/30/60/90 天可选，交易日 <5 天不出统计；入场日情绪样本 <6 天不分环境。

### 1.7 情绪历史（读数的分位语境）

`cn_shortline_daily` 六项读数（涨停家数、最高连板、炸板率、赚钱效应中位数、跌超5%家数、1进2 晋级率）在近 5/10/20/30/60 个交易日的：

- **分位**（≥0.85 标"偏热"、≤0.15 标"偏冷"，按 higher_is_hotter 翻方向；样本 <10 不给分位）；
- **跟前一天比**：只列超过噪声门槛 diff_eps 的变化（涨停家数 8 家、炸板率 8pp 等），按"变化÷门槛"从大到小排；
- 分位只跟之前比、不含当天自己；一项都不在两头时如实呈现"平淡的一天——这本身也是信息"。

### 1.8 结构变化（断点归因）

回答"图上这个断点，是市场变了、数据源变了，还是规则变了"（`structure.ts`）：

1. **数据源**：四张池子的上游字段清单（含 zttj 子键）逐日比对，列出新增/消失字段——"数据源改字段会造出假断点"；
2. **市场**：最近 10 个交易日 vs 之前 20 个交易日，涨停家数、20%/10%/北交所制度占比逐项比**中位数**（"一两天涨停潮就能把均值拉飞"）；计数类相对变化 ≥35% 或占比类绝对变化 ≥10pp 才算移位；任一窗口 <5 天不比；
3. **制度**：**只收人工登记**的 `regime_event`（可登记未来日期标"还没施行"）——"从数据反推『这天大概改了规则』是猜，猜错会把市场波动当成制度事件"。

### 1.9 每日复盘（第二个复盘页面）

打开即看市场状态（可让 Agent 按页面数据写复盘），四块：

- **市场状态八格**：涨跌家数、两市成交额与 20/60 日均值比、涨停/跌停/封板率、最高连板、昨日涨停今日平均涨跌、站上 20/60/250 日线的指数个数、两融余额 5 日变化、沪深300 PE 与股息率 vs 10 年国债收益率；
- **短线情绪**：涨跌分布 23 档、赚钱效应/亏钱效应、晋级、连板股明细；
- **中长线**：八个指数 5/20/60/250 日涨跌、均线位置、离一年高点距离；两市成交额 60 日柱图（盘中那根没收完，不和整天均值比）；两融走势；股债性价比；
- **资金去了哪**：行业资金净流入/流出居前（东财取不到换新浪并写明口径）、成交额前 20、龙虎榜净买/卖居前；
- **涨停股按行业分档**（与前两个交易日比）：连续集中（今天同行业 ≥3 只且前两天每天 ≥2 只）/ 今天集中 / 零散（2 只）/ 单只；每行业列涨停股、连板数、最高板（同高按首封最早）与梯队；前两天的涨停池没取到时写明"分不出是不是连续"。

### 1.10 交易日志与复盘的联动

交易只存本机、不发给 AI。每笔自动对上**入场那天**的情绪强中弱和板位（首板/连板/炸板/没碰涨停，带炸板次数和行业）；复查页的"看错了还是没做好"= 入场那天对照**前一晚写的明日验证条件**——复盘、验证、交易三者闭环。

### 1.11 一天的复盘数据时间线

| 时刻（北京时间） | 动作 |
|---|---|
| 09:05 | 盘前提醒（隔夜外围、连板股公告与停复牌、新股） |
| 09:25 / 09:35 / 10:00 / 11:30 / 14:00 / 15:00 | 盘中快照自动存（竞价强弱 + 情绪路径；**过了时点补不回来**） |
| 09:15 | 明日验证条件写入截止（之后写的标"事后"） |
| 15:35 | **短线收盘取数**：存每日读数/昨日涨停表现/涨停结构/事实表/连板天梯 5 个端点 |
| 15:40 | 收盘摘要推送 |
| 16:15 / 16:30 | 自选变化 / 判据到期提醒 |
| 盘后任意时刻 | 写 AI 复盘 → 生成明日验证建议 → 次日收盘自动对账 |

程序没开就不跑；过了时刻的任务当天再打开时补跑一次（盘中快照除外）。

## 二、数据源

### 2.1 数据架构总览

```
上游公开接口（东财/同花顺/问财/腾讯/新浪/深交所/通达信/…）
    ↓  取数层（Python 子进程，一次一用，确定性计算，原始响应落盘记哈希）
182 个端点（35 层），短线专用 14 个 cn_shortline_*
    ↓  快照缓存：已收盘的日子结果不变 → 长期缓存；没收盘 → 标 partial 不缓存（防盘中数字被冻住）
编排层（情绪复盘/验证/样本/结构）→ 本地浏览器 UI / AI 资料包 / MCP
```

数据层是**移植代码**（非依赖引用）自三个上游：a-stock-data v3.7.0+v3.10.1（A 股）、global-stock-data v2.0.3（港美股）、investment-news（资讯源清单），由 `datasources/UPSTREAM.md` 逐版本对账（"判据是这个修复在本产品的代码路径上会不会发生，不是版本号是否落后"）。

### 2.3 采集的注意事项与坑（源码注释中记录的实战教训）

这是本项目最有价值的部分——大量"坑"以 🔴 注释形式写在代码里，多数标注了实测日期：

#### A. 数据保留期与丢失风险

| 坑 | 处置 |
|---|---|
| **东财涨停/炸板/跌停/昨日涨停池只保留约 29 个自然日**（2026-10-10 实测，留一天余量），当天不取、过了保留期就**永久取不到** | 定时任务 15:35 每个交易日收盘后取 5 个端点存本机；历史靠快照越积越长 |
| 超过东财保留期的日子**只读缓存、不发请求**——每次打开都白问一遍会让复盘多等 82 秒（VA 实测） | `SOURCE_RETENTION_DAYS = 28`，超过直接走缓存，没缓存过就如实说取不到 |
| 东财机构调研明细只留近一年；列表接口 2026-09 起时常**整片取不到** | 资金流换新浪备源、大票池换新浪，缺口写明口径差异 |

#### B. "业务失败伪装成空数据"（最容易造假数据的一类）

| 坑 | 处置 |
|---|---|
| 东财业务失败是 **HTTP 200 + rc≠0 + data null**（实测 rc=102/205），直接读会当成空池 → **炸板、跌停被写成 0 家** | `rc != 0` 显式抛错；涨停池为空也不当"0 家"（可能只是没收盘） |
| 未来日期/非交易日上游返回**空池**，下游会算出"涨停 0 家"像真实行情 | `review_day()` 直接拒绝未来日期和非交易日 |
| 池子**必需列缺失**：缺 `zbc`（炸板次数）会被算成"一次没炸过"、缺 `lbc`（连板数）会被算成首板 | `_check_required`：必需列有缺就整池报错，"不按默认值补" |
| **炸板池取不到就整天不要**：原来失败按 0 家算，炸板率 0% 像情绪最好的一天 | `day_summary` 炸板池异常返回 None，整天读数不可用 |
| 问财翻页：**不能拿"不满 50 条"当最后一页**（上游不认 page 参数），否则只取到第一页 | 只认三种结束：空页、比第一页短、这页没给新票；翻满 10 页还没完就当失败，不交半份名单 |
| 问财返回的涨停原因**列名没带日期或日期不对**，确认不了是哪一场 | 显式核对 `[YYYYMMDD]`，不对就报错换同花顺 |
| 昨日涨停池**只含昨日收盘涨停的票**：不含昨日炸板股；冲板没封住的不在样本 | 涨停样本页固定口径警示；赚钱效应同理 |
| 缺当天涨跌幅的行原来被**悄悄丢掉却报覆盖率 100%**（partial=False 会进长期缓存） | `settled_cov` 把缺涨跌幅的行算进分母，缺了就标 partial |

#### C. 口径陷阱

| 坑 | 处置 |
|---|---|
| **涨跌幅制度随时间变**：主板 ST 2026-07-06 起 10%（此前 5%）；创业板 2020-08-24 起 20%（此前 10%）；北交所 30% | `limit_pct(code, name, day)` 按票、按日期判；注释："VA 原来一律 5%，新规施行后会把 ST 跌 6% 当成跌停"；"统一 ret≥9.8 会把 20cm 跌 12% 也算成跌停" |
| **涨停判定差一分钱也是没封住**：`abs(差) < 0.011` 会把 10.99 对 11.00 算成涨停 | 按**分**比：`round(close×100) == round(limit×100)`；缺价格才按制度+0.3pp 容差推定 |
| 东财"连板数"对**反包票只给 1**，单看会把"N天M板"的回流反包结构抹成"1板" | 优先用涨停统计 `zttj`（N天M板），板位标注"N天M板"、首板页单独计数 |
| **封板时间是"最后封板时间"不是首封**（2026-07-24 实测对照涨停池 116 只全部等于最后封板） | 涨停样本"早封/尾盘封"打法定义按最后封板；首板名单才用首封时间 |
| **两融 T 日数据 T+1 发布**，最新一条通常是前一交易日 | 资料包来源标题直接写"T 日数据 T+1 才发布"，提示词里提醒 AI"最新一条可能是前一交易日的" |
| **东财行业分类 ≠ 题材**："电网设备""元件"是行业，打板复盘说的题材是涨停原因串 | 题材树**绝不退回行业分类冒充题材**（取不到原因整棵树标不可用）；涨停数前二行业叫"涨停数前二行业"不叫"主线" |
| 涨停原因/题材标签是**同花顺编辑的归因，不是公司确认**；只有当天的标签，不能说"新发酵/延续" | 写进 AI 读法边界 |
| 新浪板块资金流口径是"流入−流出"、行业分类约 48 个，**与东财主力净额不能比、不能接起来画趋势** | 备源启用时在缺口里写明，证据标题标注"和东财不能比" |
| **龙虎榜单日榜和三日榜区间可能重叠**，不能跨记录求和；上榜净买额不能证明承接/派发/主力意图 | 写进 AI 读法边界 |
| 东财名称含**全角字符**（实测"张  裕Ａ"），ST 判断会漏掉全角 ＳＴ | 先 NFKC 归一化再判 ST |
| 腾讯行情是**快照不是逐笔**；停牌股/节假日行情停在旧日期 | 每条行情核对 `quote_time` 属于目标日，不符直接丢；README 写明"两次快照之间的变化看不到" |
| 涨跌幅**保留原始精度**，先四舍五入再平均会和逐只平均对不上 | 取数层不截断，均值由全精度算出 |
| 问财每页实际给几条没核实过（要密钥） | 不拿"不满 50 条"当结束信号（见 B） |
| **09:25 前当天池子必然为空**，但上游何时把 qdate 切到今天没实测过——先切日期、池子还没清时日期核对拦不住昨天的池子 | 09:25 之前直接报"还没开盘"，请求也不发 |
| 批量行情半死不活时只回来几只票照样出结论 = **拿 3 只票的表现冒充全体赚钱效应**（"数字看着完全正常，是最难发现的一类错"） | 覆盖率闸门：<50% 判不可用、<90% 标 partial 并在给 AI 的文字里带警示后缀 |

#### D. 工程防护机制

| 机制 | 实现 |
|---|---|
| **东财统一入口** | `_http.em`：跨进程串行锁 + 代理回退 + 原始响应落盘；全局限速约 **1.3 秒/次**；403 不重试；并发只会更慢更易超时（收盘取数宁可串行） |
| **缓存一致性** | 已收盘长期缓存（结果不变）；未收盘一律 partial 且**不缓存**（防盘中数字被冻住）；盘中 live 端点缓存最多 15 秒（页面轮询不叠加） |
| **页面拆查询** | 冷启动五个短线端点约 45 次东财请求，放一个查询要一分钟才出第一屏 → 拆成多个查询，先出当天四项再并发其余 |
| **字段清单指纹** | 每次取池记录上游原始行键清单（含 zttj 子键），"结构变化"页比对漂移——数据源改字段会造出假断点，先于市场判断排除 |
| **移植对账** | UPSTREAM.md 逐上游版本对账："一个上游 bug 修复，可能因为移植时结构不同而根本不存在；也可能一个看似无关的小版本恰好改了本产品直接照抄的那段。必须读 release notes 逐条对，不能只比版本号" |
| **原始响应落盘** | 每次请求原文落盘并记哈希，证据能回查到传输层原文 |

### 2.4 数据流闭环（以"昨日涨停股今天赚不赚钱"为例）

```
T-1 日 15:35  收盘取数：涨停池(T-1) 存本机
T 日 15:35    收盘取数：昨日涨停池(T)、涨停池(T)、炸板池(T)、跌停池(T) 存本机
              → 逐只算 ret（涨跌幅）、prev_boards、limit_up（按各自制度判）
              → 赚钱效应中位数/均值/翻红率/再涨停率；缺涨跌幅的行进覆盖率分母
T 日盘后      AI 复盘·情绪段读资料包 → 写"昨日涨停股今天的表现"（标证据编号）
              → 程序核对每个数字
T 日盘后      汇总段建议「1进2 晋级率明天上升」→ 一键进明日验证
T+1 日 15:35  收盘后自动对账：与基准发生率（近 60 日逐日变化频率）比，算 edge
```

## 三、可借鉴的设计要点

1. **"程序算数、AI 解读、程序核对"三明治**：AI 的每个数字有三档核对（对得上/算式重算通过/没出处标红），编造的证据编号也会被单独列出来示众——这是对"LLM 幻觉"最工程化的解法之一。
2. **缺口一等公民**：每条数据有 partial/missing 状态和原因文字；样本覆盖率进证据；"没取到"永远不等于 0。
3. **反自欺设计**：明日验证的"事后条件不计战绩""暂定不计入""没数据不算判错"，涨停样本的"事后名单≠可成交"警示——统计口径的诚实度是核心竞争力。
4. **对抗上游易变**：必需字段缺失整池报错（宁可不可用不要错数据）、字段清单指纹、上游版本对账表、HTTP 200 + rc≠0 的业务失败识别——都是国内公开数据源实战的结晶。
5. **快照优先于实时**：复盘类指标一律走"昨日涨停池"定稿记录（任意历史日可算），实时行情只做兜底且有覆盖率闸门和"实时行情不能冒充历史收盘"的校验。
