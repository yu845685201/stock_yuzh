## 0 定位与使用形态

KHunter 自称「开箱即用的 A 股量化交易系统」，集**数据管理 + 策略选股 + 择时交易 + 风险控制 + 回测验证**全流程于一体。它是 Dzy-HW-XD/a-share-quant-selector 的深度扩展版（README 致谢原项目）。v1.7.1 已相当成熟：策略清单、评分体系、回测离线化、大盘 ADX 仓位闸门、飞书日报等一应俱全。

- 形态：Flask Web（`localhost:5001`）+ 命令行（`python main.py web` 等）+ 飞书推送（scheduler）+ 可选 ptrade 实盘。
- 技术栈：Python 3.10+（实测 3.12）；`akshare`（行情）、`tushare`（需 token/积分）、`flask` + `flask-socketio`、`SQLite`、`matplotlib`、`schedule`、`scipy`、`fastdtw`。
- 两条核心输出链路：**选股（12 策略）→ 五维评分 → 狩猎场（支撑位/买点）**；**择时（8 策略）→ 回测 → 实盘/飞书日报**。
- 数据源：`config/data_sources.json` 声明**优先级降级** `tushare_pro(1) > tencent(2) > eastmoney(3)`，超时 30s、重试 3 次。

## 3 分析逻辑

### 3.1 选股策略框架（`strategy/`）

`BaseStrategy` 规定统一执行管线（`execute_selection`）：数据验证（长度≥20、必要字段）→ 当日 K 线检查（`_is_suspended` 判停牌/退市，不比逐只调 tushare）→ 快速过滤（`quick_filter`/`_quick_filter_with_lookback`）→ `calculate_indicators` → `select_stocks`。关键细节：

- **排 ST/退市**：`_validate_stock_name` 过滤「退/退市/已退」关键词与 `ST/*ST` 前缀；`_is_suspended` 用「最新数据日期 < 选股日期」判停牌。
- **数据方向规范化**：`execute_selection` 开头把升序数据 `iloc[::-1]` 反转成「倒序、最新在前」（注释明确指出：Web 路径传升序、CLI 传降序，不反转会导致 `_is_suspended` 误杀全部股票、0 命中）。
- **`selection_date` 透传**：用 `inspect.signature` 判断子类 `select_stocks` 是否声明 `selection_date`/`stock_code`，声明了才传入——龙头策略据此按日期查涨停池，避免「DataFrame 降序首行即选股日」的隐式假设。

**12 个已注册策略**（`strategy_registry.py` 启动真实注册；`strategy_order.yaml` 中的 `MTopStrategy`/`MultiDeathCrossStrategy` 已不存在，属历史遗留）：金三角、涨停回马枪、启明星、多金叉共振、多方炮、阻力位突破、仙人指路、龙头、主升低吸、次新腰斩、超跌反弹、2560 战法。**9 个已归档**至 `strategy/disabled/`（底部趋势拐点/趋势加速拐点/涨停横盘/强势洗盘弱转强/趋势起点/W底/金叉未绿/低位TD9/碗口反弹），不参与选股。

**代表策略参数**（`config/strategy_params.yaml`，量级准确的阈值）：

| 策略 | 关键阈值 |
|---|---|
| 金三角 `GoldenTriangleStrategy` | MA5/10/20 金三角（`ac_interval=6` 天间隔内），C 点涨幅≥1% 且量比≥1.1，要求 MA60 向上 |
| 涨停回马枪 `LimitUpPullbackStrategy` | 涨停阈值 `0.095`（±9.5%，不区分板块），回调 1~9 天、回调幅度 0~15%、不破涨停收盘 `support_ratio=0.95`，KDJ 金叉（K<20）、MACD 金叉 3 天内，选股日涨≥2% 且量比≥1.5 |
| 龙头 `LeaderStrategy` | 严格第 2 板（`min/max_limit_times=2`）、早封板（`seal_time_limit=110000` 即 <11:00，字段 `last_time`）、换手 5%~25%、流通市值 <300 亿、量能 ≤昨日 2 倍、去除开盘即涨停（一字/T 字）、近 10 日内除昨日无其他涨停 |
| 主升低吸 `MainUptrendDipBuyStrategy` | 一拉涨幅 30%~100%（近 60 日），二调回撤 18%~(一拉-8%)，突破 R 幅度 ≤2%、阳线实体 ≥5%、量比 ≥1.8 |
| 超跌反弹 `OversoldReboundStrategy` | 收盘 < 近 120 日最高价 50%（腰斩），MACD 底背离（必）+ 底分型/低位9转/启明星任一，选股日阳线涨≥1%、量比≥1.3 |
| 次新腰斩 `NewStockDrawdownStrategy` | 上市 K 线 ≤120 根（≈半年）且较上市最高价跌 ≥50% |

### 3.2 五维评分（`trading/stock_score_*`）

`StockScoreCalculator.calculate_score`：五维分别算分 → 检查一票否决 → 加权综合。

- 权重 `SCORE_WEIGHTS`：技术 35%、资金 35%、基本面 10%、板块 10%、事件 10%（README 与代码一致）。⚠️ `calculate_total_score` 的 docstring 还写着「technical×0.25 + moneyflow×0.30 + …×0.15」——**注释过时，实际以 `SCORE_WEIGHTS` 为准**（代码里用的正是 0.35/0.35/0.10/0.10/0.10）。
- **一票否决 → 总分 = -100（`VETO_SCORE`）**，等级「淘汰」。否决来源：技术面（**M 头 + 多死叉共振同时命中**）、事件面（ST/*ST、业绩暴雷、大股东减持）、资金面/基本面/板块各自的 veto 标记。
- 技术面得分 = Σ(命中策略权重)，资金面 -100~100（主力净流入/大单占比/北向/主力散户方向）、基本面 -60~60（净利增速/ROE/经营现金流/市值）、板块 -100~200（近 5 日涨幅排名 + 资金流）、事件 -100~100（正/负事件加减）。
- 评分等级：≥80 强烈推荐、60~79 推荐、40~59 中性、20~39 谨慎、<20 回避、-100 淘汰。
- 批量 `ThreadPoolExecutor(max_workers=5)`，单只失败不影响其他（失败置 0 分/「回避」）。

### 3.3 狩猎场（`trading/khunter_*`）

选股结果 → 五维评分排名 → 按「评分阈值 + 跟踪天数 + 当前价 vs 支撑位」过滤 → 入狩猎场。支撑位 `khunter_support_calculator.py`（各策略有 `support_method`：`ma20`/`key_open`/`key_close`/`key_close_5`/`low`），买点 `khunter_buy_point_judge.py`。

### 3.4 择时策略（8 种，`trading/timing_strategies.py`）

布林带、RSI、支撑位、海龟、低位海龟（`low_turtle`，去 MA20 过滤）、海龟 plus（只做第二买点：前 5 日内出现过第一买点、较第一买点盈 `add_profit_min=2%`、加仓次数≤4）、趋势回调缩量（`uptrend_pullback`）、顺势宝（`macd_bollinger`，简化后：买 2 种「稳健启动/强势突破」+ 加仓 1 种 = 买②口径数量按海龟递减 `1/(已加仓+2)` + 卖出 1 种「最低价 < 中轨且 MACD 转绿 ⇒ 全清」）。

**海龟参数统一 `10/5/10`**（注释大篇幅强调「三层同步改」）：`n_entry=10`、`n_exit=5`、`atr_period=10`；其余代码默认 `entry_atr=0.02`、`add_atr=0.5`、`exit_atr=2.0`、`base_position_amount=20000`。

### 3.5 风险控制

- **大盘 ADX 仓位上限（1.7.0）**：`ADX>25 且上升 ⇒ 100%`；`ADX<18 且上升且收盘>MA20 ⇒ 50%`；**其他 ⇒ 0%（不开新仓，加仓不受限）**；含板块回退与「双创同时放行 ⇒ 整体不放行」细则。
- **风险过滤**：自动剔除 ST/退市/市值过低/近期涨幅过高；`var_calculator.py`（VaR）+ `risk_config.yaml` 仓位管理；`continuous_temp_risk.yaml`（连续临时风险）。
- **策略运行器**（`strategy_runner` 配置）：`max_position_size=0.1`、`max_positions=10`、`min_score=70`、`stop_loss=-5%`、`take_profit=21%`、手续费 `commission_rate=0.00015`（万 1.5，`min_commission=5` 元）、滑点买 0.01/卖 0.005、印花税 0.001、过户费 1e-5。

### 3.6 回测机制（`trading/backtest_engine.py` + `vectorbt_*`）

- **时点口径统一（1.7.0）**：实盘与回测都用「信号日当天收盘」；实盘 T 日信号 → T+1 成交，回测「信号日 = 执行日前一根」，且**回测硬钉前一根**（防前视）。
- **回测本地化 + 离线闸门**：四类本地数据 + ADX，回测完全离线可复现；数据源无权限自动跳过、逐维度留痕。
- 三套回测：事件驱动 `backtest_engine.py`、向量化 `vectorbt_*`（vectorbt_data_loader/strategies/executor）、制度路由 `regime_backtest*.py`（`regime_router.yaml`）。

### 3.7 交易与报表

- 实盘：`trading/ptrade/khunter_auto_trade.py`（ptrade 恒生/量化交易终端），`ptrade_feedback.py` 回写成交反馈。
- 报表：`scheduler/pipeline_orchestrator.py` + `feishu_commander.py` + `notifier.py`（飞书日报，含「大盘 ADX + 当日仓位上限判定」一节，缺数据如实标注）；`trading_calendar.py` 交易日历。

## 5 坑与注意事项（来自注释/README/RELEASE_NOTES）

1. **Python 版本坑**：原 README 写「3.8+」，实测 `web_server.py` 用了 `StrategyRunner | None` 联合类型注解且无 `from __future__ import annotations`，3.8/3.9 会直接报错起不来；实际开发/生产是 **3.12**。
2. **升级后必做「ADX 两类回填」**：README 加粗警告——不跑 `stock_adx.backfill_all` 与 `backfill_index_adx.py`，个股闸门会**静默不放行 ⇒ 完全不买入**；顺序是「重启自动建表 → 初始化页勾 7 项 → 两回填 → `manual_check_adx.py` 自检」。
3. **策略清单以「启动注册表」为准 ≠ 配置文件**：`strategy_order.yaml` 里 `MTopStrategy`/`MultiDeathCrossStrategy` 等已不存在的策略是历史遗留；README 明确「实际执行以 `StrategyRegistry` 为准」；`config.yaml`（含本地凭据）与 `test_*.py` 不入库。
4. **评分权重注释过时**：`calculate_total_score` docstring 写 0.25/0.30/0.15 权重，但代码用 `SCORE_WEIGHTS`（0.35/0.35/0.10/0.10/0.10）——按注释理解会搞错权重。
5. **数据源依赖 tushare 积分**：README 明说「策略选股稳定，但选股排名/狩猎场依赖资金面/基本面/板块/事件数据，可能无法稳定获取；注册 tushare 6000 积分才能完整使用」。
6. **海龟参数「三层同步」**：`strategy_params.yaml` + `TURTLE_DEFAULT_PARAMS` + `SHORT_TURTLE_PRESET` 三处必须一起改，否则「批量回测与单次回测口径不同」（注释反复强调）。
7. **前沿技术债**：`web_server.py` 单体近 20 万字节（196KB），是典型的「单文件 Web Server 膨胀」，维护和检索成本高。
8. **涨停阈值统一 9.5%**：`limit_up_threshold=0.095` 不区分创业板 20%/北交所 30%/ST 5%，与同类项目同样的问题（策略注释未标注此边界）。
9. **免费数据源不稳定**：README 原话「由于免费数据源的稳定性问题……选股排名和狩猎场等功能对资金面/基本面/板块/事件数据存在无法稳定获取的情况」。
10. **`data_sources.json` 是降级顺序而非全局库**：`enabled` 只有 tushare/tencent/eastmoney，akshare 等走各自 fetcher，真正的降级逻辑散落在 `utils/*_fetcher.py` 与 `source_gaps.py`。

## 6 可借鉴的设计要点

1. **「选股 → 五维评分 → 狩猎场」三级漏斗**：策略只管「命中」（输出信号+权重），评分层统一「分值+等级+一票否决」，狩猎场再叠加「支撑位/买点/追踪」——各层职责清晰、可独立替换。
2. **一票否决独立于加权**：`VETO_SCORE=-100` + 每维度带 `veto`/`veto_reason`，把「硬性排除」（ST/爆雷/减持/M 头+多死叉共振）与「软性加分」彻底分离，是排雷优先的工程化表达。
3. **数据源优先级降级 + 离线闸门**：`data_sources.json` 声明顺序 + 无权限自动跳过、逐维度留痕，「数据拿不到不硬算、不冒充有数」，与回测可复现性绑定。
4. **实盘/回测时点口径统一**：README 用一节专门声明「两边都是信号日当天收盘、回测硬钉前一根」，是防前视偏差的制度化表达。
5. **大盘 ADX 仓位闸门**：拿「大盘 ADX 挡位 + 双创放行规则」控制当日总仓位（0/50/100%），把择时由「个股级」提升到「组合级」，是较成熟的风险框架。
6. **策略参数全外置 yaml + 前端可调**：每个策略有 `param_details`（含 min/max/default/display_name）供前端渲染滑块，参数改动无需改代码；归档策略移 `disabled/` 保留留档。
7. **策略注册表 + `inspect.signature` 透传**：既保持基类接口稳定，又允许子类按需扩展 `selection_date/stock_code` 参数，兼顾统一性与灵活性。
