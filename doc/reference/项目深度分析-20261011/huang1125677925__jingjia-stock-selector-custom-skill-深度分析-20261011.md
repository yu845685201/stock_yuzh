## 0 定位与使用形态

这是一个 **OpenClaw「自定义竞价选股」Skill**（个人定制版 v5-Top3），针对 A 股 **9:25 集合竞价**做超短线筛选，用 Tushare `stk_auction` 统一实时与回测数据源，五因子打分后输出 TOP3 首选买入池。定位是「用户专属可调参策略」，与通用版 `jingjia-stock-picking` 区分（通用请求路由到通用版，本 skill 只响应「跑我的策略 / custom / 个人版」）。

- 形态：SKILL.md（frontmatter 元数据 + 触发词 + 评分规则）+ 两个脚本（`run_daily.py`、`run_backtest.py`）。
- 技术栈：Python 3.7+；`tushare`、`pandas`；`TUSHARE_TOKEN` 环境变量（也兼容 `~/.openclaw/openclaw.json`）。
- 声明：仅供个人研究，不构成投资建议（SKILL.md 有大段免责）。

## 2 数据源来源与采集机制

| 源 | 接口 | 内容 | 用途 |
|---|---|---|---|
| Tushare | `pro.stk_auction(trade_date)` | **竞价数据**（price/vol/amount/pre_close），支持历史回查 | 主接口（实时=回测同一源） |
| Tushare | `pro.limit_list_d(trade_date, limit_type="U")` | 昨日涨停股（含连板/炸板/封板时间/封单） | 候选池 + 连板/封板质量 |
| Tushare | `pro.trade_cal` | 交易日历 | 最近/历史交易日 |
| Tushare | `limit_cpt_list` / `daily_basic` / `moneyflow` / `daily` / `stock_basic` | 概念榜/流通市值/资金流/近20日行情/名称 | 评分辅助（见 SKILL.md 接口表） |

**关键设计**（SKILL「v5 统一数据架构」）：实时与回测**统一用 `stk_auction`**——`price`（成交均价）即 9:25 竞价实际执行价，`pre_close` 自带无需 join，`trade_date` 传当天/历史均可用，故回测与实盘口径完全可比。

**重试**（`fetch_with_retry`）：竞价数据 9:25 后可能延迟，最多重试 12 次、`base_wait=5s` 按 `1.5^n` 指数退避；涨停数据 3 次、3s。

## 3 分析逻辑（v5-Top3 五因子评分）

### 3.1 硬过滤（`run_daily.py`）

ST/北交所（`.BJ`）、流通市值 `<20 亿`、竞价低开 `gap < -3%`、竞价无量 `vr < 0.05%`、封单质量 `lr(封单/成交) < 5%` 剔除。

### 3.2 五因子（总分换算见 §3.3）

| 因子 | 权重 | 判定 |
|---|---|---|
| A 竞价量能 | 25% | `vr = 竞价额/流通市值`，按市值分档（≤200亿 5/4/3/2/1，>200亿 5/4/4/3/2；`vr>1%` 扣 0.5） |
| B 开盘位置 | 20% | 竞开涨幅 gap：8~10%→5、≥10%(一字)→4.5、3~8%→4、≥1%→3、-0.5~1%→3、其余→2 |
| C 连板位置 | 15% | 3板→4.5、2板→4、首板→2.5、4板+→2 |
| D 板块热度 | 20% | 代码里固定 `d_s=4`（板块热度未动态算，是简化占位） |
| E 竞价形态 | 20% | 昨日板质量 × 今开：烂板判定 `is_lb = 炸板≥2 或 末封板时间>14:30`；`lt≥2 且 gap≥6% 且 vr>0.3` → 5（烂板降3分档）…… |

### 3.3 得分与风控扣分

```python
raw = A*0.25 + B*0.20 + C*0.15 + D*0.20 + E*0.20   # 0~5 加权
score = raw * 4 - risk                              # ×4 拉伸到 0~20 再减风控
```
风控 `risk` 扣分项：`lr<10% +2 / <30% +1.5 / <50% +0.5`；连板≥4 +2；3板且 gap<2% +1；市值≥500亿 -1、≥200亿 -0.5；烂板 +0.5。

分级：`score ≥ 16` 进首选池；`12~15` 观察池（SKILL.md 表，代码里只输出 `score≥16` 的 cand，未单独实现观察池分级输出）。

### 3.4 市场情绪判断（`run_daily`）

- `r34 = 3板股数 4进 / 3板股数`（3进4晋级率，文档称近半年基准 49%）；`max_lt = 昨日最高板`。
- `is_defense = r34 < 20 或 max_lt < 3` → **退潮防守期**：输出观察池而非买入池。
- SKILL.md 完整三档：友好（晋级率≥35%、最高板≥4）、分歧（20~35%）、退潮（<20% 或炸板率>45%）。

## 5 坑与注意事项

1. **SKILL.md 评分表与代码实现有出入**：文档称 D（板块热度）「TOP5 且涨停>20 给 5 分 / 不在 TOP10 排除」，但 `run_daily.py` 里 `d_s = 4` **写死**，未读取 `limit_cpt_list`；E（竞价形态）文档有 8 档、代码是 `if/elif` 精简版；「观察池（12~15 分）」在代码里未单独实现。以脚本为准。
2. **「量比惩罚」单位表述混乱**：文档写「量比 >1.0% 扣 0.5」，代码 `if vr > 1.0: a -= 0.5`——`vr` 本身是「竞价额占流通市值比 %」，与「量比」是两码事，名称错位。
3. **情绪判断依赖单日晋级率，噪声大**：`r34 = n4/n3` 当 `n3=0` 时除零返回 0；仅用昨日一天数据判定「退潮/友好」，样本极小（文档自己也说核心指标是「3进4 晋级率近半年基准 49%」，但代码只算单日）。
4. **回测战绩来自作者自述**：「80.6% 胜率、累计 141%」是 SKILL.md 里的表格，18 天 31 笔样本量很小，且「卖出=次日竞价开盘与收盘择高」的规则含未来择价成分，实盘未必可复制（README 免责也承认）。
5. **Token 读取链脆弱**：先 `os.environ`，再 `~/.openclaw/openclaw.json` 里固定路径 `skills.entries.tushare-data.env`；非 OpenClaw 环境需自己设环境变量才能跑。
6. **招投标日期写死 2026**：`get_recent_days` 里 `trade_cal(start_date="20260101", ...)` 硬编码年度，跨年需改。

## 6 可借鉴的设计要点

1. **实时/回测统一数据源（`stk_auction`）**：用同一接口+同一字段（`price` 作竞价开盘价、自带 `pre_close`）让「回测绩效」与「实盘信号」口径直接可比，是从根上消除「回测好看实盘拉胯」的做法。
2. **竞价额占流通市值比（vr）作为首因子**：把「9:25 竞价承接力度」量化成「竞价成交额 ÷ 流通市值」并与市值分档打分，是竞价打板资金强度的核心刻画。
3. **烂板识别规则**（`炸板≥2 或 末封板时间 >14:30`）：用结构化字段（`open_times`/`last_time`）定义「烂板」并贯穿扣分与形态分，可复用。
4. **封单/成交比（lr）风控**：`lr=封单金额/成交额`，<5% 直接排除、<50% 分级扣分，把「封板意愿」纳入风控。
5. **Skill frontmatter 触发词分流**：description 明确「通用竞价请求由 jingjia-stock-picking 处理，本不响应」，避免两个同类 skill 抢路由，是 AI 工具注册的分流范式。
6. **五因子 → 单一分值 → TOP3 宁缺毋滥**：每天最多 3 只，配合「退潮防空仓」，风控纪律清晰。
