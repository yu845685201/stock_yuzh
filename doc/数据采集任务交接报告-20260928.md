## 四、未完成部分如何继续采集（操作手册）

### 4.1 财报 PDF 续跑（优先做，长任务）

```bash
cd stock_yuzh
nohup env NO_PROXY="127.0.0.1,localhost" .venv/bin/python backend/run_cli.py sync-financial-pdf --init \
  > logs/review/financial_pdf_init_续.log 2>&1 &
```

- **断点机制**：`tmp/financial_pdf_manifest.json` 每完成一只原子保存，续跑自动跳过已完成股票；已下载文件有 %PDF 头校验，不重复下载。
- **预计耗时**：2-2.5 个通宵（可分晚跑，随时中断安全）。
- **风控处理**：巨潮 403/非 JSON 自动急停（CninfoBlockedError），冷却 10 分钟；进程退出后**直接重跑同一命令**即续，无需任何手工处理。
- **验收**：`data/reports/financial_pdf_sync_report_*.md`；manifest 中 failed 清单为 0；完成标志 = 5559 只全部处理且无 failed。
- 如只想补失败件：同一命令重跑即可（manifest 自动重试失败清单）。

### 4.2 每个交易日盘后的标准动作（日常增量，建议 18:00）

```bash
# 前置：当日全市场日K（编排器会校验，缺它则日K依赖源拒绝执行）
backend/run_cli.py sync-kline-day

# 一条命令跑全部增量（波次并行，单源失败不阻塞，缺数据自动标"待补"）
backend/run_cli.py sync-review-data
```

- 执行顺序自动处理：波次1 并行（指数K/复权因子增量/外围/指数估值/公告/披露/龙虎榜/两融/资金流）→ 波次2 THS 财报增量（依赖当日披露清单）→ 波次3 PE/PB 自算。
- 财报披露高峰期（4 月/8 月/10 月底）可 `sync-review-data --sources=...` 排除 ths_finance，单独后台补。
- 全部 upsert 幂等，**任意重跑安全**；晚间补跑子集如 `--sources=lhb,announcement` 完全安全。
- 周频任务（仅 concept/unlock，当前均待补）：`sync-review-data --sources=concept,unlock`，当前会直接输出"待补"报告。
