# 每日复盘 skill 与复盘链优化方案 V1.0（20261004）

## 1. 背景

每日复盘系统三层架构已建成并实测跑通（20260930 期为验收样本）：

| 层 | 组件 | 现状 |
|---|---|---|
| 采集层 | `sync-review-all` / `sync-review-data` 编排器 | 实测 ~11 分钟/日，单源失败不阻塞 |
| 分析层 | `daily_review` 链（8 个股截面模块）+ 报告层 `src/review/`（六维聚合） | 链 33 秒/5820 只；报告层独立重算，交叉校验通过 |
| 解读层 | `stock-analysis-chain` skill | 只覆盖"链执行 + CSV 解读"路径 |

本方案针对 2026-10-04 对 20260930 期报告与库内数据的核查结论，做收尾优化。
前置方案：《每日复盘系统方案-V1.0-20260927》《每日复盘补全实施方案-V1.0-20261002》
《每日复盘-延后项补齐方案-V1.0-20261004》（N1~N3 已当日完成）。

## 2. 优化原则（边界声明）

1. **分层不变**：所有量化计算留在项目 Python 模块（分析链模块 + 报告层聚合），
   skill 只做编排、执行与解读。skill 优化只增加"调用哪些命令、按什么纪律解读"，
   **不引入任何 agent 侧计算**。
2. **判定口径零改动**：链模块、报告层聚合、情绪判据（已定稿）等分析逻辑不动；
   数据层修复只动采集源与回填，不动分析。
3. **数据层修复优先用已有机制**：各源已备回填命令（`--start-date/--end-date`
   断点续跑），不新增同步框架。

## 4. 优化项设计

### O1（P0）SKILL.md 增补「每日复盘完整流程」章节

**对应 P-1。改动文件**：`.workbuddy/skills/stock-analysis-chain/SKILL.md`（源件），
改后重拷至 `.zcode/skills/stock-analysis-chain/`（双注册坑见 §6.1）。

新增章节要点（实施时按此落稿）：

1. **双路径导航**（放在现"执行流程"之前）：
   - **完整复盘路径**（用户说"复盘今天/每日复盘"时走）：
     ```bash
     # ① 一键采集（日K增量 + 全部复盘源波次并发，~11-13 分钟）
     CLI sync-review-all                 # run_in_background 执行
     # ② 生成六维报告（秒级，只读，基于库内数据独立重算）
     CLI review generate [--as-of yyyyMMdd]
     # ③ 按 O2 清单解读 doc/reports/daily_review_<锚定日>.md
     ```
   - **链截面路径**（现状保留；用户要看涨停/异动个股明细、做交叉校验时走）：
     `CLI analyze run --chain daily_review` → CSV。
   - **关系说明**（防止误判链是报告前置）：报告层基于库内日 K 独立重算，
     不依赖当日链运行；链用于个股截面明细（Excel 可开）与交叉校验
     （报告 meta 的"重算涨停家数与链 CSV 一致"）。
2. **数据可用时点表**（复盘路径必附）：

   | 数据 | 可用时点 | 口径 |
   |---|---|---|
   | 日K/指数/行业/概念 | 盘后 ~15:30 | 当日 |
   | 龙虎榜 | 17:30 后发布 | 当日 |
   | 两融 | 次日盘前（T-1） | 沪深官网 |
   | 美股指数/汇率 | 北京时间盘后取到为昨夜收盘（T-1） | sina |
   | 公告/披露日历 | 持续更新 | 巨潮/交易所 |

3. **长任务纪律**：`sync-review-all` 必须 `run_in_background` + 每 30~60 秒
   进度汇报（同链执行纪律）；巨潮/同花顺/交易所风控急停时"重跑自动续"，
   不硬刚；编排器汇总报告路径 `data/reports/review_orchestrator_report_*.md`。
4. **失败处置**：`review generate` 退出码非 0 时读错误输出报告用户；
   单源失败不阻塞整体，解读时按编排器汇总点名当日失败源。
5. **前置检查复用**：现有 `check_data_freshness.py`（日K新鲜度）对两条路径
   都必做；复盘路径数据落后时直接建议 `sync-review-all`（内置日K同步），
   经用户确认后执行。

**验收**：新会话 agent 只凭 skill 完整走一遍复盘（采集→报告→解读），全程零
agent 侧计算；双路径选择正确（"复盘今天"走完整路径，"看涨停截面"走链路径）。

### O2（P0）解读纪律：数据质量缺口强制点名清单

**对应 P-2/P-6。改动文件**：同 O1（SKILL.md 新增小节"复盘报告解读必检清单"）。

清单内容（解读复盘报告时逐项过，命中必须在输出中点名）：

1. **美股三大指数**：close 连续 ≥3 个交易日完全相同 → 判冻结，点名
   "数值不可信"（O4 修复并回补后本条撤下）。
2. **两融**：融券余额仅深市有值（沪市官网无该列，不展示属口径而非缺数）；
   数据日期 T-1；趋势对比中单边缺日报告已标注。
3. **题材候选**：推断口径（概念映射 × 当日热度排序），非编辑部人工归因。
4. **大单净流入**：异动子集近似口径（涨停∪跌停∪|涨跌幅|≥7%∪成交额 Top50），
   非全市场。
5. **解禁日历**：公告制仅近端（一般提前 3-5 个交易日披露），非完整前瞻。
6. **行业榜与概念聚集**：两套分类体系（sw_2021/sina_hy vs sina_gn），交叉
   结果仅供观察。
7. **公告历史**：全市场自 20260928 起，更早仅定期报告类目。
8. 既有项保留：is_st 同步时点口径、北交所不复权、前复权断裂/停牌存疑规则。

**验收**：对 20260930 期报告按清单输出解读，命中项（1/2/3/4/5/6/7）全部点名。

## 6. 风险与注意事项

1. **skill 双注册坑**：源件在 `.workbuddy/skills/stock-analysis-chain/`，
   注册件在 `.zcode/skills/stock-analysis-chain/`；**改源件后必须重拷**，
   否则 agent 加载的是旧版。
2. **不做 git 操作**：所有改动留工作区，是否入库由用户决定。
3. **风控纪律**：巨潮/同花顺/交易所官网的回补类任务分晚执行、断点续跑；
   长回补用 `nohup + caffeinate`（后台任务随会话死亡的历史教训）。
4. **换源口径**：O4 新源需核对美股 T-1 收盘与北京时间取数时点，报告口径
   标注同步更新；对拍以官网收盘价为准。
5. **链与报告层不同步窗口**：链 CSV 锚定日与报告锚定日一致时才可交叉校验；
   解读时如两者数据日期不同须点名。
