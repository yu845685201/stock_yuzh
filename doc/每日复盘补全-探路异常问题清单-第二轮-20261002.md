## 二、新发现异常详述

### X-6 🔴 财报披露日覆盖率仅 1.3%——A 项 as-of 历史回填的最大阻塞

**现状（库内证据）**

```
base_financial_report: 总行 346,018，有 disclosure_date 仅 4,623（1.3%）
  按期次：20260630 → 2311/5404 有披露日；20260331 → 2312/5285；
          20251231 及更早全部期次 → 0
披露日两路来源（COALESCE 口径）现状：
  base_disclosure_calendar：仅 2026 年 6,961 行（沪 6952 / 深 9）
  announcement_daily：仅 20260928~0930 三天（4,715 行，窗口游标滚动采集的固有范围）
```

**为什么致命**：方案 4.1 的 as-of 取数过滤条件是 `disclosure_date IS NOT NULL AND disclosure_date <= as_of`。
以现状回填 2021~2025：绝大多数股票在任何历史日期都找不到"已披露"的财报 → PE(TTM)/PB 大面积无法计算，
"5 年 660 万行"的回填目标无法达成。**披露日数据不先补，开发项 A 的回填不应开跑。**

**财报数据本身没问题**：base_financial_report 期次深度 1988~2026 全历史（2021~2025 每年 2.1 万行），
缺的只是"披露日"这一列。

**解法探路结论（两路来源的可回补性实测）**

| 路径 | 覆盖 | 可回补性实测 | 结论 |
|---|---|---|---|
| ① 上交所预约披露（fetch_sse_plan，publishYear 参数） | 沪市 | **历史年份完全可达**：L011 年报 publishYear=2021 → 2064 行（2059 有实际披露日）、2023 → 2273、2025 → 2310；2026 年报返回 0 行属正常（未披露） | ✅ 沪市 2021~2025 官方披露日可补（4 类报告期 × 5 年 = 20 次请求，分钟级） |
| ② 深交所预约披露 | 深市 | 本轮再探：页面 `disclosure/listed/fixed/index.html` 数据动态加载、ShowReport 候选目录暴力试探（timing_schedule/dqbg/1713 等八种）全空、搜索引擎无公开目录；与项目 2026-09-27 既有探路记录一致 | ❌ 维持"待补" |
| ③ 巨潮公告历史回补（cninfo hisAnnouncement/query） | 沪深全覆盖 | 接口原生支持任意 `seDate=起~止` 窗口 + 定期报告四类 category（category_ndbg/bndbg/yjdbg/sjdbg_szsh）全市场检索；按披露季窗口切分回补 5 年约 **600 请求 ≈ 20~30 分钟**（1.5s 限速，风控走既有 blocked 冷却） | ✅ **深市唯一可行解**，且沪深一并覆盖（与现有 `backfill_financial_disclosure_dates` SQL 完全衔接） |
| THS 财报源自带披露日？ | — | ths_source.py 字段映射无披露日字段 | ❌ 无捷径 |

**建议方案（待用户确认）**：X-1（龙虎榜修复）之外，先做"披露日历史回补"小工具：
沪市走路径①（精确、零风控压力），深市（或干脆沪深统一）走路径③（巨潮披露季窗口检索），
随后执行现有 `backfill_financial_disclosure_dates` 完成 COALESCE 回填，再启动开发项 A。
工作量：路径① + 现成 SQL ≈ 0.5 人日；路径③ ≈ 1 人日（窗口切分 + 风控处理 + 幂等）。

### X-7 🟠 深市龙虎榜金额字段 100% 为空——D2 的排序前提缺口

**现状（库内证据）**

```
lhb_stock_daily：深 261 行，buy_amt/sell_amt/net_amt 全部 0 覆盖；沪 7 行有值（沪市由席位行聚合而来）
```

**根因**：深交所列表接口（CATALOGID=1842_xxpl_after）仅披露**成交金额（cjje，亿元）**，买卖分列在席位明细；
采集代码（lhb_manager.py:93-95）如实留空。沪市则由 queryTradeOpenInfo.do 的 B/S 行聚合出买卖额。

**影响**：方案 D2 设计"lhb_stock_daily 当日按 `net_amt` 降序 Top10"——深市股 net_amt 全空，
龙虎榜 Top10 将只剩沪市股（而深市上榜量占 95%+），子块基本失去意义。

**解法选项（待用户选择）**：

1. **席位明细聚合近似口径**（推荐）：深市已抓 `lhb_detail`（买1~卖5 全部席位），按 (trade_date, ts_code)
   聚合 buy/sell 合计回填 lhb_stock_daily；口径标注"前 5 买卖席位合计，非全额"；沪市换 X-1 修复后的
   汇总接口按 branchTxAmtB/S 聚合（准确口径）。零新增请求。
2. **改用成交金额（cjje）排序**：D2 的"Top10"改为按当日成交额排序，口径与龙虎榜"净买"语义不同，需在报告标注。
3. 两者并用：net_amt 可算则展示净额、否则展示成交额并标注。

### X-9 🔵 tdx 中间件上游连接偶发断开（~1 分钟自愈）

- 实测：探路中一次复现——tdx-api 全部接口（index/minute-trade-all）同时报
  `write tcp 172.18.0.2:xxxxx->121.36.225.169:7709: use of closed network connection`；
  等待约 60 秒后自动恢复（容器 tdx-stock-web 全程 healthy，为上游长连接空闲断开后的重连窗口）。
- **工程含义**：F 项分笔批量回补（每股每日期 1 请求 × 数十万次）必然会遇到；采集代码应把该错误
  识别为**暂时性错误**（等待 30~60s 重试 1~2 次），而不是计入失败清单。与第一轮 X-4（首次请求 >10s 预热）
  一并纳入 `_fetch_trades` 的重试策略。
