## 二、新发现详述

### X-15 🟠 code6_to_ts_code 沪市 ETF 错标 sz. 前缀（存量 2,135 行）

**根因**（review_common.py）：代码映射只覆盖 60/68→sh、0/3→sz、4/8/92→bj，**5 开头（沪市基金/ETF）落入兜底分支 `return f'sz.{c}'`**。

**铁证（margin_trade_daily 库内实测）**：

```
20260923: 总 4108 行 = sh 真实 1677 + sz 真实 2122 + 错标 sz.5x 309（510050/510100/510150…）
20260924 / 20260929: 同样 309 行/日错标
全表错标 2,135 行，跨 10 个交易日（两融采集启用以来的全部天数）
其他五表（lhb/lhb_detail/money_flow/announcement/unlock）扫描 0 错标
```

期间发现过程即证据链：0923 两融"深 2431 行"超过深市真实标的数（2122+309 错标），重采日志"沪 2002 行"与库内"sh 1677"的差值 325 行全部是 5 开头（其中 309 行 ETF + 16 行其他差异）。

**影响评估**：

- D1 两融总量 `SUM(rzye)`：**不受影响**（前缀错不影响求和）；按市场分组会错（当前设计不做分组）；
- 未来任何 join `base_stock_info`/`his_kline_day`（正确前缀）的场景会失配；
- C 项回补将把错标放大到 3 年（750 日 × ~300 行 = 22 万行污染）。

**修复方案（建议开发前先做，约 0.1 人日）**：

1. `code6_to_ts_code` 补 `5` 开头 → `sh.`（同时审查 11 开头沪转债等当前未覆盖码段）；
2. 存量清洗：`UPDATE margin_trade_daily SET ts_code = 'sh.' || substr(ts_code, 4) WHERE ts_code LIKE 'sz.5%'`（upsert 幂等，随后重跑当日可自愈对齐）。

### X-14 🟢 两融 0923 单边缺口（当日已修复）+ 回看机制的 stats 歧义

**现象与修复**：库内 0923 曾只有深市单边（D1 趋势出现"单日 +1.3 万亿"假跳变）；重采 `--trade-date 20260923` 后库内恢复与相邻日同构（sh 1677 / sz 2431）。根因是采集当晚官网沪市数据渐进就绪（深市先出），日常采集 T-1 语义此后不再回头。

**暴露的实施注意点（C 项）**：`margin_manager.execute` 内置"发布滞后逐日回看"（`for offset in range(lookback_days): ... break`）——

- 回补模式传 `--trade-date d` 时，若官网 d 尚未就绪，会**静默采到 d-1 的数据入库 d-1**，stats 行数却计入本次调用 → CLI 输出（只显示行数不显示实际日期）会误导"当日已成功"；
- 文档 C 项设计的断点续跑判定（查库"当日行数>0"）恰好规避误判，**实现时必须坚持查库判定、不得信任单次调用的 stats**；
- CLI 输出建议带上 `szse_date/sse_date` 实际数据日期（字段已存在，仅未打印）。
