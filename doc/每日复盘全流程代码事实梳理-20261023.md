## 〇、一句话总览

每日复盘 = **一条采集流水线 + 一条计算流水线 + 三层解读**，共 5 个阶段：

| 阶段 | 命令 | 耗时 | 产出 |
|---|---|---|---|
| A0 | `check_data_freshness.py` | <5s | 新鲜度读数（最新K线日 / 日历最近交易日 / 落后交易日数） |
| A1 | `sync-review-all` | 11~13 min | 16 个复盘数据源 + 全市场日K，落 40+ 张表 |
| A1.5 | `analyze run --chain daily_review / hk_stock_review / overseas_index_scan` | ~75s | 3 个 CSV（5820×24 / 33×8 / 6×5） |
| A2 | `review generate` | ~35s | 六维报告 MD + HTML + meta.json |
| A3 | agent 解读 → `review digest` | agent 耗时 | 自包含图文解读 HTML（**最终交付物**） |

关键架构事实（`SKILL.md:42-47`）：**报告层基于库内日K独立重算，不依赖链运行**。链提供个股截面明细与交叉校验，二者是"摘要 vs 底表"关系，不是"前置 vs 后置"。

## 三、A1.5 每日惯例三链

### 3.1 为什么必须三链都跑

`SKILL.md:89-119`。三链**必须在 `review generate` 之前**串行执行：报告交叉校验读 `daily_review_<锚定日>.csv`，链先落盘，报告才带"重算涨停家数与链 CSV 一致"校验行（`SKILL.md:97-98`）。

### 3.2 链引擎执行流程（`backend/src/analysis/chain_engine.py`）

```
ChainEngine.run(chain)                                                     :100
 ├─ domain = get_domain(chain.domain)                                      :106   (a_share/overseas_indices/overseas_stocks)
 ├─ DataReader(config_manager)                                             :108
 ├─ as_of = domain.resolve_as_of(reader, opts.as_of)                       :109
 ├─ universe = domain.load_universe(reader, cfg)                          :110   空则 ValueError(:112)
 ├─ modules = [build(spec.name_en, spec.params) for spec in chain.modules]  :114
 ├─ columns = domain.base_columns + 各模块 required_columns 并集            :118-120
 ├─ module_days = max([m.effective_lookback() for m in modules] or [0])     :123
 ├─ load = domain.load(reader, columns, as_of, chain, opts, module_days, universe)  :124
 ├─ pre = domain.precheck(...)                                             :127
 ├─ for env_name in chain.env_list(): load.env_extras.update(assemble_env(...))  :134-136
 └─ reader.close()                                                         :137
```

**逐股执行** `_run_modules`（`:257-281`）：
- `ctx = ChainContext(as_of, stock, suspect_reasons, upstream=dict(env_extras))`（`:268-269`）——env 预置进 `upstream`，逐股拷贝防泄漏
- 顺序执行 `mod.analyze(group, ctx)`（`:273`）
- 返回 None → `ModuleResult.insufficient("模块返回 None")`（`:274-275`）
- 异常兜底 `ModuleResult.insufficient(repr(exc))`（`:276-278`）——**单模块失败不中断整链**
- 结果回写 `ctx.upstream[mod.name] = result`（`:280`），**键是中文名**（如 `'连续涨停数'`、`'R1梯队接力'`）——这是 R 系列读前置模块的方式

- `是否存疑=是` 的行逐一点名原因（`前复权断裂` → 该行结论打折）
- **量能趋势列**：统计分布（连续放量/放量/温和/缩量家数），连续放量股按成交额排行点名；缩量股占比骤升提示情绪转弱
- **资金趋势列**：净流入理由串按金额排行 Top5 与连 n 天极值点名，与涨停/新高名单交叉（资金流入的涨停股=强证据）；口径提醒：`money_flow_daily` 为分笔分桶口径，20260917 之前历史行仅异动子集覆盖
- **R 列理由串格式**（P1-7）：R1 带分层前缀（高位板开板上限收紧为 1）；R2 带聚集家数（<2 不入选）；R3 反高开低走已过滤（属正常）
- 报告候选表新增「五维评分」列——**评分只排序不改池**

**hk_stock_review CSV**：60 日位置% 极值点名（≤5% 底部区 / ≥95% 顶部区）；AH 5日差与溢价 |差值| 前列点名；`未对齐`/`无A股映射`/`汇率待补`/`数据滞后` 行逐一点名且不得进入 AH 结论（`无A股映射` 是 18 只仅港股的结构性事实，非数据缺陷）。

**overseas_index_scan CSV**：与报告"外围指数"块互证（同表同口径应逐值一致，不一致点名并核对锚定日是否错位）。

**通则**：外围两链遵守「外围链解读规范」（口径三注/存疑词表/**严禁涨跌停语言**）；外围锚定日 ≠ A 股锚定日时说明（假期/时点差异属正常）；免责声明照常附。

### 6.3 第三层：图文并茂解读 HTML（最终交付物）

**综合研判整合层**（`SKILL.md:207-219`）——解读文本**第一节必须是「综合研判」**，三段结构：
1. **市场状态一句话定位**：情绪周期 × 量价四象限（双锚一致性/分歧）× 资金锚方向（北向活跃度/南向/ETF）× 梯队高度，四要素合成
2. **多维证据交叉表**：每行一个结构判断（如"高低切换进行中"），列 = 支持它的各维度证据（行业榜/大单板块净额/新高新低/资金趋势/外围 AH），**矛盾或缺失的证据必须点名**
3. **精选操作池（≤3 只）**：从候选池按**证据强度（五维计数降序）+ 证据链完整性**精选至多 3 只，每只一段证据链表述，并点名"被排除的强证据股"及原因；**证据 <2 维的不入选**；精选池是候选的子集不是新增

**表格优先原则**（`SKILL.md:220-225`）：可枚举对照内容**一律用 markdown 表格**，不用长列表；叙述性结论保持段落/列表；每表 ≤10 行为宜，超出取 Top N 并注明全量底表位置。

**防幻觉三件套（P0-3，2026-10-20）**（`SKILL.md:232-255`）——写解读文本前必读，digest 生成前必跑校验：

| 件 | 规则 |
|---|---|
| ① 数字接地 | 每个关键数字必须挂来源：`（CSV:量能趋势=连续放量）` 或 `（报告§四）`；推断产生的数字标 `（推断）` |
| ② 推断标注 | 推断句必须带 `【推断】` 前缀；无法验证的假设带 `【假设·待验证】`；事实段只放带来源数字 |
| ③ 编号可查 | 引用证据用 `ev-<锚定日>-<序号>`（序号 = CSV 行号或报告章节号）；引用不存在的编号 = 该段作废重写 |

**程序校验**（WARN 级）：
```bash
python3 scripts/check_digest_numbers.py \
  --note doc/reports/daily_review_<锚定日>_digest_note.md \
  --csv  data/analysis/daily_review_<锚定日>.csv \
  --meta doc/reports/daily_review_<锚定日>.meta.json
```
- 输出 WARN 清单 = 不在「CSV 列值 ∪ meta 已知值 ∪ 已标注（推断）」白名单的数字
- agent 必须**逐个人工过 WARN 清单并在最终输出点名**
- 已知边界（诚实声明）：白名单按方案设计为「CSV 列值集合」，汇总型数字（报告情绪章的点位/超额）会落入 WARN——这正是人工复核环节存在的理由；全自动 grounding 需结构化声明块，成本高，列为后续可选
- `--strict` 可供 CI 场景（WARN 退出码 1）；日常复盘用默认 WARN 级
