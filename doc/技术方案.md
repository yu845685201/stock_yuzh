# 技术方案

> A股盘后静态分析系统 —— 技术选型与架构记录

## 1. 项目概述

本项目是一个专注于A股市场的盘后静态数据分析系统，包含两大核心模块：**数据同步**（采集、落地）和**股票分析**。所有数据必须来自真实数据源，严禁模拟数据。

## 2. 整体架构

```
┌─────────────────────────────────────────────────────┐
│                   backend (Python)                   │
│   sync / analysis / kline_1min / services / cli      │
└──────────┬─────────────────────┬────────────────────┘
           │ SDK 直连             │ HTTP API
   ┌───────▼────────┐    ┌───────▼─────────────────┐
   │   baostock     │    │  TDX API 中间件 (Go)     │
   │  (官方数据服务) │    │  http://127.0.0.1:8080  │
   └────────────────┘    └─────────────────────────┘
           │                     │
   ┌───────▼─────────────────────▼────────────────────┐
   │        数据落地：PostgreSQL + CSV 文件             │
   │        （UAT / PROD 环境目录隔离）                  │
   └──────────────────────────────────────────────────┘
```

## 4. 数据源（核心中间件）

系统通过 `DataSourceBase` 统一接口抽象数据源，支持热插拔，当前接入两个：

### 4.1 baostock（主数据源）

- **接入方式**：Python SDK 直连，`baostock>=0.9.3`
- **版本要求**：必须 0.9.0+（服务端已迁移至 `public-api.baostock.com`；旧版 0.8.x 连接的 `www.baostock.com:10030` 端口已下线，login 会挂死）
- **提供数据**：股票列表、日 K 线、财务基本面数据、交易日历
- **代码位置**：`backend/src/data_sources/baostock_source.py`，线程安全封装见 `thread_safe_baostock.py`

### 4.2 TDX API 中间件（通达信行情服务）

- **GitHub 地址**：https://github.com/oficcejo/tdx-api
  （基于原作者 https://github.com/injoyai/tdx 的通达信协议库二次封装）
- **技术实现**：Go 1.22+ 编写，解析通达信协议，对外提供 RESTful API 与 Web 界面
- **部署方式**：Docker 容器（`tdx-stock-web`），监听 `http://127.0.0.1:8080`
- **提供数据**：K 线数据（主要是分钟级），核心接口：
  - `/api/kline-all` —— 全量 K 线
  - `/api/kline-history` —— 区间 K 线
  - 不提供股票列表与财务数据
- **代码位置**：`backend/src/data_sources/tdx_api_source.py`
- **中间件源码本机位置**：`~/develop/ai/claude/claude-code/workspace/test/tdx-api`

## 5. 关键设计

- **数据源抽象**：统一继承 `DataSourceBase` 基类，新增数据源只需实现接口并在配置中注册
- **限流保护**：`ApiRateLimiter` 对 API 调用做限流（每周期 50 次）+ 失败重试，baostock 与 TDX API 独立配置
- **1 分钟 K 线模块**：采用六边形（端口-适配器）架构，`domain` / `usecase` / `adapters` 分层，按天分区写入 PostgreSQL（`partition_writer`），索引精简
- **数据双落地**：同步结果同时写入 PostgreSQL 与 CSV 文件，按 UAT/PROD 目录隔离
- **环境隔离**：UAT（`uat/data`、`uat/vipdoc`）与 PROD（`prod/data`、`prod/vipdoc`）严格分离，配置驱动，禁止硬编码

## 6. 部署环境

| 环境 | 说明 |
|-----|------|
| 开发/UAT | 本机运行 Python 后端 + Docker 运行 TDX API 中间件，数据写入 `uat/` |
| PROD | 同结构，数据写入 `prod/`，数据库与目录资源独立 |
| 依赖服务 | PostgreSQL 12+、Docker（TDX API 中间件）、外网访问 baostock 服务端 |
