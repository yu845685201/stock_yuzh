# 每日复盘报告优化 V2.0 技术实现方案 V1.0（2026-10-24）

> 对应《每日复盘报告优化方案-V2.0-20261024.md》（P0~P4 五批、八步授权顺序）。本文给到函数级改动设计、测试用例、验收命令与回滚方式。所有"现状"均经代码核实（文件:行号为 2026-10-24 快照）。

## 〇、总体技术原则

1. **两入口同实现**：涨停/缠论等判定逻辑改共享层（`limit_up_rules` / `chan.scan`），链模块与报告层自动同步，禁止两侧各改一份。
2. **同数据同结果**：任何确定性查询必须可重放（ORDER BY 稳定排序、无 as_of 泄漏）；每步验收含"同 as_of 连跑两次 diff 为空"。
3. **不硬造**：门控/降级一律返回 `insufficient`/标记而非猜测值；报告层失败降级为 note 不炸链。
4. **每项三件套**：单测 + 10-23 重跑 A/B diff + 对拍（`_chan_parity`/指标对拍/涨停家数交叉校验机制沿用）。
5. **回补红线**：动历史数据的步骤（步骤 6）先备份表、出 diff 报告、经用户确认后执行。

## 二、步骤 1：四项小修（P0-3/P0-5/P0-4/P0-6）

### 2.1 P0-3 资金锚源编排（B7）

**现状**（已核实）：`review_sync_orchestrator.py:34-41` `DEFAULT_SOURCES` 16 项不含 `hkex_connect`/`etf_scale`；两源已在 `SOURCE_WAVES[0]`（54 行）与 `SOURCE_LABELS` 中——**仅 DEFAULT_SOURCES 漏配**。`_parse_sources`（332-336 行）对 `all` 返回 DEFAULT_SOURCES，显式指定时报"未知源名"。

**改动**：
```python
DEFAULT_SOURCES = [
    'index', 'factor', ..., 'news',
    'hkex_connect', 'etf_scale',   # B7：资金锚两源并入默认集（波次表已含）
]
```
`ALL_SOURCES = DEFAULT_SOURCES + WEEKLY_SOURCES` 自动生效，`_parse_sources` 无需改动。

**测试**（`test/test_review_sync_all.py` 增）：断言 `DEFAULT_SOURCES ⊇ {hkex_connect, etf_scale}`；`_parse_sources('hkex_connect')` 不抛错且返回单元素列表。

**验收**：`sync-review-all` 执行后查 `hkex_connect_daily`/`etf_scale` 快照表最新日期=当日；`--sources hkex_connect` 单源可跑。

### 2.2 P0-5 滚动战绩双计（C8）

**现状**（已核实）：`verifier.py:315-317` 查询 `WHERE trade_date <= %s ... LIMIT 30` 后 `payloads.insert(0, current)`——当日核验已入库时 current 被计入两次。

**改动**：`trade_date <= %s` → `trade_date < %s`（current 由 insert 单独补位，语义不变、计数正确）。

**测试**（`test/test_review_verifier.py` 增）：同 as_of 连续两次 `rolling_stats`，两次输出 dict 相等。

### 2.3 P0-4 VETO 前视偏差（C3）

**现状**（已核实）：`aggregator.py:1970` `_candidate_veto_map` 业绩查询取 `base_financial_report` 最新 `stat_date` 行，**无披露时点约束**——用未来公告否决历史候选。

**改动**：查询加披露日约束与稳定排序：
```sql
SELECT DISTINCT ON (ts_code) ts_code, net_profit_yoy
FROM base_financial_report
WHERE net_profit_yoy IS NOT NULL
  AND COALESCE(pub_date, to_char(stat_date::int + 304, 'YYYYMMDD')) <= %s   -- 披露日以真实 pubDate 为准，缺失回退"报告期+304天"保守估计
ORDER BY ts_code, COALESCE(pub_date, ...) DESC
```
（列名实施时以 `doc/init.sql` 实际披露字段为准；回退规则写入函数 docstring。）

**测试**：构造公告日 > as_of 的净利暴雷行 → 不进 veto_map；同 as_of 两次重跑 veto 清单逐值一致。

**验收**：10-23 重跑，被否决候选清单与修复前 diff 逐项有解释（预期仅"当时尚未披露的公告"类差异）。

### 2.4 P0-6 行业归属不确定（C2）

**现状**（已核实）：`aggregator.py:361` `_sector_money` 行业映射查询（sector_concept_map × sector_concept，source IN ('sw_2021','sina_hy')）**无 ORDER BY**，下游 seen-取首行决定归属。

**改动**：查询加稳定排序并显式声明源优先级：
```sql
ORDER BY m.ts_code,
         CASE c.source WHEN 'sw_2021' THEN 0 ELSE 1 END,
         c.concept_code
```
配套：函数 docstring 写明"sw_2021 优先，sina_hy 兜底"；同优先级映射缓存复用（供 P1-8 缠论行业列调用同一归属结果）。

**测试**：同一 as_of 循环调用 5 次，行业净额 dict 逐值一致（同数据同结果）。

## 三、步骤 2：P0-7 缠论输入完整性（三件套）

### 3.1 引擎层缺日门控（`chan/scan.py`）

**现状**：`scan_stock_anchor`（scan.py:85-118）前置过滤仅：空 df / 锚定日无 K / <120 根 / NaN / 非正价 / 锚定日 ST。**无窗口交易日覆盖检查**。

**设计**（复用系统既有缺日定义，不另造标准——数据预检 `data_reader.precheck` 的 missing_day 口径即链 meta 存疑清单来源）：

```python
def scan_stock_anchor(df, as_of, expected_bars: Optional[int] = None):
    ...
    # 既有六项前置过滤之后、ST 判定之前插入：
    if expected_bars:
        coverage = len(ordered) / expected_bars
        if coverage < CHAN_MIN_COVERAGE:          # config: 0.98（约缺 >10 天/520日）
            return "insufficient", None, f"窗口缺日{1-coverage:.1%}(<{1-CHAN_MIN_COVERAGE:.0%})"
        if coverage < 1.0:
            data_flag = f"缺日{expected_bars-len(ordered)}天"
    ...
    return "hit", hits[-1], data_flag   # hit 且有缺日时 reason 承载标记（原为 None）
```

- `expected_bars` 来源：**链侧** `ctx` 窗口交易日数（链 meta 已有窗口信息）；**报告侧** `_aggregate_chan` 用 `reader` 交易日历计算 `[start, as_of]` 区间交易日数。两入口各自传入，引擎不依赖日历（保持纯函数）。
- 前复权断裂不在引擎重复检测（非正价已挡极端值；断裂检测属数据预检职责，见 3.3）。

**config 新增**：
```yaml
chan:
  min_coverage: 0.98        # 低于此值 insufficient；[min_coverage,1) 打标记保留
```

**测试**（`tests/test_chan_structure.py` 或新 `test_chan_scan_gate.py`）：①窗口删 3 天 → `hit` 且 reason="缺日3天"；②删 15 天 → `insufficient`；③`expected_bars=None` → 行为与旧版完全一致（兼容性）；④520 根全 → reason=None。

### 3.2 调用方透传（两入口）

- `chan_divergence_buy.analyze`：`scan_stock_anchor(df, ctx.as_of, expected_bars=ctx.window_trading_days)`；hit 分支 detail 增 `'data_flag': reason`。
- `aggregator._aggregate_chan`（aggregator.py:1699）：`expected_bars = self.reader.trading_days_between(start, as_of)`（DataReader 补一个小方法，SQL 数 `base_trade_calendar`）；items 增 `'data_flag'` 字段。

### 3.3 报告层交叉披露（`chan_candidates.py` + digest 数据质量）

- `chan_candidates.build`：表格头增**"数据标记"**列（items 的 `data_flag`，无标记显示 —）；小节脚注固定统计行：`本日 {N} 只候选中 {M} 只带缺日/断裂标记`。
- 与链 meta 存疑清单的**全集交叉**（覆盖 data_flag 之外的前复权断裂）：`_aggregate_chan` 末尾读当日链 meta 存疑清单（`_csv_path` 同目录），items 与存疑集求交，交集结果写入 `data['suspect_overlap']`；`chan_candidates` 脚注渲染。链未跑/无 meta 时该字段缺省并注明"存疑清单不可得"。
- digest 数据质量表（digest_note 模板项）：新增固定行"缠论候选×存疑交叉 | N/M | …"，由 P2-5 校验脚本断言存在（见 §5.3）。

### 3.4 回测敏感性脚本（新增 `scripts/chan_missing_sensitivity.py`）

目的：验证 +6.8%/53.1% 先验在门控下量级不变（V2.0 P0-7 的结论性风险项）。

1. 用当前库 520 日窗口逐股跑 precheck 缺日统计 → 验证样本（2015-2026 全A）中缺日股占比；
2. 复用 `chan/backtest.py` 口径分两遍：全样本 vs 剔除 `coverage<0.98` 样本，输出一买/二买 60 日费后均值/胜率对比表；
3. 产出 `data/chan_validation/missing_sensitivity_<ts>.md`：**若任一统计变动 >1pp → 升级为 HIST_NOTE 修订流程**（同步 `chan_candidates.py` 常量、SKILL.md、本方案状态）；≤1pp → 记录"量级不变"结论并附数字。

**验收（本步整体）**：单测全绿；10-23 重跑 digest 缠论小节含数据标记列与交叉脚注（16 只逐只可查）；敏感性报告产出且结论明确；同 as_of 两次重跑 chan items 逐值一致。

## 六、步骤 5-6：P0-1/P0-2 涨停判定重构与回补

### 6.1 数据基准决策（实施前先做一个核实动作）

### 6.2 判定算法（`limit_up_rules.py` 重构）

采用**价格量级动态阈值法**（免精确昨收、对除权日鲁棒，且向量化友好）：

```python
def dynamic_threshold_pct(pct: float, raw_preclose_est: float) -> float:
    """涨停判定下浮 = 半个最小报价单位 / 估计昨收。0.005/5元=0.10%（退化为现口径）。"""
    return pct - 100.0 * 0.005 / max(raw_preclose_est, 0.5)

# annotate_limit_up 内（向量化）：
raw_close = out['raw_close']（缺失列时回退：est = close，并打 _limit_exact=False）
raw_preclose_est = raw_close / (1 + change_rate/100)
threshold = 动态阈值(limit_pct, raw_preclose_est)      # 逐行向量化
hit = change_rate.ge(threshold) & close.ge(high)       # 护栏保留
```

- 精确性依据：真实涨停涨幅 ∈ [pct − 0.005/p, pct + 0.005/p]；动态阈值覆盖下界，护栏剔伪命中，两者配合召回精确双优。
- `raw_close` 缺失的历史行回退现固定阈值并标 `_limit_exact=False`（口径注记随行）。
- `annotate_limit_down` 镜像同改。
