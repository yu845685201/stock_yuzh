# 盘后采集数据源整合详细技术方案

**V1.0 · 2026-11-26 · 待评审**　工程 `stock_yuzh`，核对基线 `16789c6`。需求、样本统计和选源理由见[优化方案](盘后采集数据源整合优化方案-V1.0-20261125.md)，原始故障见[缺口报告](reports/collection_gap_analysis_20261119_1124.md)。下文标注“拟增”的表、配置、接口均属于待实施设计。

## 1. 交付边界与实施批次

每次采集既要核对目标交易日的必需分区是否齐全，也要记录复盘截止时实际能使用的数据版本。首轮按一次正式作业计算，允许在同一轮切到已核验的备用源。必须次日才发布的项目按其披露时点考核。日 K 仅作为已有只读输入。

| 批次 | 变更范围 | 第一组验收数据 |
|---|---|---|
| A | 日期解析、分区提交、补采、两融、上海 ETF 期权 | 11-20 两融沪深 4,138 条逐股对账。11-16/17 补风险表，11-20 在已有风险表时单补标的统计 |
| B | 龙虎榜三块交易所数据、巨潮席位、国证行业日期快照及读端 | 11-20 沪市 30 起 A 股事件和 1 起基金。11-24 国证 5,581 个 A 股代码 |
| C | 正式财报触发、财报版本与估值可知时点、除权事件与兼容因子 | 三个北交所说明会反例、2026Q3 包、688150 差异化分红、北交所除权样本 |
| D | 分笔差集续跑、情绪按日验收、全链路指标、故障演练 | 11-24 分笔 5,576 只和封板 182 行，同日复跑零新增仍完整 |

保留 `sync-review-all`、`sync-review-data`、各单源命令及 `sync-review-pending`。新来源挂在原有 dataset 下，避免调度同一业务两次。新增外部路径均采用公开可访问的文件或查询。本机样本支持字段与历史日期核对，持续可用性按第 11 节量度。

## 2. 日期、运行入口与分区契约

### 2.1 锚定日、业务日、截止时刻

统一用 `YYYYMMDD` 存业务日，`TIMESTAMPTZ` 存时刻。上海交易时钟用 `Asia/Shanghai`。进入 `base_trade_calendar` 查询时才转为带横线日期。保留 `RunContext.target_date` 表示作业锚定日，分区 `expected_date` 表示应采业务日。区间、单源显式日期、队列都带“日期已解析”语义。日历缺失登记 `CALENDAR_UNKNOWN`，等待日历就绪再发请求。[日期契约](../backend/src/sync/collection_contracts.py) · [源期望](../backend/src/sync/source_expectations.py)

| 运行入口 | 日期规则 | 2026 年样例 |
|---|---|---|
| 盘后编排 `--as-of A` | A 为报告锚定日。两融目标为 A 前一交易日，期权等取 A。默认 A 取最近已收盘交易日 | 周一 11-23 盘后 → 两融 11-20、期权 11-23 |
| 次交易日晨间采集 | 两融按“发布交易日 P 的上一交易日”排任务，持久化该业务日。可在前一晚预排。凌晨唤醒按待办运行 | 周一 11-23 早晨 → 周五 11-20，避免对最近收盘日再减一次 |
| 单源 `--trade-date D` / 历史区间 | D 已是业务日。区间先按交易日历展开，再逐日分区 | 指定 11-20 → 两融、期权都请求 11-20 |
| 跨午夜补采 / `SCOPE_RETRY` | 只用持久化的业务日、交易所、子项及缺口范围 | 11-25 领到 11-20 深市两融 → 只补 11-20 深市 |

把期望规则的读取路径统一到 `review_sync.source_expectations`，兼容现存顶层同名配置，重复定义时显式采用新位置。区分 `first_check_at` 与 `deadline_at`，两融截止锚到业务日的**下一交易日**盘前。`_build_runners` 中两融、期权、行业、情绪需透传目标日。拆开 `sync-review-pending` 的整源重跑与回填期望计算，该处调用 `expected_partition` 时依赖导入且异常会被吞掉，现有结果不能充当业务日凭据。[正常入口](../backend/src/sync/review_sync_orchestrator.py) · [单源及待办入口](../backend/src/cli/review_sync_cli.py)

### 2.2 分区、结果及必需范围

沿用 `build_partition_key`，格式为 `日期|市场|交易所|dataset|子项[|证券]`，源名独立保存在 `PartitionResult.source`。例如 `20261120|CN|szse|margin|detail`、`20261120|CN|sse|option|stats`。管理器接收已解析的计划、返回一组 `PartitionResult` 和兼容的作业摘要。旧调用方仍可读取 `success/stats/errors/blocked`。迁移后的编排和待办以分区为准。

| dataset | 必需范围与验收单元 | 其他数据的处理 |
|---|---|---|
| `margin` | `sse/detail`、`szse/detail` | 巨潮是同分区的验证或替代提供者 |
| `option` | `sse/risk`、`sse/stats` 各自验收，整日需两者及跨表核对通过 | 最新挂牌主数据按真实观察日独立缓存 |
| `lhb` | `sse/main`、`sse/star`、`szse/auction` 各分 `events` 和 `seats`，如子项 `star.seats` | 父分区记录缺席位的事件 ID，不按席位逐条创建队列任务 |
| `industry` | `cni_l1`、`sw_2021`、`sina_hy` 按各自口径独立验收 | 报告声明必需体系。其他体系失败只影响其读者 |
| `ths_finance` | 先验收当日公告清单，再验目标证券、报告期、公告版本集合 | 季报包本身的下载成功只说明文件可用 |
| `factor` | 沪、深、北分别记录 `events` 和 `compatible` | 无有效事件时给出零事件凭据，有事件而无兼容值时保留缺口 |
| `money_flow / valuation_calc / sentiment_metrics` | 资金流按有成交证券、估值按当日价格截面、情绪按锚定日一行 | 封板指标另按适用证券验收，可复用同批分笔 |

`expected_codes/observed_codes/invalid_codes/missing_codes` 的单位随子项固定为证券、合约、事件或报告。三组实到有效、实到无效、缺失互斥，相加等于应到数。范围外记录、重复行、尚无独立分母分别单记。`page_evidence` 保存官方总数、分页面摘要及日期凭据。`quality` 保存适用范围、字段缺项、差集摘要、来源及尝试结果。无独立分母不伪造计数，用官方完整名单、分页闭合或可核的当日事件清单证明完整。

| 情形 | 分区结果与调度 |
|---|---|
| 本次写入为 0，已有同目标日、范围、规则版本的合格数据 | `COMPLETE`，引用已有 revision |
| 官方明确发布且该范围无适用记录 | `CONFIRMED_EMPTY`，保存发布日期、覆盖范围和空集合证据 |
| 未到首查时刻或本轮早查发现仍未发布且未到约定发布时点 | `NOT_DUE`，保存下次观察时刻。超过截止后未取得须计入超时 |
| 部分证券、页面、必需字段缺失，或跨表发现矛盾 | `PARTIAL`，只排未解决范围。错日、重复分页或错误单位的批次禁止发布 |
| 外部拒绝、依赖未就绪 / 解析失败、无可信响应 | 分别用 `BLOCKED` / `FAILED` 并保留原因。`NOT_APPLICABLE` 用于合同范围外的项目 |

将 `_fill_entry`、`_derive_execution_status`、`entry_to_partition_result` 和待办结账统一读分区结果。完整或有证据为空计成功，有成功也有缺口返回退出码 3，全部应到项失败返回 1。全部未到期、计划预览或不适用且无执行故障返回 0 并报应到数 0。业务是否齐备仍呈现在独立的 `data_readiness`。真正没有运行的日子也应出现在稳定性分母。

**拟增内部调用约定。** `plan_partitions(ctx, dataset, *, business_date=None, scope=None)` 返回包含 `dataset, exchange, sub_dataset, expected_date, partition_key, first_check_at, deadline_at, contract_version` 的计划。只有显式业务日和队列提供 `business_date`。manager 的新增关键字参数 `plan` 为可选传入，单源旧签名按同一规则适配。`execute` 返回的 `partitions` 列表保存真实来源、预期与实到业务键、质量、状态和 revision。`stats.rows` 继续表示本次写入量。每个已迁移的入口都以同一组 `partitions` 计算待办和对外摘要。

## 3. 事务、队列和访问控制

### 3.1 每次尝试与当前可用版本

`sync_partition` 现有唯一键 `(job_id,dataset,source,market,partition_key)` 适合记录作业观察。`latest_partition_status(dataset,market,date)` 会把不同子项混在一起。保留前者，新增一张小表保存逻辑分区的发布指针与首轮验收时刻。旧记录由回放复核后再建立指针。下列为批次 A 拟增 DDL 核心，迁移与 Python 的 `ensure_*` 保持一致。[现有分区事务及索引](../backend/src/database/dao_collection_lineage.py) · [已部署的闭环表定义](migrations/20261119_review_closed_loop_up.sql)

```sql
CREATE TABLE IF NOT EXISTS sync_partition_current (
    dataset              varchar(64)  NOT NULL,
    partition_key        varchar(256) NOT NULL,
    business_date        varchar(8)   NOT NULL,
    contract_version     varchar(32)  NOT NULL,
    first_check_at       timestamptz,
    deadline_at          timestamptz,
    first_daily_job_id   varchar(36),
    first_ready_job_id   varchar(36),
    first_ready_at       timestamptz,
    accepted_revision_id varchar(36) REFERENCES dataset_revision(revision_id),
    accepted_status      varchar(24)
        CHECK (accepted_status IN ('COMPLETE', 'CONFIRMED_EMPTY')),
    accepted_source      varchar(64),
    accepted_at          timestamptz,
    PRIMARY KEY (dataset, partition_key, contract_version)
);
CREATE INDEX IF NOT EXISTS idx_partition_current_day
    ON sync_partition_current (business_date, dataset, contract_version);
```

计划时创建当前合同的期望行，首次正式作业写 `first_daily_job_id`。第一次合格提交用 `COALESCE` 固定首达时间、作业号。后续来源修订只更新当前指针。历史回放保留实际观察时刻和 `RunMode.BACKFILL`，不回填历史“按时成功”。某天作业整轮漏跑，根据交易日历、当时启用的合同版本重建该日应到集合，缺失指针算未达。查询当前结果按完整逻辑键和启用版本。查询当时结果按当时截止和修订链。

**单次提交顺序**

1. 在事务外经限速器抓取、解析、标准化并校验。原响应按 SHA-256 去重落盘，保留 URI、源、业务参数、拉取时刻和解析版本。保留被有效 revision、已发布报告或未结待办引用的原件，定期清理无引用的临时件。完整快照另存规范化数据。临时文件同目录写完后原子改名，失败不发布引用。公开可重放数据可使用压缩文件。
2. 复用 `apply_partition` 的事务级 advisory lock。同一逻辑分区固定先锁分区，再锁当前指针，再锁相关待办。若为租约作业须重新检查 token、到期时刻与缺口版本。网络请求、文件下载都在锁外。
3. 锁内重新读已发布 revision。比较日期、范围、官方修订证据与来源优先级。迟到响应的基线已过期时重新核对或登记冲突。针对不同子项写同一业务表的情况，按相同目标行顺序加锁，或指定一个投影写者。`content_hash` 对按业务键排序的规范化数值求哈希，`quality_hash` 只含影响语义的字段。耗时、请求 ID 等不进这两个哈希。
4. 通过使用外层连接的 `*_tx` writer，一次提交业务数据、`sync_partition`、`dataset_revision`、当前指针、相应 `recompute_task` 和待办状态。当前 `apply_partition` 即使哈希未变仍可执行 writer，且验收行可能缺父 revision。迁移后未变时复用父版本、保存本次观察并结账。真实零行修订也须能撤下旧的非空投影。对整分区采用“完整快照校验后替换该范围”，对局部补采只改已证明的行。影子结果及失败尝试只写审计，不移动正式指针。同一逻辑分区一次只有一个合同版本拥有正式表写权。切换时锁内同步更新读路由和投影版本。不同合同或解析语义要纳入质量哈希，历史读者仍按冻结的 revision 取快照。
5. 子项可独立提交。整日验收从必需子项和跨表检查汇总。崩溃发生在提交前时事务回滚，提交后而主进程未回报时，接管者按目标键读取已验收版本，幂等结账。

### 3.2 待办与风控

`sync_collection_retry` 的现有去重键为 `dataset|market|target_date[|sub_key]`。沿用 `SCOPE_RETRY` 与固定子键（如 `szse.detail`、`sse.stats`），由同一映射生成分区键及待办键。旧 `SOURCE_RETRY`、`lhb.seats`、`industry.sw_2021` 在领取时展开为子项，全部必需子项就绪后结清父项。有几千个缺失股票时持久化完整集合的快照 URI 和摘要，领取时用数据库差集重新确定个股，现有截断的 `missing_scope` 仅供显示。[队列 DAO](../backend/src/database/dao_collection_retry.py) · [既有补采迁移](migrations/20261120_collection_latency_up.sql)

保留 `FOR UPDATE SKIP LOCKED`，按实际发起的失败尝试消耗预算。未到时、已存在合格数据或在发出请求前命中冷却只改下次领取时间。最后一次领取进程崩溃时，清理过期租约并转入可恢复的失败状态。待办新一代缺口重建预算，留旧失败轨迹。并发新增范围只扣除本次已验集合。租约过期的旧进程在业务提交前被拦下。对备用路径可工作的任务，领取器不得因主路径域冷却而整项跳过。沿用 `pending_handoff_enabled` 的现有调度方式。

全部 HTTP 请求使用 `HttpCollectorBase` 的 `get_json/post_json/get_content`。为需要日期头、304 或指定状态码的场景补充返回少量响应元数据的接口。按主机规范化 `hostname`，包括 `down.tdx.com.cn:8001`。登记 `www.cnindex.com.cn`、`www.tdx.com.cn`、`down.tdx.com.cn` 和实际用到的新浪主机。端点键使用稳定家族名或“短名＋完整路径与白名单参数的哈希”，在现有 32 字符冷却键长度内区分长 `sqlId`，不把日期、股票代码划为独立限速域。巨潮全市场响应同一业务日只拉一份，冷却期复用已验证的不可变缓存。[HTTP 采集基类](../backend/src/data_sources/http_collector_base.py) · [域门](../backend/src/data_sources/domain_gate.py)

| 现象 | 请求端处理 | 作业端处理 |
|---|---|---|
| 429、明确拦截页、服务端指定 `Retry-After` | 遵守服务端等待时间、暂停对应主机 | 切换可独立访问的合格源或延期 |
| 403 / 400 | 403 暂停端点，多端点连续被拒才升级。400 保存业务参数进行诊断 | 保留源错误原因，同一失败请求不循环重放 |
| 200 返回登录页、损坏 ZIP、列变更、错日 JSON | 识别拦截特征与格式异常，分别标记。检查文件签名、字段、日期和 CRC | 记录证据，已有正式快照继续可读 |
| 国证日期目录指定 404 / 5xx 或超时 | 按约定时点解释 404。5xx、超时按现有限额退避 | 队列登记首次与末次尝试、主备实际耗时 |

目前 `domain_gate_enabled=false`。为灰度增加可选域白名单，保留旧布尔配置的全局语义。先验证多进程单域节拍，然后开放到下一个域。BaoStock 的非 HTTP 查询单独串行登录复用，每业务日一个事件清单请求，失败只影响对应核验项。

## 4. 两融与上海 ETF 期权

### 4.1 两融提取、校验与写入

改造 `SzseSseSource`、`CninfoSource`、`MarginManager.execute/backfill_range` 和 `upsert_margin_trades`。每个代码按来源声明的交易所加前缀，保留六位代码，证券类型从范围清单判定。沪深项目范围包括原已收录的基金和存托凭证，巨潮的北交所记录进入范围统计。规范化金额全程使用 `Decimal`，最终落现有 `NUMERIC(24,4)`。[交易所采集器](../backend/src/data_sources/sse_szse_source.py) · [两融管理器](../backend/src/sync/margin_manager.py) · [巨潮采集器](../backend/src/data_sources/cninfo_source.py)

| 来源 | 请求与完备证据 | 字段对照 |
|---|---|---|
| 上交所 | GET `query.sse.com.cn/marketdata/tradedata/queryMargin.do`。`tabType=mxtype,detailsDate=D,isPagination=true`，`pageHelp.pageSize=2000,cacheSize=1`，每页把 `pageHelp.pageNo/beginPage/endPage` 同设为 n。核 `pageHelp.total/pageCount`、`result`、每行 `opDate`、代码集合与页哈希 | `stockCode → ts_code`，`rzye/rzmre/rzche` 为元。`rqyl` 为余量。融券金额无可靠值时保留字段缺项 |
| 深交所 | GET `www.szse.cn/api/report/ShowReport`，`SHOWTYPE=xlsx,CATALOGID=1837_xxpl,TABKEY=tab2,txtDate=YYYY-MM-DD`。按表头识别金额列、去千分位。文件名、生成时刻均不含业务日 | `融资余额(元) → rzye`、`融资买入额(元) → rzmre`、`融券余额(元) → rqye`。另读两融合计作校验。`rzche` 为空 |

统一新增 DAO 读方法 `fetch_financial_versions_asof(cutoff_at, codes, periods, mode)`。先按截止时间过滤，再在每只股票的每个报告期内选一个完整可用版本，最后截取最近 N 个报告期。真实更正按已证实的公告继承关系生效，同一公告多个数值源按字段权威次序选择，缺入参不能用未来版本补。严格回放需公告已公开且**该版本**当时已观察到。只有可核原件但缺当时观察记录的，进入 `PUBLIC_RECONSTRUCTION` 研究视图。只有日期且要判定盘中可知时，采用首次有可信观察的时间或暂缓使用。当前版本指针用于最新视图，历史查询必须选当时版本。历史截止筛选同时约束报告期上界。若同一公告的数值存在冲突且无裁决，保留待核，不用记录的写入顺序决定采用版本。

接入 `ValuationCalcManager`、`analysis/env_assembly.py` 的估值/CAGR 查询及 `candidate_veto.py` 的财报判断，取消个别消费端只按报告期下界过滤或用固定天数猜发布日期的路径。日常估值沿用当前计算函数，保留价格口径与有效日股本的来源。对有股本变动的样本核实生效日和信息到达日。已发现价格输入口径异常时登记输入缺项，交由既有行情治理流程处理。[估值同步](../backend/src/sync/valuation_calc_manager.py) · [TTM 计算](../backend/src/utils/financial_ttm.py) · [分析查询](../backend/src/analysis/env_assembly.py)

TTM 利润使用 `本期累计 + 上年年报 − 上年同期累计`，年报直接取全年。三项财报分别按同一截止时刻取版本。缺上一年年报不能用更早年报顶替。`total_mv=价格×有效股本`，`pe_ttm=total_mv/TTM归母净利`，`pb=total_mv/期末归母权益`，保留既有分母与缺失处理。更正触发 `recompute_task`，范围限该证券、版本可知日起且 TTM 或权益依赖该报告期的交易日。定向重算绕过历史回填“达到 80% 行数就跳过”的快捷条件。合并同输入版本的重算。原已发布报告保留其输入清单，必要时另发修订批次。验证更正前的严格回放值和批次摘要保持一致。

## 8. 除权事件和兼容因子

**事件采集。** 通达信 `gbbq.zip` 按版本下载，行业和因子共用文件缓存，用兼容的离线读包器解析除权文件，按记录数、类别、有效日期、证券覆盖验证。包更新时保留全量原始摘要，比较当前版与上个版本，提取 `category=1`，把分红、送转、配股等权益分量分别存储。源单位（如每 10 股）与转换后的每股值分列。同股同日可能同时具备多种权益，不以证券和日期两列去重。预告进入候选清单，到达生效日才进入当日验收。仅有旧包且无当日发布或覆盖凭据时，空差集保留待核。沪深按日调用 BaoStock 交叉检查，北交所用公告和有事件证券的新浪记录。[通达信文件](https://www.tdx.com.cn/products/data/data/dbf/gbbq.zip) · [BaoStock 更新接口](https://baostock.com/mainContent?file=DailyUpdates.md)

`/api/ths-factor` 的现有定义是 `q=同花顺前复权收盘/同日通达信未复权收盘`，`h=同花顺后复权收盘/同日通达信未复权收盘`。BaoStock 涨跌幅因子、事件包和新浪记录用于发现与核验。候选算法显式保存权益参考价、现金项、锚定日和价格舍入规则。单一乘数无法表示的现金平移不得忽略。可取得当时同口径 Q/H 与原始 R 时，以共同日期计算候选 `q=Q/R, h=H/R`。走权益重建时先用官方参考参数生成可回放的 Q/H 序列，再按同一 R 转成现有定义。R 缺失或为零、参考现金不明时停止该证券的提升，其他证券可继续。R 来自已有已校验原始价格字段，不能以已经前复权的价格充当 R。[因子管理器](../backend/src/sync/adjust_factor_manager.py) · [中间件实现](../../tdx-api/extend/spider-ths.go) · [BaoStock 算法说明](https://baostock.com/mainContent?file=factorInfo.md)

提升前逐日核 `R×q`、`R×h`，并对非零 q 检查消费端 `Q×h/q` 对 H。按该证券当日价格刻度及正式因子存储精度比对。历史负前复权价格需保留符号。比对现金分红、送配组合、多次事件、更正及无事件日。`688150` 区分除息参考现金 0.199 和实际分红 0.20。`920176/920201` 用于验证北交所覆盖。七个交易日两源原始事件量 81 与 66 包含 ETF 及市场范围差异，验收以解释后的适用证券事件集合为准。[差异化分红公告](https://static.cninfo.com.cn/finalpage/2026-11-11/1225665861.PDF)

`read_adjust_trigger` 对“已确认空”“不存在”“损坏”返回不同结果。事件发现与 K 线依赖解耦，兼容值仍走价格质量门控。按证券锁整段发布，防止相邻生效日同时改写此前锚点。事务内核对父版本，写入序列后重检下游窗口并只重算受影响日期。`chan.data._rebuild_hfq` 当前在缺日期时使用序列末值，空序列还可能取下标失败。改为按同系列、目标日明确有效区间取值，无匹配、q 为零或无前值时输出不可用及原因。事件已恢复与可供负价股重建的因子已恢复分别验收。[后复权消费端](../backend/src/chan/data.py)

**运行指标。** 连续观察 20 个交易日，财报另覆盖一次披露高峰。按数据集和市场公布应到分区数、主源首轮完成数、同轮备用接管数、首轮完整率、截止前完整率、补采恢复时间、403/429 和错日次数。整日再独立计算“当日全部必需子项一次齐”的天数/应到天数，避免多个小分区的平均值掩盖每天缺一项。首轮已过截止才成功，只算首轮完整。历史回放与影子吞吐单独统计，不并入生产首轮。事后发现首轮误收错日或错单位时，依据首次验收修订链重述该日有效成功数，同时保留原报值和撤销原因。建议门槛为首轮完整率 ≥95%、截止前完整率 100%，同时错日、错误单位、正式表重复键均为 0。跨源未解释差异不计通过。

建议冷缓存同机整日 P95 预算为两融 30 秒、期权 30 秒、龙虎榜 60 秒、国证 90 秒、资金流 10 分钟。分别记录排队、限速、关键网络请求、解析、数据库提交和端到端耗时，跨日发布等待单列。另外报告暖缓存复跑。用单轮作业墙钟统计算法链并发耗时，避免把所有并发请求耗时相加。若新源首轮通过而截止率或开销未达标，保留在校验或备源角色，继续使用该数据集已经验收的路径。

下面的 SQL 按逻辑分区检查一个业务日的落地结果。第二段用于预建好应到集合后的截止完整率核对，示例截止时间可替换。生产指标还需按启用日期与日历补齐漏运行的应到行。首轮指标另按 `first_daily_job_id=first_ready_job_id` 核算，仅限正式运行和其真实截止证据。

```sql
SELECT dataset, partition_key, accepted_status, accepted_source, first_ready_at
FROM sync_partition_current
WHERE business_date = '20261120' AND contract_version = 'v1'
ORDER BY dataset, partition_key;

SELECT dataset, count(*) AS due_partitions,
       count(*) FILTER (WHERE first_ready_at <= deadline_at) AS ready_on_time,
       round(100.0 * count(*) FILTER (WHERE first_ready_at <= deadline_at)
             / NULLIF(count(*), 0), 2) AS on_time_pct
FROM sync_partition_current
WHERE contract_version = 'v1'
  AND deadline_at <= TIMESTAMPTZ '2026-11-25 09:30:00+08'
  AND business_date BETWEEN '20261102' AND '20261124'
GROUP BY dataset
ORDER BY dataset;
```

## 12. 迁移、发布及回退

1. **扩展结构。** 在测试库跑每批 up 两次并核对索引、约束和随应用建表逻辑。生产按批次扩展结构、建立快照目录和合同版本。大表索引采用适合部署窗口的方式。首批仅准备控制表、交易所事务写入及必要配置。记录原报告、旧业务行、目标分区快照及输入摘要。
2. **并行验证。** `shadow` 将数据写入版本化候选或校验快照，沿用相同域门、同日巨潮缓存与正式作业核对。旧数据没有子项/日期证据的按旧口径展示，不预填为新合同成功。两融先回放 11-20、11-24，再核 11-16、11-18。期权分子表补 11-16 至 11-24。
3. **按分区切换。** A 先单所或单子表投产，再开放同批其他子项。B 先发布新事件和国证快照，再切报告读者。C 分别启用财报事件、可知版本、除权清单、兼容序列。无匹配算法的证券停留待核。D 核查差集、恢复和真实作业耗时。每个切换点记录运行配置、可回退版本与影响报表。
4. **回退数据与读者。** 关闭有问题的适配器或读路径。按本次影响的业务日/证券，在相同分区锁下用上一已验收快照恢复投影，创建注明回退原因的新修订并挂接重算。覆盖、删除过的行都需可还原。已发布批次及修订链保留。已查明为错误且无可用旧版的分区撤下可用标志、回到待补。仅改开关无法纠正已写入的错误金额或历史因子。
5. **收尾。** 复核源及单位、目标日差集、队列积压和报告使用日期。旧 `FAILED` 待办在对应范围确实齐全时关联到新作业并保留失败经过。仅在确认没有新读写引用且备份可恢复后执行结构 down。常规回退只切读写及恢复版本。

每批切换评审检查日期与单位对账、同源与跨源覆盖差、首轮及截止完整率、P95、故障注入结果和可恢复快照。尚缺实盘首发时点或同口径替代的项目按其实际覆盖范围发布，其中包括通达信季报包披露当日的到达时差、部分证券的兼容复权值和分笔资金流的独立备用源。
