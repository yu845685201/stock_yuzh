### 分桶口径（compute_money_flow 扩展，单遍循环按 direction 累计四桶）

| 桶 | 单笔金额 | 列 |
|---|---|---|
| 超大单 | ≥ 1,000,000 | super_big_* |
| 大单 | ≥ 500,000（**含超大**，现有 big_* 口径不变） | big_* |
| 中单 | [100,000, 500,000) | mid_* |
| 小单 | < 100,000 | small_* |

核对恒等式：`mid_buy + small_buy + big_buy ≈ 买盘总额`（big 含 super_big，桶间互斥全覆盖）。
**净额口径注记**（0930 实测教训，茅台 big_net 7.29 亿 < super_big_net 7.92 亿属正常）：
各桶净额是独立差值（买-卖），非嵌套包含关系——大额买单被非超大卖单对冲时
super_big_net 可大于 big_net；解读按"桶内方向"而非"桶间大小"比较。

## 1. 背景与目标

用户指出复盘体系缺少两个重要维度：**成交量**与**资金走向**。现状为半成品——
量能只有单点指标（放量倍数、成交额今昨对比），资金只有异动子集近似口径（tdx 分笔
大单单桶）。本方案把两维度升级为一等公民：

- **量能**：市场级量价四象限 + 量能趋势；个股级量能趋势档位；板块级量能聚合；
- **资金**：板块级资金流向聚合、个股资金趋势、候选资金确认谓词；
  P2 解锁全市场分桶口径；P3 补北向与 ETF 两个市场级增量资金锚。

**用途边界（继承复盘框架 §3）**：量价/资金指标用于状态描述与条件-动作参考框架，
非次日涨跌预测；候选资金确认只作加分证据，不改变候选=观察名单非推荐的定位。

**数据源红线（用户约束 2026-10-05）**：东方财富、akshare、tushare **一律不使用**；
全部数据仅来自库内计算、tdx-api、沪深/港交易所官方披露渠道。

## 3. P1：零采集落地（库内数据直接算）

### 3.1 链新模块（backend/src/analysis/modules/）

**① `volume_trend`（量能趋势档位）**
- 输入：个股日 K volume 序列（纯 K 线，零新依赖）；
- 计算：今日量 vs 前 5 日均量（比值 r5）与 vs 前 20 日均量（r20）双档；
  判定：`连续放量`（r5≥1.5 且近 3 日中 ≥2 日 r5≥1.2）/ `放量`（r5≥1.5）/
  `温和`（0.7≤r5<1.5）/ `缩量`（r5<0.7）；附 r20 供排序；
- 返回：`连续放量` / `放量` / `温和` / `缩量` / `数据不足`（窗口不足/停牌）；
- 参数：`surge_ratio=1.5`、`shrink_ratio=0.7`、`window=20`；
- **登记 README.MD**；与 volume_surge 并存（单点倍数 vs 档位，口径互补不替代）。

**② `money_trend`（个股资金趋势，口径受限版）**
- 输入：money_flow_daily 该股最近 N 行（引擎装配 upstream 查表 `mf_history_map`，
  仿 env_assembly 机制扩展；**不进模块内查库**）；
- 计算：今日 big_net、5 日累计净额、连续净流入天数（big_net>0 计数）；
- 返回：`净流入{X}亿/连{n}天` / `净流出{X}亿` / `否`（无行）/ `数据不足`；
- **口径注记**：异动子集行才有钱流数据——非异动股多为 `否`（P2 后覆盖面提升，
  模块逻辑不变）；描述中的"亿"保留 2 位。

**③ 环境装配扩展**（env_assembly.py）
- `assemble_env` 增装 `mf_history_map`：{ts_code: [(trade_date, big_net_amt)] 最近 10 行}
  （一次 SQL，AS OF 锚定日）；仅当链声明 `env: a_share_candidates` 或新链声明时装配；
- tomorrow_candidates 链 YAML 增补 money_trend 模块（放 R4 之后，展示列用）。

### 3.3 报告层

**① 大盘环境块新增「量价状态」**（market_env.py + aggregator）
- 输入：trade_index_info 上证指数 volume/amount 序列（config
  `review.volume_price.index_codes`，默认 ['000001', '000985']——上证+中证全指双锚）；
- 计算：今日量 vs 5日/20日均量比值；**量价四象限**：当日涨跌 × 量能档位
  → `放量上涨=健康` / `缩量上涨=背离（反弹缺承接）` / `放量下跌=恐慌` /
  `缩量下跌=阴跌`；5 日量能趋势（均量递增/递减）；

## 4. P2：全市场分桶资金流

### 4.1 采集扩面（money_flow_manager.py）

- config `review_sync.money_flow.full_market: false`（默认关，灰度开关）；
- full_market=true 时子集 = 全股票池（~5,820 只/日）；请求节拍沿用

### 4.2 分桶扩展（compute_money_flow 纯函数扩列）

### 5.1 港交所互联互通日度数据（北向总额 + 南向净额，一表双锚）

> **2026-10-05 复核修正**：初判"北向停披露全不可得"有误——被假期文件（A 股休市日
> Northbound 表全空）误导。实测修正：**停披露的是买卖分项/净额/额度余额/十大活跃股，
> 成交总额一直在披露**。北向（活跃度锚，无方向）与南向（方向锚，真净额）同文件双采。

- **源（实测可得）**：港交所每日统计静态 JSON
  `https://www.hkex.com.hk/eng/csm/DailyStat/data_tab_daily_YYYYMMDDe.js`
  （页面隐藏字段 `hidCSMDailyStatJsonPath` 揭示；按交易日一文件，无登录无渲染）；
- **文件含 4 个 market 段，一次抓取全拿**：
  - `SSE/SZSE Northbound`（北向）：Total Turnover、Total Trade Count、ETF Turnover
    （**Buy/Sell 分项与 DQB 为停披露占位**——北向只作活跃度锚，无方向）；
  - `SSE/SZSE Southbound`（南向/港股通）：Total/Buy/Sell Turnover + 笔数
    （**净买入 = Buy − Sell，真净额口径**）；
- **历史深度（实测）**：文件滚动保留**约 2 个月**（20260401 完整可得 / 20260315 起
  404）——**实施时先回补最近 2 个月，此后每交易日增量，漏采即永久丢失**；
  休市日（如国庆假期）Northbound 表为 "-"，Southbound 为 0——休市状态可识别，
  假期"港股无南向定价"的解读证据即来源于此；
- 新表 `hkex_connect_daily`（trade_date, channel[north_sse/north_szse/south_sse/
  south_szse], total_turnover, buy_turnover, sell_turnover, etf_turnover,
  trade_count, source）——北向行 buy/sell 置 NULL（停披露不硬造）；
- 采集：`sync-hkex-connect-daily` CLI（日频，港股交易日盘后；按日文件幂等回补）+
  编排器波次（失败不阻塞）；合规沿用现行纪律（正常 UA/限速/退避）；
- 报告层两行呈现：
  - 「北向资金（成交总额）」行：当日总额 + 占两市成交比（外资参与度）+ 5 日趋势
    ——**口径强制点名：仅总额无方向，禁止解读为净流入/流出**；
  - 「南向资金（净买入）」行：当日净额 + 5 日趋势；假期并入「假期外围观察」块
    （区间累计净买入；假期 0 = 港股通关闭的真实状态，解读为"无南向定价"）；
- 与港股复盘链协同：南向正是港股池/恒指的边际定价力量，A1.5 外围链解读直接引用；
- 保留观察：北向 Buy/Sell 分项若恢复披露（同文件字段结构不变），采集器零改动扩展。

### 5.2 ETF 份额变动（沪深两所官方 API，确定性落地）

> **2026-10-05 复核修正**：初版"spike 后可能砍"升级为**确定性落地**——沪深两所
> 官方接口均实测打通（接口签名经开源实现核对后直连官方验证），历史深度远超预期。

- **上交所（实测）**：`https://query.sse.com.cn/commonQuery.do`，参数
  `sqlId=COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L&STAT_DATE=YYYY-MM-DD`
  （+pageHelp 分页，Referer 必须 sse.com.cn）；返回 SEC_CODE/SEC_NAME/ETF_TYPE/
  STAT_DATE/TOT_VOL（**份额，万份**）；**STAT_DATE 支持任意历史交易日，实测回溯
  2020-01 可得（6 年+）**；920 只全量单次拉取；
- **深交所（实测）**：`ShowReport/data?CATALOGID=1945`（PAGENO 翻页），749 只，
  `dqgm` 字段=份额（**万份，已用 159915 易方达创业板 206 亿份/510300 嘉实 241 亿份
  /159919 定标验证**）；**仅当日快照、无历史参数**——历史靠每日增量积累；
- 单位一致性：两所均为万份份额，可直接同表存储与求和；份额日变化 = 申赎方向
  的直接代理（份额增=净申购=增量资金流入）；
- 新表 `etf_scale_daily`（trade_date, exchange[sse/szse], fund_code, fund_name,
  etf_type, shares_wan）；
- 采集：`sync-etf-scale` CLI——上交所按 STAT_DATE 幂等（**先回补近 250 交易日
  历史，成本 = 每日 1 次请求**）；深交所当日快照增量（从复市日起积累）；两所
  各 1~2 次请求/日，编排器波次挂载；
- 报告层：「ETF 份额变动 Top」块（当日份额增减 Top10 + **头部宽基合计**
  ——沪深300/上证50/科创50/创业板/中证500 等宽基份额日变化合计，作为市场级
  增量资金锚，与两融/北向总额/南向净额并列）；口径注记：份额变动为 T 日快照
  差分，深交所在积累期不足 2 日时标"待积累"；
- 数据边界：上交所历史按 STAT_DATE 逐日回补（每交易日 1 请求）；场外申赎数据
  不覆盖（仅场内份额口径）；货币 ETF/债券 ETF 的份额波动与股市资金面弱相关，
  报告默认按 ETF_TYPE 过滤为股票型（config 可调）。
