## 1. 背景与目标

用户指出复盘体系缺少两个重要维度：**成交量**与**资金走向**。现状为半成品——
量能只有单点指标（放量倍数、成交额今昨对比），资金只有异动子集近似口径（tdx 分笔
大单单桶）。本方案把两维度升级为一等公民：

- **量能**：市场级量价四象限 + 量能趋势；个股级量能趋势档位；板块级量能聚合；
- **资金**：板块级资金流向聚合、个股资金趋势、候选资金确认谓词；
  P2 解锁全市场分桶口径；P3 补北向与 ETF 两个市场级增量资金锚。

**用途边界（继承复盘框架 §3）**：量价/资金指标用于状态描述与条件-动作参考框架，
非次日涨跌预测；候选资金确认只作加分证据，不改变候选=观察名单非推荐的定位。

**数据源红线（用户约束 2026-10-05）**：东方财富、akshare、tushare **一律不使用**；
全部数据仅来自库内计算、tdx-api、沪深/港交易所官方披露渠道。

## 3. P1：零采集落地（库内数据直接算）

### 3.1 链新模块（backend/src/analysis/modules/）

**① `volume_trend`（量能趋势档位）**
- 输入：个股日 K volume 序列（纯 K 线，零新依赖）；
- 计算：今日量 vs 前 5 日均量（比值 r5）与 vs 前 20 日均量（r20）双档；
  判定：`连续放量`（r5≥1.5 且近 3 日中 ≥2 日 r5≥1.2）/ `放量`（r5≥1.5）/
  `温和`（0.7≤r5<1.5）/ `缩量`（r5<0.7）；附 r20 供排序；
- 返回：`连续放量` / `放量` / `温和` / `缩量` / `数据不足`（窗口不足/停牌）；
- 参数：`surge_ratio=1.5`、`shrink_ratio=0.7`、`window=20`；
- **登记 README.MD**；与 volume_surge 并存（单点倍数 vs 档位，口径互补不替代）。

**② `money_trend`（个股资金趋势，口径受限版）**
- 输入：money_flow_daily 该股最近 N 行（引擎装配 upstream 查表 `mf_history_map`，
  仿 env_assembly 机制扩展；**不进模块内查库**）；
- 计算：今日 big_net、5 日累计净额、连续净流入天数（big_net>0 计数）；
- 返回：`净流入{X}亿/连{n}天` / `净流出{X}亿` / `否`（无行）/ `数据不足`；
- **口径注记**：异动子集行才有钱流数据——非异动股多为 `否`（P2 后覆盖面提升，
  模块逻辑不变）；描述中的"亿"保留 2 位。

**③ 环境装配扩展**（env_assembly.py）
- `assemble_env` 增装 `mf_history_map`：{ts_code: [(trade_date, big_net_amt)] 最近 10 行}
  （一次 SQL，AS OF 锚定日）；仅当链声明 `env: a_share_candidates` 或新链声明时装配；
- tomorrow_candidates 链 YAML 增补 money_trend 模块（放 R4 之后，展示列用）。

### 3.2 candidate_rules 资金确认谓词

- `is_r2` / `is_r3` 增加可选参数 `big_net`（今日大单净额）与开关 `money_confirm`
  （BUY_RULES 增键，默认 **false**——待用户校准）；
- money_confirm=true 时：R2/R3 额外要求 big_net>0（R4 本身即资金口径不变，
  R1 梯队股天然全有分笔数据不加约束）；
- 理由串不变（资金确认不进 label，作为报告候选表"资金确认"列展示）；
- **红线**：默认关，避免改变现有候选集；用户校准后 config 开启。

### 3.3 报告层

**① 大盘环境块新增「量价状态」**（market_env.py + aggregator）
- 输入：trade_index_info 上证指数 volume/amount 序列（config
  `review.volume_price.index_codes`，默认 ['000001', '000985']——上证+中证全指双锚）；
- 计算：今日量 vs 5日/20日均量比值；**量价四象限**：当日涨跌 × 量能档位
  → `放量上涨=健康` / `缩量上涨=背离（反弹缺承接）` / `放量下跌=恐慌` /
  `缩量下跌=阴跌`；5 日量能趋势（均量递增/递减）；
- 渲染：四象限判定 + 指数双锚对照表（同 digest 表格优先规范）。

**② 维度4 新增「板块资金流向」块**（stock_movers.py + aggregator）
- 聚合：当日 money_flow_daily（异动子集）join sw_2021 行业映射 → 行业大单净额
  合计与净流入家数 Top/Bottom5；join sina_gn → 概念净额 Top5；
- **口径注记（强制）**：聚合自异动子集（≈300-400 股），**系统性偏向异动板块**
  （涨停多的板块天然净额大），仅供观察不作排序结论——与"行业榜/概念聚集两套
  体系不混排"纪律并列；子集覆盖率（子集股数/全市场）随行展示；
- 个股大单净流入/流出 Top10 保留（现状），移入本块统一呈现。

**③ 预案与候选升级**（tomorrow_plan.py）
- V1 量能验点：单点 ±20% → **四象限 + 趋势**（"放量上涨→跟随；缩量上涨→兑现为主；
  放量下跌→防守；缩量下跌→观望或等企稳"），阈值沿用 volume_band_pct；
- 候选表加「资金确认」列：R1/R2/R3 行展示该股当日 big_net（子集口径，
  无行显示 `—`）；money_confirm 开启时未确认股标注 `⚠未确认`；
- 决策树 R2/R3 话术增补资金分支（"大单净流出且缩量→否决"）。

## 4. P2：全市场分桶资金流

### 4.1 采集扩面（money_flow_manager.py）

- config `review_sync.money_flow.full_market: false`（默认关，灰度开关）；
- full_market=true 时子集 = 全股票池（~5,820 只/日）；请求节拍沿用
  0.15s×3 并发 → 纯请求 ≈5 分钟，加抓取/计算预计 **每日 +6~10 分钟**；
- **灰度实测（实施第一步）**：连续 3 个交易日开 full_market 跑每日增量，
  监控：超时率（throttle_on_timeout_pct 自动降速触发次数）、风控急停次数、
  单股分笔可得率——任何一项异常即回退子集模式（单源失败不阻塞整体原则不变）；
- 编排器（sync-review-all）波次不动，money_flow 波次自然变长。

### 4.2 分桶扩展（compute_money_flow 纯函数扩列）

- 阈值参数：`super_big_threshold=1,000,000`（超大单）、现有 50 万=大单、
  中单 10-50 万、小单 <10 万（config 可调）；
- money_flow_daily 扩列（ALTER TABLE）：`super_big_buy/sell/net`、
  `mid_buy/sell/net`、`small_buy/sell/net`（9 列，numeric(24,4) NULL）；
- **历史不回填**：存量异动子集行的分桶列保持 NULL（不硬造，口径注记
  calib_note 更新为 `分笔分桶:全市场` / `分笔分桶:异动子集` 区分行级口径）；
- 封板指标逻辑不动（同分笔源，共用抓取）。

### 4.3 下游解锁

- money_trend 模块：口径注记自动升级（子集行覆盖率提升，模块零改动）；
- 板块资金聚合：口径注记由"异动子集"升级为"全市场分桶"；行业榜资金列
  （板块资金块表加"净流入家数"列）；
- 报告大单 Top10：口径注记随 calib_note 动态点名。

### 4.4 P2 验收标准

- 灰度 3 日实测报告（超时率/风控/覆盖率数据）经用户确认后转正；
- 分桶单测（构造分笔序列验四桶金额与方向）≥8 例；
- ALTER 脚本 + init SQL 同步更新；存量行分桶列 NULL 渲染 `—` 验证。

## 5. P3：南向资金（替代北向）+ ETF 份额变动

> **换源说明（2026-10-05 实测修订）**：用户红线不使用东财/akshare/tushare；北向官方
> 已停披露（实测确认），故本节由"北向资金"修订为**南向资金 + ETF 份额变动**，
> 数据源全部为交易所官方渠道（已逐一 curl 实测可得）。

### 5.1 南向资金（港交所官方日度统计）

- **源（实测可得）**：港交所每日统计静态 JSON 文件
  `https://www.hkex.com.hk/eng/csm/DailyStat/data_tab_daily_YYYYMMDDe.js`
  （页面隐藏字段 `hidCSMDailyStatJsonPath` 揭示的端点；按交易日一文件，无登录）；
- **字段（实测）**：SSE Southbound / SZSE Southbound 各含 `Total/Buy/Sell Turnover`
  与成交笔数——**南向净买入 = Buy − Sell**（真净额口径，优于原北向近似方案）；
  同文件 Northbound 表全空（停披露），同步记录该口径事实；
- **与港股复盘链协同**：南向资金正是港股池/恒指的边际定价力量——假期外围复盘
  （1002 大跌、1005 反弹）可用南向净额解释承接力量，A1.5 外围链解读直接引用；
- 采集：`sync-southbound-flow` CLI（日频，交易日盘后；按日文件幂等）+ 编排器
  波次挂载（失败不阻塞）；新表 `southbound_flow_daily`（trade_date, channel,
  buy_turnover, sell_turnover, net_buy, total_trade_count, source）；
- 报告层：大盘环境块加「南向资金」行（净买入 + 5 日趋势）；假期场景并入
  「假期外围观察」块（区间累计净买入）；口径注记：南向=内地资金买港股，
  与北向（外资买 A 股）方向相反，不得混称"北向"；
- 保留观察：若未来北向披露恢复（政策变化），同一端点 Northbound 表字段
  结构相同，采集器可直接扩展。

### 5.2 ETF 份额变动（深交所官方 API）

- **源（实测可得）**：深交所 `ShowReport/data?CATALOGID=1945`（ETF 列表，
  749 只，JSON 分页 + xlsx 导出；`subname` = 数据日期，随交易日更新）；
- **字段（实测）**：基金代码/名称/管理人 + `dqgm` 当前规模（**单位待 spike
  确认：万份份额 vs 亿元规模**，两者日度变化均可代理申赎方向，精度不同）；
- spike（半次会话）：①确认 dqgm 单位与精度 ②上交所对应端点探测
  （fund.sse.com.cn 本次探测返回空，沪市 ETF 510300 等大头在上交所，
  单边深市覆盖不全则降级为"深市 ETF 观察窗"）③近 30 日回补可行性；
- 落地（spike 通过后）：新表 `etf_scale_daily`（trade_date, fund_code, fund_name,
  scale, exchange）→ 报告层「ETF 份额变动 Top」块（份额增=增量资金流入代理）；
- **判定规则不变**：spike 结论（覆盖率/口径精度）写入附录，价值/成本不匹配即砍；
  两融（已有）+ 南向（5.1）已覆盖市场级增量资金锚，ETF 为锦上添花项。
