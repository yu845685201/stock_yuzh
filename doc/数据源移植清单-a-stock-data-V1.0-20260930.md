# a-stock-data 移植清单 V1.0（20260930）

> 来源：github.com/simonlin1212/a-stock-data（V3.10.0，Apache-2.0，10.4k star，约每 1~2 周发版）
> 性质：该仓库不是可安装的库，而是面向 AI 助手的"数据源技能文档"——87 端点 / 34 数据源，
> 内嵌可运行 Python + 每端点标注实测日期与踩坑记录。**移植 = 把对应章节代码改写为
> 本工程 `data_sources/` 正式模块**（遵守 `base.py` 接口、`http_collector_base` 稳定性设计、
> 安全红线文件头），并把其坑记录一并抄进模块 docstring。
> 原文快照：doc/reference/a-stock-data/SKILL.md（自 /tmp/a-stock-data-inspect 拷入，含 CHANGELOG）。

## 〇、与现状的关系（为什么这些算"缺"）

本工程已有方案 4.1~4.14 全套采集：指数K线/复权因子/财报指标/披露日历/指数估值/业绩预告/
PE-PB自算/概念板块/龙虎榜/资金流近似/两融/解禁/公告清单(巨潮)/外围市场，另有行业分类(sw)、
财报PDF、日K pipeline、1分钟K线。涨停/连板/炸板/跌停为**自算口径**（`analysis/limit_up_rules.py`
§3.9 阈值法 + close≥high），不依赖外部涨停池。

因此移植清单只含三类：**修既有 P1 缺陷**、**采集基础设施增强**、**自算不了/没有的新数据层**。
已有对应物的（复权因子、龙虎榜、两融、解禁、公告、业绩预告）不重复移植，最多列为对拍项。

## 五、移植总则

1. **坑随代码走**：每移植一个端点，把它章节里的实测日期、失效模式、校验逻辑（翻页 total
   一致性、身份字段校验、宁抛错不返回空表）一并抄入模块 docstring 与入参校验——这是该
   文档相对自行试错的核心价值。
2. **东财一律走 `em_get()`**（P1-5 落地后）；上游失效先查其 CHANGELOG（该项目 issue→修复
   响应约 1~2 周，如 #52 通达信 TCP 失效两周内补齐 HTTP 替代）。
3. **覆盖面声明以实测为准**：官方自述"北交所覆盖依端点而异"；主行情层（腾讯 K 线、逐笔、
   估值历史、baostock）均**不含北交所**，北交所只靠盘后包（2022-05-06 起）、北交所官方
   行情备胎与东财 clist，移植时不得假设全市场覆盖。
4. **每项移植后跑一次与现有源的对拍**（如同现有验收模式），差异进审计报告。
5. 本清单不含 git 操作；代码与文档改动均留在工作区，入库由用户决定。
