# 复盘闭环与赚钱效应四期优化方案 V1.0

> 日期：2026-10-07
> 依据：`~/.zcode/workspace/default/开源股票复盘系统调研.md`（15 个开源项目方法论对比）+ 用户三项决策（交易日志不做 / 周复盘不做 / 新闻层按调研清单能抓则抓）
> 定位：补齐「预期→验证→修正」闭环（调研称"区分玩具与系统的分水岭"）与赚钱效应/亏钱效应深度，报告结构向"结论先行"靠拢。

---

## 0. 总体设计约束

1. **不新增链模块**：daily_review / tomorrow_candidates 等链 YAML 与模块零改动 → 链 CSV 逐字节不变，A股回归红线自动安全。四期全部落在**报告层聚合（backend/src/review/）+ 两张新表 + 一个新采集器**。
2. **数据源红线**：全部指标库内计算（his_kline_day / sentiment_metrics_daily / limit_seal_stats_daily / sector_concept_map / trade_index_info / overseas_kline_day）；新闻层仅新增调研文档点名且实测可抓的源（财联社电报），东方财富/akshare/tushare 恒不采，同花顺（hexin-v 反爬，合规红线禁破解）不采。
3. **数据真实性原则**：无数据 → 三态中的「数据不足」或章节「⏳ 待补」，禁止编造；核验三态中**数据不足 ≠ 判错**（不污染战绩）。
4. **幂等可复现**：预测/核验按 trade_date upsert；同锚定日重复生成报告逐字节一致（正文无运行时间戳）。

## 1. 第一期：T+1 核验闭环（P0）

### 1.1 预期落库

新表 `review_prediction_daily`（trade_date 主键，payload JSONB），由 `review generate` 在生成当日报告时 upsert 写入：

| payload 键 | 内容 | 来源 |
|---|---|---|
| sentiment | 情绪定位 / 高度 / 涨停家数 / 炸板率 / 溢价均值 | agg.sentiment |
| verify_points | V1 量能基准（两市成交额亿元+±band%）、V1.5 四象限（双锚 quad）、V2 高度股（code/name/streak）、V3 溢价基准（premium_mean+涨停家数） | agg.market_env / volume_price / movers / sentiment |
| scenarios | gap_pct、两锚（恒指/纳指）锚定日收盘与日期 | tomorrow_plan._OVERSEAS_ANCHORS |
| candidates | R1~R4 全量池（ts_code/code/name/label/streak/evidence） | agg.candidates |
| version | 载荷结构版本（`1`） | — |

### 1.2 核验器 `review/verifier.py`

生成锚定日 T 报告时，读取 T-1（前一可得交易日）的 predictions，对今日截面核验，产出 `out['verification']`：

**三态规范**：`成立 / 不成立 / 数据不足`。竞价与盘中过程判据（决策树 confirm/veto 的竞价分支）无盘前数据，**按设计核验"结果端"**，过程端不核验、不冒充。

**核验项与 eps 阈值**（"变了才算变"）：

| 项 | 昨日预期 | 今日实测 | 判定 |
|---|---|---|---|
| 情景档位 | P1/P2/P3 判据（两锚较基准 ±1.5%） | 两锚最新可得收盘较基准累计变动 | 实际触发档 + 低开/高开预期是否兑现（上证 open vs 昨收，±0.3% 平开带） |
| V1 量能 | 今日基准 X 亿 ±20% | 今日两市成交额 | 放量(≥1.2X)/缩量(≤0.8X)/温和 + 与上证涨跌组合对照预案（信息性） |
| V1.5 象限迁移 | 昨日双锚 quad | 今日双锚 quad | 迁移描述 + 对照预案（信息性） |
| V2 梯队 | 高度股 X（N 板）晋级 | 今日是否涨停（同口径判定） | 晋级=成立 / 断板=不成立 / 无K线=数据不足 |
| V3 溢价 | 均值基准 Y% | 今日昨日涨停溢价均值 | 升/降/平（eps=0.5pct）+ 对照"接力修复/亏钱扩散" |
| 候选池 | R1~R4 观察池 | 每只今日涨跌幅/是否涨停/炸板/跌停 | 池统计：均值/中位数/胜率/晋级数/跌停炸板数/**超额 = 池中位 − 全市场已交易中位**（基准发生率口径） |

### 1.3 核验落库与滚动战绩

新表 `review_verification_daily`（trade_date 主键，payload JSONB）。滚动战绩 = 取最近 30 个有记录交易日聚合：

- R1~R4：平均超额、池中位>市场中位的天数占比（胜率）、晋级率 vs 全市场涨停率基准；
- 情景：P1 低开兑现率、P3 高开兑现率；
- V2：观察 n 次，晋级 n 次；
- 基准发生率旁证：按情绪回填表（sentiment_metrics_daily）回溯各情绪态的次日溢价均值分布（对照判据"用途=状态描述非预测"）。

### 1.4 报告与 digest 集成

- 新章节文件 `review/sections/yesterday_review.py`：渲染为**「〇、昨日核验（预期 vs 实际）」**，插在报告标题段之后、「一、大盘环境」之前；无昨日预测记录时输出"⏳ 无昨日预期记录（核验体系 2026-10-07 起逐日积累）"。
- digest（图文 HTML）在「一、大盘环境」前加「〇、昨日核验」摘要块。
- 章节顺序调整达成"结论先行"：情绪定位一句话提至报告开头导语段。

## 2. 第二期：赚钱效应/亏钱效应深度（P1，纯报告层）

聚合器新增 `_aggregate_money_effect(panel, cs_today, cs_prev)` → `out['money_effect']`，全部由 60d 面板向量计算：

| 指标 | 口径 | 调研出处 |
|---|---|---|
| 反馈矩阵 | 昨日涨停股按昨日板位（首板/2板/3板/4板+/合计）× 今日五分类（晋级涨停/收红/小跌(−5~0)/跌超5%/跌停）+ 停牌缺行单独计数；行内附今日均值/中位数 | vibe-astock"复盘先看死在哪" |
| 昨日炸板今日修复 | 昨日炸板股（cs_prev._burst）今日均值/中位数/翻红率/回封数 | vibe-astock prev_broken_recovery |
| 连板溢价 | 昨日 2 板及以上今日均值/中位数/翻红率（与反馈矩阵 2板+ 行互相印证） | vibe-astock consec_premium |
| 大面统计 | 今日全市场跌超5%/跌超7%家数、最惨跌幅、跌停家数；昨日涨停股中跌超5%家数与占比 | vibe-astock loss_effect |
| 涨跌幅分档 | 全市场累计分档家数：涨≥2/4/6/8/10%，跌≤−2/−4/−6/−8/−10%（剔除停牌无成交） | go-stock Up2~Up10/Down2~Down10 |

渲染：`sections/sentiment.py` 增「昨日强势股反馈」「亏钱效应与市场分布」两小节（维度2 章内）。

## 3. 第三期：情绪周期与题材深化（P2，纯报告层）

| 项 | 口径 | 渲染位置 |
|---|---|---|
| 情绪周期走向 | sentiment_metrics_daily 近 10 交易日：涨停家数/最高连板 0-1 归一 + 炸板率取反，三项均值为 score；走向 = score 首尾差（eps 0.05）；距窗口最低点第 N 天；窗口内分位；样本 <10 天标注不完整 | sentiment 章节「情绪周期定位」后 |
| 梯队断层 | ladder 中最高板与最低板（≥2）间缺失档位列表；无缺口="梯队完整" | sentiment 章连板梯队注记 |
| 封板时段分布 | limit_seal_stats_daily 首封时间五时段（≤09:35 / 09:35-10:00 / 10:00-11:30 / 11:30-14:00 / 14:00 后）+ 涨停股一次未炸占比 + 尾盘封（≥14:00 首封）占比；表无行→待补 | sentiment 章「封板质量」 |
| 头部题材集中度 | 第一大概念涨停家数 ÷ 全市场涨停家数 | sector 章节 |
| 题材事件树 | 涨停聚集前 3 概念（黑名单剔除后）：昨日题材涨停家数→今日家数（扩散/收敛）、昨日题材涨停股今日均值/翻红率/晋级数、今日题材内炸板数与最高板、题材内首封时间范围（首末拉开=发酵判读）；概念成分为 sina_gn 时点匹配口径注记 | sector 章节「主线候选」后 |

## 4. 第四期：消息催化新闻层（P3）

1. **源实测**（先 curl 后动手）：财联社电报（cls.cn 公开接口/公开页面，正常 UA 串行限速）为唯一新增源；同花顺热榜因 hexin-v 合规红线不采；东财系（人气榜/互动易）红线不采；Anspire/Tavily 等搜索 API 需 key，无 key 不采。实测记录（2026-10-07 curl）：cls.cn `get_roll_list` 返回 errno 10012 签名错误、
   `updateTelegraphList`/`telegraphList` 404、桌面/移动公开页均为客户端渲染无内嵌数据
   → 按合规红线不实现签名，**财联社不采**；改用**新浪 7x24 快讯**（调研清单"市场要闻"
   类目；`zhibo.sina.com.cn/api/zhibo/feed?zhibo_id=152` 公开 JSON，实测 200/0.2s，
   id/create_time/rich_text/tag 齐全，项目已有多条新浪源在用）。`day` 历史参数实测无效
   → **历史不可回补**，自 2026-10-07 起逐日积累，缺日标待补。首采实测：3 页 150 条入库，
   二次运行增量幂等（新入库 0）。
2. **采集**：新表 `news_telegraph`（news_id 唯一键 / publish_time / title / content / subject / importance / source）；采集器 `sync/news_telegraph_manager.py`（增量按发布时间游标，串行间隔走 config `review_sync.news_interval`，风控退避复用 http_collector_base）；CLI `sync-news-telegraph`；挂入 `sync-review-all` 波次。
3. **消费**：聚合器 `_aggregate_news(as_of)` → 当日要闻 Top10（重要优先）+ 聚集前列概念的关键词命中计数；渲染维度1「市场要闻」小节 + 维度3「题材催化」小节；digest 增要闻列表。**口径注记：新闻归因是市场叙事，不是核验过的因果。**
