## 3. 风险点清单

### P0——正在发生的静默缺口

| # | 风险点 | 证据 | 影响 | 建议 |
|---|---|---|---|---|
| P0-1 | **盘后编排外的源无任何新鲜度监控** | macro 停 26 天、option 停 2 日、north 源死 2 年，全部无人发现 | 分析/复盘引用到 stale 数据无感知 | 建"新鲜度巡检"：对全表 max(date) 设阈值（日频 T-1、周频 T-7），编排末尾或独立 CLI 输出红黄灯；已停 26 天的 macro 决定续跑或退役 |
| P0-2 | **"采集成功"≠"有当日数据"** | index_valuation 11-17 编排成功 40 行，实为 11-16 值；THS 因子 q_factor=0 当晚"拉取成功 0 行" | 官网文件 T-1 口径/未更新时，成功状态掩盖缺口 | 对关键日频源增加"数据日 vs 目标日"校验（入库行数>0 但 max(trade_date)<目标日 → 标"待补"而非"成功"） |
| P0-3 | **日K门控 80% 阈值过宽** | `_check_kline_ready`（orchestrator.py:402-423）：4873/5571=87.5% 放行 → 资金流子集按 4873 圈定，697 只静默失去资金流/PE-PB | 部分漏采被放行，缺口向下游扩散且不自知 | 阈值收紧至 95%+绝对差（如 |当日-上日|≤300 行），超限标"部分失败"并触发补拉；或门控对比"请求股票数 vs 实际入库股票数" |

### P1——单点与口径坑（有实测案例）

| # | 风险点 | 证据/案例 | 建议 |
|---|---|---|---|
| P1-1 | **Docker Desktop 不自启 = 中间件全灭** | 11-17 实际发生，日K/指数K/因子/分笔全挂 | macOS `launchd`/登录项设置 Docker Desktop 自启；或同步入口前加中间件健康预检（connect refused 即报"中间件未启动"并中止，避免 697 式静默漏采） |
| P1-2 | **日K单股 fail-fast 无整批熔断** | 11-17 首批 697 只连接拒绝 3 次耗尽即放弃，无批次级重试 | 中间件不可达时（连续 N 只同类型连接错误）整批熔断中止/延迟重试，而非逐股烧完 |
| P1-3 | **指数日K唯一来源无兜底** | index_kline_manager.py:2 "唯一来源，无兜底" | 可用中证/新浪指数接口做二级兜底，或至少 raw 与 qfq 对拍 |
| P1-4 | **除权检测两个盲区** | ①仅日常增量执行（显式区间补齐跨除权日→断裂）；②qfq 事后修订绕过检测（11-08 案例 002083） | 显式区间补齐后追加同款接缝检测；修订检测纳入 xdxr 触发清单复查 |
| P1-5 | **DO UPDATE 无条件覆盖** | dao_kline_day.py:57-77 全字段 SET；源端缺字段→已有值改 NULL | 高价值列（volume/amount/close）加 `COALESCE(EXCLUDED.x, his_kline_day.x)` 或源端字段校验 |
| P1-6 | **交易日历双口径与历史误判** | his_kline_day.trade_date 无横线 vs base_trade_calendar 有横线（写错静默 0 行，两次实际踩坑）；workday/range 硬编码 2025/2026 节假日表，历史误报 | 统一封装日期格式转换；跨年 前核对节假日表 |
| P1-7 | **缺省日期陷阱** | sync-money-flow 缺省当日（11-18 实际踩坑 289 全失败）；sync-lhb 缺省当日（补历史扑空） | 补历史命令统一要求显式日期或加 `--trade-date` 必填提示 |
| P1-8 | **concept/etf_scale 未入交易所串行链** | 依赖链仅 disclosure→lhb→margin（11-17 改造）；周频 concept 与日频源并发时仍可能撞同一域 | 依赖链追加 `'etf_scale': {'margin'}`；concept 周频避开日频时段 |

## 4. 已生效的缓解（本次排查确认）

- raw 兜底 + 台账 + 恢复阶段（今日实施）：THS 发布滞后类缺口当日自愈；
- disclosure→lhb→margin 串行链 + 1800s 冷却：交易所域三源防并发；
- 日K依赖源门控 + kline gate：总账级缺失有拦截（但精度不足，见 P0-3）；
- 断点续传（"已完成日已入库，重跑自动续"）：重跑不重复消耗请求配额。

## 5. 建议优先级

1. **立即**：新鲜度巡检（P0-1）+ 指数估值"成功≠有数"校验（P0-2）——两者都是低成本高收益；
2. **本周**：Docker 自启 + 中间件健康预检（P1-1/P1-2）——消除最大单点；
3. **迭代**：门控阈值收紧（P0-3）、除权检测盲区补齐（P1-4）、COALESCE 覆盖（P1-5）；
4. **顺手**：concept/etf_scale 入链（P1-8）、缺省日期提示（P1-7）、macro/option 续跑或退役决策。
