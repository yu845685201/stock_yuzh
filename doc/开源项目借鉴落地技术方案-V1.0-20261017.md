## 一、文档定位与基线实测

### 1.1 本方案做什么

评估报告回答了「129 个开源项目里有什么值得抄」；本方案回答「怎么抄、落到哪个文件、什么口径、怎么验收」。三个不做：

1. **不重复评估**——借鉴选型以评估报告 §5 分级清单为准，本方案只做落地设计；
2. **不改定位**——纯盘后静态分析 + 确定性计算 + 大模型解读，评估报告 §6 的「明确不建议」项本方案同样不接（实盘通道 / RL·ML 预测 / 重多智能体平台 / 实时盯盘 / TradingView 远端筛选）；
3. **不新造架构**——全部借鉴项插入既有架构的既有扩展点（模块目录 / 链 YAML / env 装配 / 报告层 sections / skill），不引入新框架。

### 2.4 结构决策：取消独立候选链（V1.3 决策，2026-10-18 已实施·增量 A）

**决策内容**（2026-10-17 用户定）：不设独立的 `tomorrow_candidates` 分析链；R1-R4 四模块合入 `daily_review` 链；候选全量底表即 daily_review CSV 的 R1-R4 四列；「最终推荐哪些股票」由 skill 对 CSV + 六维报告做**综合研判**产出（SKILL.md 路径 A 第三层精选池纪律），链只做确定性计算。

**理由**：
1. R 系列的五个前置模块（涨停/连板/放量/量能/新高）与 env 装配本就都在 daily_review 内，合入零额外机制；
2. 消灭一条「容易漏跑」的链——此前候选全量底表只在按需场景产出，日常复盘实际消费不到（覆盖率审计见 §2.3.1）；
3. 单一 CSV 底表：每日复盘跑完即得截面 + 候选，skill 解读从一个文件取全部输入；
4. 与「程序算数 + AI 解读」分工一致：链出确定性命中，skill 做过滤（按当日情绪定位）与精选（证据强度）。

**代价与影响面**（【事实】= 2026-10-17 临时实施实测后回退，数字留作预估；【推断】= 标注处）：

### 2.5 命中统计口径规格（V1.5，2026-10-17 用户六项确认）

**问题背景**（2026-10-17 临时实施 R 系列合入时实测暴露，【事实】）：链跑毕的 CLI「命中」摘要默认口径只认「是」/布尔/数值>0，对两类模块产生失真——① 档位类（大涨大跌 / 60日新高新低 / 量能趋势）恒显示 0，当日实际大涨 147、大跌 130、新高 165、新低 158、连续放量 217、放量 205；② 比率类「数值>0 即计」导致**假满**（放量倍数命中 5499/5820 ≈ 覆盖率，零信息量；60日位置% 同理恒 >0）。假满比假零更危险——假零一看是 bug，假满像个正常数字会被当成事件数解读。

**设计原则**（【观点】，用户确认）：
1. 「命中」只服务于有**天然事件边界**的模块（制度定义，或事实上约定的阈值）；
2. 连续比率的任何阈值语义归**消费层**（报告层 / agent 解读）按需定义，链只保证可算样本数可见；
3. 方向性指标（涨跌 / 新高新低 / 正负溢价）**分桶分别统计**，不合并——合并数丢失方向信息；

**与源项目的关键差异**【事实】：`SpiralDevelopment/candlestick-patterns` 的抽象是 `required_count + logic(idx)` **逐行扫描**；本项目模块规范第 3 条「禁止逐行 Python 循环（性能红线）」。故自建库改用**整列布尔表达式**（pandas shift 构造前 K 参照列），`required_count` 语义保留（前 required_count−1 行结果置 False，不置 None——模块值域只允许 是/否/数据不足/理由串）。几何占比统一走 `geometry._ratio(numer, denom)`：

```python
_EPS = 1e-3  # 0.001 元，远小于 A 股最小 tick 0.01 元
def _ratio(numer, denom):          # 防一字板除零（源项目 hammer.py:17 的 .001+ 惯例）
    return numer / (denom + _EPS)
def _has_body(h, l):               # 一字板（涨跌停）h==l：无实体无影线，形态判定无意义
    return (h - l) > 2 * _EPS
```

#### 3.2.2 21 形态清单（【事实】= 判定式来自源项目源码；【观点】= 收录取舍）

双根（9）：看涨吞没、看跌吞没、看涨孕线、看跌孕线、十字星(Star)、雨滴(RainDrop)、射击之星、乌云盖顶、穿刺形态

代表判定式（与源项目逐字对应，均加 `_has_body` 前置门）：

| 形态 | 判定（源项目源码位置） |
|---|---|
| 锤子线 | `(h−l) > 3×(o−c)` 且 `(c−l)/(.001+h−l) > 0.6` 且 `(o−l)/(.001+h−l) > 0.6`（hammer.py:16-17） |

### 5.3 通用采集纪律（任何采集都适用，立为 `src/sync/README` 规范）

1. **两态异常契约**：「确实没有数据」（记 no_data，正常产出）与「接口坏了」（记 error，进汇总报告点名）必须分离，禁混为「无数据」静默跳过；
2. **限流**：按域名限流（东财风控阈值：>5 次/秒、并发 ≥10、1 分钟 ≥200 即封——来自 a-stock-data 实测表【事实】）；403 不重试；1s + 抖动串行兜底模式；
3. **幂等续跑**：`--start-date/--end-date` 区间幂等 + 断点 manifest（模式同 `fundamentals_rebuild_manager` / `financial_pdf_manager`）；
4. **列契约集中化**：换源不换 schema（adata 模式），字段缺失写 NULL + insufficient_note；
5. **不阻塞复盘**：新采集默认不进 `sync-review-all` 一键链（风控风险会拖累主链路），独立命令 + 用户显式触发。
