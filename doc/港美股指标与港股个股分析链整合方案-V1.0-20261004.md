# 港美股指标与港股个股分析链整合方案 V1.0（20261004）

**关联**：采集技术方案 V1.0（阶段1已实施，`overseas_kline_day` 80,629 行在库）、
阶段2报告层细化方案 V2.0（报告层三块，待实施）。本方案是用户决策的第三块拼图：
**外围分析进分析链与 skill**——使外围截面成为可配置、可下钻、与 A 股链同等的
分析资产。

**一句话定位**：报告层（V2.0 三块）负责每日复盘的**固定呈现**；分析链负责**可配置
截面与明细下钻**（全量 33 只港股排行、指数全指标、A-H 差值筛选）；两者**同表同口径
互证**（先例：重算涨停家数 vs 链 CSV 交叉校验）。

## 1. 现状架构盘点（整合的可行性论证）

### 1.1 模块层：市场无关，可直接复用

`AnalysisModule.analyze(df, ctx)` 只依赖列名（`trade_date/close/volume` 等），
不接触库与网络（纯函数红线）。实测论证：`new_high_low` 对港股 qfq K 线的逻辑
**逐行适用**（qfq 已平滑除权跳变，"复权口径技术新高新低"的口径注释甚至无需改）；
`volume_surge` 是无量纲比值，单位差异免疫；`big_mover` 阈值参数化即可。

**不可复用清单（制度性差异，必须排除）**：`limit_up_today / consecutive_limit_up /
limit_down_today / burst_limit / limit_up_premium`——全部依赖 A 股涨跌停制度
（`limit_up_rules` 按板块查制度上限），港股美股**无涨跌停**，这些模块严禁进入
外围链（引擎不做硬拦截，靠链 YAML 纪律 + 本方案 §6 链配置注释 + skill 文档约束）。

### 1.2 引擎层：三个数据耦合点，抽"数据域"策略

`ChainEngine.run()` 对 A 股的耦合集中在三处调用：

| 调用点 | 现状（A 股域） | 外围域需要 |
|---|---|---|
| `load_stock_universe()` | `base_stock_info ∩ his_kline_day` 全市场 | config 池（6 指数 / 33 只个股） |
| `load_kline(columns…)` | 读 `his_kline_day`，列白名单含 `preclose/change_rate/is_st` | 读 `overseas_kline_day`，无 change_rate（需自算）、无 is_st（恒非 ST）、需附 `a_close` 对照列 |
| `precheck()` | 规则1 前复权断裂（**以涨跌停制度上限为容差基准**）+ 规则2 缺日/停牌 | 规则1 **不可用**（无制度上限，美股单日 ±30% 合法）；保留停牌检测 + 新增"尾部滞后"检查 |

规则 1 不可移植是"必须做域抽象、不能只换表名"的根本原因。

### 1.3 链注册层：`ChainConfig` 需加一个字段

`chains/*.yaml` 一文件一链；`ChainConfig` 增加 `domain: str = 'a_share'`
（`a_share / overseas_indices / overseas_stocks` 三值，未知值加载时报错），
`chain_config.py` 解析时校验。CLI `analyze run/list-chains` 无需改动（domain 随链
配置走）。

## 2. 架构设计：数据域抽象（domain）

```
ChainEngine.run(chain)
  ├ domain = chain.domain（默认 a_share）
  ├ universe = DOMAIN[domain].load_universe(config)          ← 域策略 ①
  ├ kdf      = DOMAIN[domain].load_kline(reader, …)          ← 域策略 ②（列映射/A股join/窗口语义）
  ├ pre      = DOMAIN[domain].precheck(kdf, …)               ← 域策略 ③
  └ 逐股跑模块 → CSV（行=universe 成员，列=模块）             ← 引擎主干零改动
```

新增文件 `src/analysis/data_domain.py`：三个域策略实现（A 股域 = 现状三个函数的
搬运封装，行为逐字节不变）；`chain_engine.run` 的三处调用改为经域策略分发。
**A 股链回归红线**：改造后 `daily_review / limit_up_scan` 重跑 CSV 与改造前逐字节
一致（锚定日相同），作为序 1 的硬验收。

## 3. 外围域实现设计

### 3.1 universe（域策略①）

- `overseas_indices`：config `review_sync.overseas_kline_indices`（6 指数）→
  `StockInfo(ts_code='hkHSI', stock_code='hkHSI', stock_name='恒生指数', board='外围指数')`；
- `overseas_stocks`：config `overseas_kline_stocks`（33 只）→
  `StockInfo(ts_code='hk00700', stock_code='hk00700', …, board='港股')`，
  `a_code` 存入 `StockInfo.list_date`？**否**——`StockInfo` 是 frozen dataclass，
  外围域新建 `OverseasStockInfo(StockInfo)` 加 `a_code: Optional[str]` 字段
  （frozen dataclass 继承安全，引擎按基类访问不受影响）。

### 3.2 load_kline（域策略②）

SQL（一次取全池，pandas 侧再按 ts_code groupby，与 A 股 loader 同模式）：

```sql
SELECT market_code AS ts_code, market_code AS stock_code,
       trade_date, open, high, low, close, volume
FROM overseas_kline_day
WHERE market_code = ANY(%s) AND trade_date <= %(as_of)s
ORDER BY market_code, trade_date
```

pandas 侧加工（域内完成，模块无感知）：

1. `change_rate = close.groupby(ts_code).pct_change() * 100`（A 股 loader 是库列，
   外围域自算，口径=该市场相邻交易日）；
2. `is_st = 0`（港股无 ST 制度，列存在仅为引擎兜底列不缺）；
3. **`a_close` 对照列**（仅 `overseas_stocks` 域）：对池内带 `a_code` 的港股，
   `merge_asof` 挂 A 侧 `his_kline_day`（前复权 close）"≤该行日期最近 A 股收盘"；
   无 `a_code` 的 18 只整列 NaN。口径注记：H 侧 qfq 与 A 侧前复权**各自滚动**，
   比值仅作参考（同 V2.0 块④口径）。

**窗口语义**：外围域忽略链 `lookback` 的 A 股日历换算，直接按
`max(模块 effective_lookback) + WINDOW_BUFFER` 取**每股最近 N 行**（市场自身日历）；
`analyze run` 打印的窗口起点取全池最早行日期，并注明"市场自身日历"。

### 3.3 precheck（域策略③）

| 规则 | A 股域 | 外围域 |
|---|---|---|
| 前复权断裂 | `|change_rate| > 制度上限+容差` | **不适用**（无涨跌停；qfq 连续性由采集层双源对拍哨兵负责，跨域不重复设防） |
| 缺日(单日) | 计入存疑 | 同口径保留 |
| 连续缺行疑似停牌 | 不计入存疑 | 同口径保留（港股停牌/台风停市） |
| **尾部滞后**（新增） | — | 个股/指数最近行距锚定日 >3 个该市场交易日（用 hkHSI / usDJI 行日历判定，同 V2.0 §3.4 对齐规则）→ 存疑原因`数据滞后`（如假期未补采） |

存疑词表：`缺日(单日)` / `数据滞后`；CSV 的"是否存疑/存疑原因"结构沿用。

## 4. 模块设计（复用 3 + 新增 5）

### 4.1 复用模块（零改动）

| 模块 | 外围链用途 | 备注 |
|---|---|---|
| `big_mover` | 大波动（阈值参数：指数链 3%、个股链 5%） | 无涨跌停语境下解读为"大波动"，skill 注明 |
| `volume_surge` | 放量倍数（个股链） | 比值无量纲；指数链不用（指数放量语义另议） |
| `new_high_low` | 60 日新高/新低（两链通用） | qfq 口径口径注释已天然适用 |

### 4.2 新增模块（`src/analysis/modules/`，遵守模块开发规范 5 条）

| 模块 name_en | CSV 列名 | 逻辑 | required_columns |
|---|---|---|---|
| `chg_5d` | 5日累计% | `close[-1]/close[-6]-1`，不足 6 行→数据不足 | close |
| `chg_20d` | 20日累计% | `close[-1]/close[-21]-1` | close |
| `position_60d` | 60日位置% | `(c[-1]−min(w))/(max(w)−min(w))`，w=尾部 61 行（与 A 股指数章、V2.0 块①同构同口径） | close |
| `ah_5d_diff` | AH 5日差 | A侧5日 − H侧5日（A 侧 = `a_close` 尾 6 行首尾比）；`a_close` 整列 NaN → `无A股映射`（区别于数据不足）；H 侧尾部滞后>3 市场交易日 → `未对齐` | close, a_close |
| `ah_premium` | AH溢价% | `a_close[-1]/(close[-1]×fx)−1`；fx 经 `ChainContext` 注入（引擎在外围个股域启动时读 `overseas_market_daily` fx_shkdcny 最新行，缺→模块返回`汇率待补`） | close, a_close |

`fx` 注入方式：`ChainContext.upstream` 预留字典携带（键 `fx_hkdcny`），不破坏
模块纯函数红线（引擎装配，模块只读）。5 个新模块均登记 `analysis/README.MD`。

## 8. 风险与红线

1. **A 股链回归是最高优先级验收**——域抽象动了引擎主干，任何 A 股行为漂移
   （列序/存疑口径/窗口）都是 P0 事故；序 1 的逐字节对拍不可省略；
2. `Lookback` 类是 A 股日历语义，外围域**不复用其换算**（直接行数窗口），
   `analyze run` 输出的窗口说明须注明"市场自身日历"，防误读；
3. 涨跌停系模块误入外围链的防线是三层（YAML 注释/README 登记/skill 规范），
   引擎不做硬拦截（避免域知识倒灌引擎；链由用户配置的项目原则不变）；
4. `a_close` merge_asof 的 A 侧查询限定池内 15 个 `a_code`（一次取全，勿逐股
   查库）；`his_kline_day` 为前复权口径，与 H 侧 qfq 基准独立——AH 两列永远
   标注参考口径；
5. 外围链**不进每日固定流程**（按需触发），每日复盘的主干仍是"编排采集→报告
   生成"；链价值在研究/下钻场景，防止复盘流程膨胀；
6. 不做 git 操作；skill 源件改后重拷。

**实施中发现与决策**：

1. **锚定日解析是第 4 个域耦合点**（方案 §1.2 列了 3 个）：引擎 `resolve_as_of`
   原按 his_kline_day 解析，外围链缺省锚定日会静默错位到 A 股最新交易日（全部模块
   返回"数据不足"）→ 域策略增 `resolve_as_of`，外围按 overseas_kline_day 自身日历
   解析/校验。方案 §3.2"市场自身日历"语义的必要延伸。
2. **AH 5日差的链/报告窗口语义差异（两口径均成立，非 bug）**：链 ah_5d_diff 的
   A 侧= a_close（按 H 行 as-of 对齐）尾 6 行首尾比（H 日历），报告 aggregator 的
   A 侧= his_kline_day 自身尾 6 行（A 股日历）——基差一个交易日（如比亚迪链 2.95 vs
   报告 2.13，方向一致）。链口径按本方案 §4.2 原文实施；AH 溢价只用品尾值故两口径
   逐值一致。AH 列本就是参考口径，解读时注明即可。
3. **外围域行数窗口的实现**：`overseas_kline_day` 全池 ≤80k 行，一次取全后
   `groupby.tail(max(模块回看)+2)` 截尾，window_start=截尾后最早行（指数链实测
   20260702）；`resolve_paths`/进度/CSV 全链复用，链文件名带域无关链名。
4. **fx 注入**：按 §4.2 经 `ChainContext.upstream`（键 fx_hkdcny，注解放宽为
   Dict[str, Any]），引擎逐股拷贝防泄漏；fx 缺失仅影响 ah_premium（汇率待补）。
5. **big_mover 参数**：方案 §5 伪码 `{threshold: 3}` 落地为既有注册参数
   `{up_pct: 3, down_pct: -3}`（未知参数会报错）。

**改动清单**：`chain_config.py`（domain 字段+校验）、`data_domain.py`（新增，三域
策略）、`chain_engine.py`（三调用点+锚定日改域分发，主干零改动）、`module_base.py`
（upstream 注解放宽）、5 个模块文件、`README.MD`（5 行登记）、2 条链 YAML、
`analysis_cli.py`（list-chains 域标注）、skill 两份（五处）、
`test_data_domain_overseas.py`（15 项）。**引擎对 A 股行为逐字节不变（已对拍）**。

**外围链用法**：`analyze run --chain overseas_index_scan`（6 指数截面）、
`analyze run --chain hk_stock_review`（33 只港股截面，含 AH 对比/溢价）；锚定日
缺省=外围库最新市场日；**不进每日固定流程**（按需触发，方案 §8.5）。

## 10. 决策修订记录（2026-10-05，用户拍板）

**§8.5"外围链不进每日固定流程"修订为：三链每日全跑。**

用户决策：每日复盘流程 = `sync-review-all` → **三链串行（`daily_review` +
`hk_stock_review` + `overseas_index_scan`，~31 秒）** → `review generate` → skill
基于报告 + 三份 CSV 解读。

- **顺序约束**：三链必须在 `review generate` 之前——报告交叉校验读取
  `daily_review_<锚定日>.csv`，链先落盘报告才带校验行；
- **修订理由**：原"防流程膨胀" concern 在实测亚秒级（0.1~0.4s）后不成立；
  三链 CSV 是解读的直接输入（全量明细 + AH 排行 + 互证底表），每日产出有消费方；

  最新市场日，两者可差 1 个交易日（市场日历差异，正常现象，解读点名）；
- **落地位置**：skill 路径 A 新增 A1.5 步骤 + A3 改为"报告 + 三链 CSV"两层解读
  （.zcode 与 .workbuddy 已同步）；本方案 §9 实施记录中的"不进每日固定流程"表述
  以本节为准。
