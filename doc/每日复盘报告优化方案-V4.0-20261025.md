## 2. 逐项设计

### X1 解禁窗口日历比较修复（A1，确定性 bug）

**现状与证据**（2026-10-25 实测）：
`_aggregate_unlock`（aggregator.py:1883-1912）在 :1890 调
`self._next_n_dates(as_of, 10)` 裸传 `20261023`；`base_trade_calendar.calendar_date`
为 TEXT 存 `YYYY-MM-DD`，裸串比较恒小于全部带连字符日期 → 返回空 →
`end = as_of` → 窗口塌缩为单日 → `share_unlock_calendar WHERE unlock_date >= '20261023'
AND <= '20261023'` 恰 0 行 → available=False → 第六章恒显
`⏳ 待补：解禁日历（share_unlock_calendar 窗口内无已披露记录）`（conclusion.py:91-92）。

**数据实测**：窗口内实有 **19 行**已披露解禁（20261026 华勤技术起，最大 20261102）；
`_dot` 修复后窗口 [20261023, 20261106]（前 10 交易日）全部命中，LIMIT 30 不截断。
同病排查：`_disclosure`（:2710）已正确传 `_dot(as_of)`，全库仅此一处裸传
（v10 修复 `_next_trade_date` 时已排查过，本处为 V3.0 遗留记录的同源点）。

**改法**：
1. :1890 一行：`self._next_n_dates(_dot(as_of), 10)`；docstring 补口径句
   （同 `_next_trade_date` :2254-2255 的警示写法）。
2. `AGG_CACHE_VERSION` v10→**v11**（v10 缓存 `unlock=available=False` 会原样回放）。
3. 新增**聚合级 SQL 参数测试**（正是能拦住这类 bug 的测试形态）：fake reader
   记录 `_next_n_dates` 收到的参数，断言为 dotted 形态——现有
   `test_next_trade_date_w7`（fake reader 直返行）拦不住格式错误，补齐该盲区。

**验收**：20261023 重跑（v11 缓存重建）后第六章出现「未来 10 个交易日解禁日历」
表 19 行 + 口径注；digest 不受影响（无 unlock 消费点，已核实）；渲染层既有测试
`test_unlock_block_rendered_sorted_by_date` 不动。

**不做**：不改 `_next_n_dates` 本身（其调用方 `_disclosure`/解禁修复后均传 dotted，
未来新调用方由测试守住）；不动采集侧（unlock_manager 周频采集正常）。

### X2 R3 对账错位修复（A2，两侧去重口径对齐）

**现状与证据**：
- 链侧：`r3_trend_new_high.py:48-53` 先查 upstream `R1梯队接力`/`R2主线跟随`
  **命中即否**（链 R1 为全量谓词、不带弱档闸门——闸门是报告层设计）；r2 模块同构。
- 报告侧：`_build_candidates` 的 `used` 集合（:2503）只收**闸门后** R1 行
  （:2531 `is_r1(..., market_weak=market_weak)`，弱档日 r1_rows=[] → used 不含
  R1 原命中）→ R2/R3 多收。
- 20261023 实例（实测复核）：链 R1=3（华阳智能/上海九百/睿能科技）、R2=11、
  R3=26（华阳智能 R3 列=否，被 upstream R1 去重）；报告 R1=0（弱档否决）、
  R3=27（华阳智能以「新高/+7.2%」画像入池）——**同一只股两侧画像与数量皆错位**。

**修复选项评估**：
- **A（采纳）：报告侧去重输入对齐链侧全量口径**——R1 段构造前先按
  `market_weak=False` 计算 **R1 原命中集**（raw 谓词命中，含被弱档否决者），
  仅用于 `used` 播种；`out['R1']` 输出仍走闸门（弱档日 0 开放**不变**）。
  语义：R1 画像股（连板接力）在弱档日被整类否决是设计本意，不应以 R2/R3
  画像"改头换面"回到报告池；链侧早已如此。
- B（否决）：链侧改为不去重 R1——破坏 r3/r2 模块文档化设计
  （"R1/R2 命中股不重复入选"），影响全部历史链语义。
- C（否决）：仅在对账表披露不修——核验闭环的对账噪声永续存在。

**改法**：
1. `aggregator.py` `_build_candidates` R1 段（:2524 附近）：闸门过滤前先收集
   `raw_r1 = {ts_code for lu 行 if is_r1(streak, is_st, oc, rules)}`（不带
   market_weak）；`used |= raw_r1` 置于 R2 构造之前；`out['R1']` 装配路径不动。
   实施时顺带核实 r2 链模块确查 upstream R1（预期同构），写进实施记录。
2. 非弱档日零行为变化（gated==ungated）；弱档日 R2/R3 各剔除与 R1 原命中的
   交集（20261023 实例：R3 27→26，华阳智能出池；R2 无交集——2 板股不满足
   R2 首板谓词，实测确认）。
3. SKILL.md 弱档否决词条补一句：「被否决的 R1 原命中不再以 R2/R3 画像入报告池
   （与链去重口径一致，X2）」；三副本同步 + 预算基线重固。
4. digest note 质量点名表该行（"R3 池报告/链差 1 只 | 实现错位（待授权修复）"）
   于修复验收后撤行。

**测试**：`test_review_report.py`（或 phase3）补两路——弱档日合成用例（一只股
同时满足 R1 原谓词与 R3 谓词 → 报告 R1=0 且 R3 不含该股、与链口径一致）；非弱档
日用例输出不变（回归锁定）。**验收**：20261023 重跑 R3=26 与链一致；链/报告
R2 逐一对账。

**不做**：不动闸门逻辑与判定阈值；不动链模块；`used` 播种集**不进任何输出**
（仅去重用途，不渲染"被否决 R1 命中"新表——该信息链 CSV 已有，note 已有解释位）。

### X3 A50 Phase 2 准入证据（A4 证据生产；A5 实施另行授权）

**现状**：Phase 1 观察锚 note 已上线（V3.0-S5：锚定日口径 A50 行 + 周末缝提示，
不入触发）。入触发需双证据，此前无回测。

**数据可用性（2026-10-25 实测）**：
- `overseas_kline_day` CHA50CFD：**20161025~20261023 共 2593 根**（约 10 年）。
- `trade_index_info` 上证 000001：19901219 起全历史（open/preclose 齐备）。
- 结论：历史回测**现在就可做**，不必等观察期。

**证据生产设计（A4 交付物 = 校准回测报告）**：
1. 新增一次性回测脚本（落 `backend/scripts/` 或 analysis CLI 子命令，
   形态仿 chan_validation 先例），产出 `doc/reports/a50_trigger_calibration_<日期>.md`：
   - **一致性**：A50 隔夜变动（D-1 收→D 收）vs 上证 D 开盘 gap 方向的同向率，
     全历史 + 分年度 + 仅周五锚定日子样本（周末缝场景）。
   - **触发可用性**：周五→周一 A50 累计变动越 ±1.5%（及 1.0/2.0 灵敏度档）的
     历史频度与当日上证开盘方向的分档命中表——A50 若极少越阈则无触发价值。
   - **对照**：同表并列恒指/纳指同口径作参照（A50 相对增量的来源）。
   - **局限如实标注**：日K 为"全天收"代理，含开盘后信息，同向率是乐观界；
     盘前实时读数的可得性历史不可回测，由前向观察补。
2. **前向观察**（Phase 1 note 已积累）：至 2026-11-08 观察满 2 周，收集
   周末缝案例（周五锚定日的 A50 读数 vs 周一开盘方向）。
3. **A5 准入门（量化，写死）**：① 回测同向率 ≥60%（乐观界不达即否）；
   ② 周五样本 A50 越 ±1.5% 频度 ≥10%（触发器有实际用途）；③ 前向周末缝案例
   ≥2 例方向一致。三门齐开才进 A5。

**A5 实施预案（本轮不授权，仅留设计）**：
- `tomorrow_plan.py`：触发判据扩「恒指/纳指 ±overseas_gap_pct 或 A50 ±
  `review.tomorrow_plan.a50_gap_pct`（默认 1.5，回测定值）」；A50 以独立触发行
  呈现，不入盘前对照基准表（A50 无 5 日/60 日位置语义，表内语义错位）。
- `verifier.py`：`SCENARIO_ANCHORS` + `name2code` + anchors payload 加 A50 基准；
  **核验口径切换日登记**（滚动战绩 30 日窗口重起并注明分界——本方案即 V3.0
  预告的"历史核验口径变更单独说明"载体）。
- 字典/SKILL：P1-P3 与富时A50 词条「不入触发」句改「入触发（Phase 2 起）」；
  预案复述指引同步；缓存 v+1。

### X4 高潮第二证据阈值校准数据包（A3 证据生产；调值/升格另行授权）

**现状**：`breadth_ratio_gte: 2.0` 为初版未校准参考阈值（config.yaml:162 注释
自认）；判据表第四行永远 reference 角色，"极端宽度对次日是否有增量信息"无数据。

**数据可用性（2026-10-25 实测）**：`sentiment_metrics_daily`
**20210104~20261023 共 1405 日，up_count/down_count 全量非空**——回测数据齐备
（次日溢价/涨停数同表，上证涨幅 trade_index_info）。

**数据包设计（A3 交付物 = 校准报告 `doc/reports/sentiment_breadth_calibration_<日期>.md`）**：
1. **分布**：breadth_ratio（up/down，down=0 记 +∞ 档）全历史分位表
   （P50/P75/P90/P95/P99）；≥2.0 历史占比与聚类特征（是否集中在普涨日）。
2. **判别力**：按 breadth_ratio 分桶 × 次日结果（次日溢价均值/涨停家数变化/
   上证涨幅中位），并做**条件增量**分析——在"高度≥5 且溢价≥4"已命中的日子
   之外，宽度极端是否单独预告次日退潮/兑现（第二证据的存在意义）。
3. **阈值选项表**：1.5 / 2.0（现状）/ 2.5 / 分位法（如 P90）各自的历史命中
   天数、次日表现、与高潮判据的交叠度。
4. **结论选项三态**：(a) 调阈值、维持参考判据；(b) 升格定位判据
   （role reference→position——高潮判据语义变更：三条件"与/或"结构需用户定）；
   (c) 维持 2.0。

**用户决策点**（数据包产出后）：阈值数值 + 是否升格。升格路径预留：
config 改值 → `aggregator.py` criteria（:1254-1276）role/expr 同步 → trial 水印
机制沿用（`sentiment_calibrated` 流程同情绪判据 §3）→ verifier 情绪定位核验
口径登记变更 → 字典/SKILL 同步。V3.0 红线"不动情绪定位规则与阈值"在本方案内
**由用户看完数据包后主动解锁**，非本轮默认动作。

## 4. 红线与不做清单

1. 本轮（A1~A4）**不改任何判定语义**：A1 是格式修复（数据本就在库）、
   A2 是去重输入对齐（闸门与阈值不动）、A3/A4 只读库产报告。
2. A5（A50 入触发）与 X4 阈值调值/升格**不在本轮授权内**；升格触碰
   V3.0 红线"不动情绪定位规则与阈值"，须用户基于数据包显式解锁。
3. verifier 核验历史连续性：A5 与 X4 升格实施时必须登记口径切换日
   （滚动战绩分段），本方案 §2.X3 的 A5 预案即该说明的载体。
4. 链模块判定逻辑不改（X2 修报告侧）；`_next_n_dates` 函数签名不改
   （由测试守住调用方格式）。
5. 继承红线：六维章节编号与口径、burst_rate 存储小数、digest"只装配不加工"、
   同输入逐字节一致（A1/A2 属内容变更——渲染基线重固 + 实施记录注明）。
6. SKILL.md 三副本同步 + prompt_budget 基线随固（X2/A5 触及 SKILL）。
