## 2. 逐项设计

### 批次一（纯呈现与提取，零口径变更）

#### D4 「距窗口最低点第 N 天」措辞去歧义（P1）

**现状与证据**：字段语义 = days_since_low（`aggregator.py:1389-1395`）——锚定日
距 10 日窗口内 score 最低日的**交易日数**（10-23 的「第 1 天」= 昨日是窗口 score
最低日）。现措辞可读成「最低点出现在昨天」（陡 V）或「最低点在窗口第 1 天」
（缓慢修复），两种读法方向相反。双渲染位各自拼串、非共享常量：
`digest.py:772`（图文§二）与 `sections/sentiment.py:140`（六维§二）；解读区
note:20 系 agent 转抄同一短语。

**改法**：两渲染位统一改为 `距窗口 score 最低点已 {N} 个交易日`；N=0 特例
`今日即窗口最低点`。六维与图文同步受益（同口径文案）。

**验收**：回放 10-23 后两份报告该行显示「距窗口 score 最低点已 1 个交易日」，
无双读。

**不做**：不改 days_since_low 计算逻辑、不动缓存（纯渲染文案）。

**测试**：两渲染位单测补 N=0 / N=1 分支断言；grep 更新存量断言。

#### D5 免责去重（P3，规约）

**现状**：note 末行 blockquote 免责（note:75）与 digest 页脚恒带免责
（`digest.py:893-896`）语义重复。SKILL.md 已有「免责声明由 digest 页脚恒带」
一句，但未明确禁止 note 自带，写作惯性延续。

**改法**：SKILL.md 明确**note 不写免责 blockquote，页脚为单一出处**；digest
装配逻辑不动（「只装配不加工」红线——不在渲染器里过滤 agent 文本）。

**校验**：check 语汇扫描追加规则——note 含「免责声明」→ WARN。

**存量**：10-23 note:75 随下次复盘按新规约自然消失（历史 note 不改写惯例）。

#### D7 页首三行速览框（P2）

**现状**：digest 信息密度高但无速览入口——主干判断、关键读数、转天倾向散在
页面各处，日常使用须通读全页。

**改法**：
1. 落点 `digest.py:678-687`（h1 之后、口径说明/章节对照行之前）加
   `<div class="tldr">` 三行，**零新计算**，全部装配已有产物：
   - ① 主干句：从 note 正则提取 `**主干：…**` 独立行；note 缺失或未提取到则
     该行整体省略。
   - ② 关键数一行（build 时均已提取的字段，缺失逐项降级省略）：
     `情绪档 {cycle.position} · 空间高度 {梯队最高档} 板 · 涨停
     {limit_up_count} 家 · 溢价均值 {premium_mean}% · 两市 {turnover 今日} 亿
     （较昨 {delta_pct}%）`。
   - ③ 转天倾向：从 note 提取「**基准倾向**：」行；缺省回退
     `_match_positioning`（`sections/tomorrow_plan.py:255-260`；digest 已有
     import sections 先例 `digest.py:556`）。
2. note 读取时机前移：现 `digest.py:878-891` 装配时读文件 → 前移到 build 早期
   读一次，提取速览要素后原样装配。装配逻辑不变——速览框是**提取+渲染既有
   产物**，不改写 note 任何内容（红线兼容）。
3. `_PAGE_CSS` 追加 `.tldr` 样式（浅底框、三行紧凑）。
4. SKILL.md 补两句**提取契约**：主干行必须独立成行且以 `**主干：` 开头；
   基准倾向行保持 `**基准倾向**：` 现有格式。

**验收**：回放 10-23 后页首速览框三行可读：主干句与解读区①一致；关键数与
§二/§一正文一致；转天倾向与预案节一致。note 缺失日速览框退化为仅关键数行。

**不做**：速览框不放 P 档判定——`verification.scenario.triggered` 语义是次日
核验对昨日预测的判定（`verifier.py:137-195`），不是锚定日当日状态，放入速览
会误导；速览框不新增任何计算。

**测试**：提取函数单测（正常 note / 缺 note / 多候选行容错）；速览框渲染单测
（字段缺失降级）；byte-stable 基线重固。

#### D8a 要闻缺口标注去歧义（P3，代码侧）

**现状与根因（已查明）**：`aggregator.py:2242` reason「未采集或当日无快讯」
二义。实况：10-08~10-23 采集断档——`data/reports/` 采集报告显示 10-07 23:42
之后下一次运行为 10-24 17:15；增量游标设计（只入库 news_id > cursor 的行，
`news_telegraph_manager.py:119-121`）+ 新浪接口翻页深度有限 → 10-23 缺口
**基本不可回补**。

**改法**：`_aggregate_news` 查库内最新日期（MAX(trade_date) 或最新
publish_time）区分两种 reason——最新 < 锚定日 → `采集断档（最新 {d}，历史缺口
不可回补）`；库内日期覆盖锚定日窗口而无当日行 → `当日无快讯（已采集）`。
（agg 字符串变更，并入 v13 bump。）

**运维建议（不在本轮代码内，单列授权）**：每日固定时点跑
`sync-news-telegraph`（建议 ~15:30 与 ~21:30 各一次，单次 ~200 条覆盖
~8 小时快讯）；如需配置调度自动化，另行授权。

**已知边界**：10-23 要闻缺口接受为不可回补，质量点名表如实标注。

### 批次三（规约与校验）

#### D1b 工单号清场·规约侧 + lint（P2）

**改法**：SKILL.md P2-8 读者面语汇边界追加工单号禁令——note 全文（含质量点名
表说明列）禁 X/P/A/S 系列工单编号，溯源一律用日期表述。check 语汇扫描追加
工单号模式（WARN 级）：

```
\b(?:X\d+|[PSA]\d{1,2}-\d{1,2})\b
```

已核对不误伤合法词：P1-P3（连字符后非数字不匹配）、V 系列/V4 验点、R1-R4、

（存量 note 豁免不改写，WARN 属预期，新 note 起生效）。

#### D2 解读区括注降噪（P3，规约）

**现状**：note:13 机制句三重嵌套括注 + 双来源标注；note:10 资金句一句三括注。
P0-3① 数字接地义务（每个关键数字挂来源）推高括注密度，但现行规约无密度与
嵌套上限——接地义务与可读性失衡。

**改法**：SKILL.md「解读生成规范」追加第 9 条，三条硬约束：
1. 每自然句接地括注 ≤2 处——超出则拆句，或并入句尾合并括注；
2. 括注内禁再嵌套括注——条件定义/闸门规则移口径字典或改独立括注句；
3. 同句多来源合并为一个括注——`（六维§2/§6）`、`（CSV:缠论背驰买点；图文§六）`。

**校验**：语汇扫描追加嵌套括号检测 `（[^（）]*（`（WARN）。

**不做**：不给 md 渲染器加脚注/上标语法——渲染器极简是「同输入逐字节一致」
红线的实现基础，规约+lint 达同等效果；接地义务本身不减（P0-3① 完整保留，
D2 只治嵌套与堆叠）。

#### D3 精选观察池排序确定化（P2，规约+校验）

**现状与证据**：精选池无代码排序——agent 按 SKILL.md:170/244「证据强度
（五维计数降序）+ 证据链完整性」执行，档内次序无规则。10-23 实况：
大港（4 证，42.9 分）→ 科远（4 证，49.1 分）→ 恩捷（3 证，71.3 分）——
同 4 证档内呈**分数升序**，全场最高分垫底，且排序依据读者无从得知（事后核实
恰合池基础序=成交额降序 `aggregator.py:2612`，纯偶发非规则）。

**改法**：SKILL.md 综合研判③ 排序固化为 **（证据数 desc → 评分 desc →
成交额 desc）**，表头括注标明「按证据数×评分降序」；同时写明与六维§六报告表
（评分 desc，`tomorrow_plan.py:485-496`）的口径差异是**设计意图**——精选池是
证据强度优先的严格子集，报告表是全池评分视图。

**校验**：check 新增规则（WARN）——解析池表类别列「N 证，X 分」模式，校验
证据数降序 + 同档内分数降序。

**验收**：新 note 池表首行 = 证据数最高且档内分数最高者；排序口径在表头可见。

   阈值、X4 阈值三选一（另行走决策）。
