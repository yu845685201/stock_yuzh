> 未登记的模块在 `analyze list-modules` 时会给出告警。
>
> 返回值约定（§2.5）：无法计算一律返回 `数据不足`，不允许空串或静默丢弃。

| 英文名 | 中文名 | 详细描述 | 返回值格式 | 参数 |
|---|---|---|---|---|
| limit_up_today | 是否涨停 | 锚定日是否涨停。按 `change_rate` 阈值法判定，阈值随板块与制度分段（主板 10% / 创业板 20% / 科创板 20% / 北交所 30% / ST 5%），并以 `close ≥ high` 作为逻辑必要条件剔除伪命中；1996-12-16 前无涨跌停制度、板块未知、新股上市首日（`trade_date == list_date`）均返回 `数据不足` | 是 / 否 / 数据不足 | 无 |
| consecutive_limit_up | 连续涨停数 | 以锚定日为终点向过去数连续涨停天数，锚定日本身未涨停则为 0；涨停判定规则同 limit_up_today。回看窗口内数据不足（如次新股）以实际可得数据计算；若锚定日之前不足 1 个交易日返回 `数据不足`。连板数用满回看窗口时返回窗口上限值 | 整数（≥0）/ 数据不足 | max_lookback=60 |

## 实现口径说明（重要）

### 1. 涨停判定为什么用 `change_rate` 阈值 + `close ≥ high`

- **`change_rate` 阈值法**（方案 §3.9）：全表为前复权价（`adjust_flag=2`），历史日期的
  `close` 不等于当日真实价，不能用 `close == round(preclose * 1.1, 2)` 精确判定。
- **`close ≥ high` 是逻辑必要条件**：收于涨停 ⟹ 收盘价即当日最高价（涨停价就是当日
  可成交的最高价）。该项只剔除「涨幅达标但收盘价不是当日最高价」的伪命中，不会引入漏判。

实测（uat 库，主板 60/00 非 ST，以「未复权价 `raw_close == round(前一日 raw_close × 1.1, 2)`」为参照口径）：

| 交易日 | 纯阈值法 精确率 / 召回率 | 加 `close ≥ high` 后 精确率 / 召回率 |
|---|---|---|
| 20260923（锚定日） | 100.0% / 97.7% | 100.0% / 97.7% |
| 20260601 | 100.0% / 98.2% | 100.0% / 98.2% |
| 20240913 | 100.0% / 94.3% | 100.0% / 94.3% |
| 20220104 | 90.5% / 100.0% | **100.0% / 100.0%** |
| 20150901 | 34.5% / 100.0% | **100.0% / 100.0%** |
| 20100104 | 21.1% / 100.0% | **88.9% / 100.0%** |
| 20080610 | 5.7% / 80.0% | **100.0% / 80.0%** |

全表 `close > high` 仅 96 行（0.0006%），护栏本身安全。

### 2. 数据预检（存疑）规则与原方案的差异

方案 §3.5 原定规则 1 为「相邻交易日 `close[t-1]` 与 `preclose[t]` 相对差 > 0.1% 记为前复权断裂」。
**实测该规则恒不触发**：全表 `preclose == lag(close)` 占 **99.987%**（16,487,043 行样本），
即 `preclose` 就是前一日 `close` 的复制，二者相对差恒为 0。

因此改用**可证伪**的一致性规则：

> **规则 1（前复权断裂）**：`|change_rate| > 制度上限 + 容差（默认 0.6 个百分点）`
>
> 涨跌幅在物理上不可能突破涨跌停制度上限，一旦突破，必为前复权序列基准断裂。
> 输出格式：`YYYYMMDD前复权断裂(涨跌幅x.xx%超出制度上限±y.yy%)`

> **规则 2（缺行）**：交易日历内缺失 K 线行，按**缺口连续段**分流：
>
> - **孤立单日缺行** → 计入存疑，格式 `YYYYMMDD缺日(上一交易日YYYYMMDD)`；
> - **连续 ≥2 交易日缺行** → 归入**疑似停牌**，**不计入存疑**，仅聚合计入
>   `.meta.json` 的 `precheck.suspended_stock_count` 与 `suspended_detail_sample`。
>
> 分流依据（实测，250 交易日窗口 / 5,200 只）：共 452 只股票存在缺口，其中
> 209 只仅单日缺口、243 只存在连续缺口；连续缺口的段长呈明显的 **5 日（108 段）/ 10 日（73 段）**
> 簇，是典型停牌形态（例：`sh.601059/601198/601995` 三只券商同为「20251120 起连续 20 个交易日无K线」，
> 与 2025-11 券商合并停牌事件吻合）。若一律判存疑，8.7% 的股票会被标记，淹没真正的数据问题。
> 停牌是市场事实而非数据缺陷，模块按可得行计算，涨停/连板判定不受影响。
>
> 可通过 `analysis.missing_day_mode` 切换：`gap`（默认，上述分流）/ `all`（方案原文行为，逐日列出）
> / `off`（关闭）。

> **规则 2b（上市前）**：缺行检测起点取 `max(该股窗口内首行, list_date)`，上市前无数据不算缺行。

**已知局限（诚实声明）**：规则 1 只能捕捉「超过上限」的断裂，属**存疑下界**——
基准偏移未超上限的轻度断裂不会被标记。各年「主板非 ST 行中 |change_rate| 突破上限」的比例实测为：

| 年份 | 2008 | 2015 | 2020 | 2022 | 2023 | 2024 | 2025 | 2026 |
|---|---|---|---|---|---|---|---|---|
| 占比 | 15.17% | 8.04% | 1.61% | 0.79% | 0.25% | 0.40% | 0.13% | 0.01% |

即：**锚定日/近期数据的判定可信度高，越往历史越不可信**，`--as-of` 回看历史时请重点
关注「是否存疑」列。

### 3. 分析窗口（lookback）

**默认只分析最近 1 年的日 K 线**，窗口在**链 YAML 的 `lookback` 字段**配置（单一来源）：

```yaml
chain: limit_up_scan
lookback: 1y          # 默认值
modules:
  - name: limit_up_today
  - name: consecutive_limit_up
    params: {max_lookback: 60}
```

| 写法 | 含义 |
|---|---|
| `1y` / `2y` | 自然年（锚定日往前 1 / 2 个自然年） |
| `6m` / `3m` | 自然月 |
| `250d` / `120d` | **交易日**数（按 `base_trade_calendar` 精确回溯，不受长假影响） |
| `250`（纯数字） | 交易日数 |
| `0` / `all` | 全历史 |

- 实际加载窗口 = `max(链 lookback, 各模块 effective_lookback())`：链窗口小于模块回看需求时
  自动扩展，`.meta.json` 的 `window_expanded_by_modules` 会标 `true`，CLI 也会提示。
- 启动即校验：非法写法（如 `1x`）在链加载阶段直接报错退出，不做静默降级。
- CLI 可临时覆盖：`--lookback 6m` / `--lookback 0`。
- 实测规模（锚定日 20260923）：`1y` → 起点 20250923 / 243 交易日 / 端到端 14 秒；
  `6m` → 128 交易日；`250d` → 251 交易日。全历史（`0`）会加载 1,650 万行、约 3 GB 内存，
  仅在确需时使用。

> 早期版本把窗口放在 `config.yaml` 的 `analysis.precheck_lookback`，现已移除——
> 窗口是「链」的属性，放在链 YAML 里可让每条链各自决定分析范围。

### 4. 运行与测试

```bash
cd stock_yuzh/backend
export NO_PROXY=127.0.0.1,localhost
PY=../.venv/bin/python

$PY run_cli.py analyze run --chain limit_up_scan
$PY run_cli.py analyze run --chain limit_up_scan --lookback 6m   # 临时覆盖分析窗口
$PY run_cli.py analyze list-chains
$PY run_cli.py analyze list-modules
$PY run_cli.py analyze progress --chain limit_up_scan

$PY -m pytest test/analysis -q                      # 单测（109 例）
ANALYSIS_GOLDEN=1 $PY -m pytest test/analysis/test_golden_sample.py -q   # 黄金样本回归（需数据库）
```

黄金样本回归（§3.8）固定 10 只代表股在锚定日 `20260923` 的结果与基线比对；
已与 `limit_up_scan` 链的 CSV 输出交叉核对一致。

### 5. 输出物

| 文件 | 内容 |
|---|---|
| `<链名>_<锚定日>.csv` | UTF-8 with BOM；列：股票代码, 股票名称, 是否存疑, 存疑原因, 模块列…；按股票代码排序 |
| `<链名>_<锚定日>.progress.json` | status / total / done / percent / elapsed_seconds / eta_seconds / warnings / csv / error |
| `<链名>_<锚定日>.meta.json` | 模块、耗时、股票数、存疑数、分析窗口（`lookback` / `window_start` / `window_trading_days` / `window_expanded_by_modules`）、precheck 统计（断裂 / 缺行 / 疑似停牌） |

同一锚定日重复运行，CSV **逐字节一致**（已用 SHA-256 验证）。
